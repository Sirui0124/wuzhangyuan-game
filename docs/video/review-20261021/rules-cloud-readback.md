## 两套状态独立流转

两列均沿用用户当前设置的四个下拉值，大小写保持原样：**待生成、待review、已通过、待更新**。正常流转为待生成→待review→已通过；收到返修意见后为待更新→待review→已通过。不擅自改名或扩展选项。

| 状态 | prompt状态 | 当前状态（视频） |
|-|-|-|
| 待生成 | Prompt 尚未编写完或尚无可提交的完整文档 | 对应版本的新视频尚未产出；包括仍在生成的过程，完成后再改待review |
| 待review | 完整 Prompt、参考图、时长和分镜已整理到链接文档，等待用户或指定审核人确认 | 实际新片已产出并填写路径，等待画面、声音及前后衔接审阅；需要返修时转待更新，并在待更新的备注中保留问题 |
| 已通过 | 用户或指定审核人明确通过当前 Prompt 版本 | 用户或指定审核人明确通过该版成片；不等于已完成游戏接入或实际试玩 |

| 待更新 | 已有稿件收到新修改要求、参考图变更或合并要求，尚未完成处理及回读验证 | 已有视频需要重做、返修或重新适配新版Prompt；保留旧片路径供核对 |

上传、格式检查、版本一致性检查及助手自查不等于人工审核通过。不得仅因同步完成把“待review”改成“已通过”。读取现有用户选择后只改本次有依据的状态，不批量重置。

只有非停用、非保留、非待定项目，且 Prompt 已通过、当前版本与审批版本一致、制作已获得用户授权，才能进入生成操作。Prompt 处于待review或待更新时，不自动调用视频生成服务；备注有未处理的明确修改意见时也不能绕过审核，即使下拉暂未调整。

## 改稿、发布与回退

1. 先读取表格链接的在线正文和本地当前稿，确认用户没有在另一端改出新版本；出现差异先比对，不直接覆盖。
2. 当前本地提交入口为 `video/production/CURRENT-20261021/`。历史 v3/v4、来源包及旧导出包保留历史身份，不能按目录名中的“最新”混用。
3. 每个请求独立成文，保持项目的 Seedance 标准格式：四行参数开篇、按序真实参考图、逐镜时间与参考关系、连续性、拍摄手法参考、末段声音要求。版本说明与审阅记录放台账/规则/审阅文档，不插到生成文档末段声音要求之后。
4. 优先在原飞书文档上更新。上传真实图片并核对编号、身份及顺序；本地路径文字不能替代附件。时长、分镜或图号有变化时同步修改对应表格单元格。
5. 更新后重新读取在线正文，对比全部文本、参数、分镜和参考图顺序；保存本地文件哈希、在线文档修订号、核对时间及链接。不能仅因 URL 相同或旧校验通过就宣称最新。
6. 已有Prompt收到修改意见或实质改动后，原审核失效，先标“待更新”；完成修改、同步并重新读取验证后回到“待review”，不能直接改“已通过”。尚无完整初稿时才用“待生成”。已有视频若受改稿影响则标“待更新”，保留原路径并说明旧稿关系；新片或返修片到齐后再送待review。
7. 新片产出后填写真实路径、当前状态改为待review；通过审核后才标已通过。游戏接入、播放与存档触发另行验证，不从文档状态推导。
