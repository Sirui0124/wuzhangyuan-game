# 本地视频制作台账与 Prompt 规则

维护日期：2026-11-17。制作索引、Prompt、意见与审核状态均在本地维护；不以外部表格、在线文档或同步快照作为前置条件。各制作目录的当前索引明确指向正文与成片，不能按目录日期自动认定最新。

## 台账内容

保留场景编号、名称、内容说明、当前Prompt路径、Prompt状态、用户待更新意见、时长、视频状态、处理反馈及当前视频路径。沿用稳定编号；写前读取当前字段与原值，写后核验。用户原始意见及对应版本依据不得丢失。停用、取消、保留及筹备限制仍有效，不因清理旧稿恢复制作。

## 两套状态独立流转

两列均沿用用户当前设置的四个下拉值，大小写保持原样：**待生成、待review、已通过、待更新**。正常流转为待生成→待review→已通过；收到返修意见后为待更新→待review→已通过。不擅自改名或扩展选项。

| 状态 | prompt状态 | 当前状态（视频） |
| --- | --- | --- |
| 待生成 | Prompt 尚未编写完或尚无可提交的完整文档 | 对应版本的新视频尚未产出；包括仍在生成的过程，完成后再改待review |
| 待review | 完整 Prompt、参考图、时长和分镜已整理到链接文档，等待用户或指定审核人确认 | 实际新片已产出并填写路径，等待画面、声音及前后衔接审阅；需要返修时转待更新，并在待更新的备注中保留问题 |
| 已通过 | 用户或指定审核人明确通过当前 Prompt 版本 | 用户或指定审核人明确通过该版成片；不等于已完成游戏接入或实际试玩 |
| 待更新 | 已有稿件收到新修改要求、参考图变更或合并要求，尚未完成处理及回读验证 | 已有视频需要重做、返修或重新适配新版Prompt；保留旧片路径供核对 |

文件生成、格式检查、版本一致性检查及助手自查不等于人工审核通过。不得仅因同步完成把“待review”改成“已通过”。读取现有用户选择后只改本次有依据的状态，不批量重置。

## 游戏选片与版本核验

用户明确选定或要求保留的版本优先；其余比较当前剧情、已处理反馈、画面与声音，不能只按上传日期或文件名里的“最新”判断。新片存在问题时明确标记，不能把“最新可用候选”写成“最佳定稿”。没有更好成片时保留问题，不通过删减内容掩盖。

每次确认游戏采用版本，联合核对本地当前台账、项目原片目录、原始来源、剪辑/混音记录与实际播放文件；按内容哈希核验，不能仅核对路径和文件名。组合片逐段追溯，例外保留片单独注明。当前选片明细见 `VIDEO-SELECTION-MANIFEST.json`；该文件是日期明确的核验快照，后续更新仍须重新读取本地当前台账。播放器稳定ID中的旧日期不代表影片旧版，实际资源路径及内容才是依据。

只有非停用、非保留、非待定项目，且 Prompt 已通过、当前版本与审批版本一致、制作已获得用户授权，才能进入生成操作。Prompt 处于待review或待更新时，不自动调用视频生成服务；备注有未处理的明确修改意见时也不能绕过审核，即使下拉暂未调整。

## 修改与交付

1. 读取当前索引指向的本地正文、参考图与用户意见，比较原值，避免覆盖并发修改。
2. 按 Seedance 规则逐请求独立成文，检查时长、分镜、声音、图序与路径。参数格式见 [固定规则](SEEDANCE-DOCUMENT-RULES.md)。
3. 台账记录当前提交文件的内容哈希、审核状态及必要依据；生成成功不等于已审核。
4. 已有稿件发生实质修改，标待更新；完成和核验后改待review，用户明确通过才改已通过。
5. 交付每份本地正文的绝对路径，不生成压缩副本。旧稿、旧同步快照和重复报告不另行保留，历史查 GitHub。
6. 删除旧素材前检查实际播放、当前剪辑、参考图及用户明确保留的引用；仍有用途的来源不是冗余版本。游戏接入与实际播放另行验证。

制作必须在当前授权内进行；待review不自动触发生成。已取消或要求保留的段落不能仅凭台账状态恢复制作。
