# 文案表如何转成游戏视频与生成Prompt

2026-10-23。适用于《逆转五丈原》各章。对白来源是在线文案表的实时表头、稳定编号和原句；本规范解释演出方法，不增加剧情，也不取代章节判定。当前逐句执行为七列。

## 2026-10-25用户实审后的优先规则

用户已否定影片中出现工作文档式文字及明显方框模糊层。下方“后期准确叠加”仅可指游戏独立信息层或另外明确获准的字幕文件，不再授权把说明卡、账页摘要、流程文字或字幕列表烧入视频。精确内容仍保留来源和事件映射；拍摄用真实动作与合适构图承载，不能删去剧情事实，也不能只拆遮罩让伪字重新暴露。必要时重拍相应镜头。

生成请求每镜将“声音执行（控制说明，不朗读）”与“唯一允许发声的原句”分开；只能朗读后者引号内真实原句。说话人、受话人、画内／画外、旁白类型、原编号、表演指示保存在结构化制作映射，均不得混入TTS的text或台词引号。“苟安说”“苟安叮嘱”“我画外”等元说明不能变成声音。无台词镜头明确无对白、无旁白、无额外人声，保留无BGM要求。

检查必须实际覆盖是否误读元说明、烧入工作文档文字及出现可见方框补丁。ASR可定位误读，最终不能用未听审的ASR输出声称逐字通过。用户点名的静音、删除和替换区间以其所评具体文件版本为准，保留旧文件、原评论与修订映射。

## 七列分别控制什么

| 文案列 | 视频中的对应 | 不能误读成什么 |
| --- | --- | --- |
| 编号 | 对白、动作、字幕、切点与游戏事件的追溯键 | 文件顺序不代表强制交谈顺序 |
| 说话人／类型 | 决定谁发声、谁有说话口型，以及是否是心声、旁白、演出或界面 | 画面上出现的人不一定是说话人；相邻上一行人物不能继承本行台词 |
| 一句对白／界面文案 | 原句逐字进入对应音轨；演出说明转成动作，界面文字由游戏叠加 | 不润色台词，不把导演说明、按钮或AI例句读出来 |
| 线索录入／引用（人工） | 确定听完哪句、读完什么或实际发生什么之后才取得信息 | 镜头拍到了、生成预览完成了不等于玩家已经取得 |
| 线索（编号） | 把实际播放片段映射回原证据来源 | 不因为切成视频就新建相同线索 |
| 触发条件逻辑（人工） | 决定播放前提、自由顺序、互斥、暂停、确认与行动后果 | 不能为少生成几条而跨过用户选择、实际授权或回令 |
| 触发条件与逻辑衔接（编号） | 程序执行对应事件，建立续播／返回／重试边界 | 不让视频模型生成按钮或自行决定判定结果 |

## 每句都要有演出对应关系

在Prompt中，每句明确列出：原编号、原说话人、受话对象、声音位置、允许开口的人、必须闭口的人、听者反应、原句。不能只在整片开头写“第一人称”后，便把双方台词堆在同一镜头下面。

| 内容类型 | 声音与口型 | 合理反应 |
| --- | --- | --- |
| 我（普通对白） | 我的声音从镜头位置／画外传来；我可以不出镜，对面的NPC不做本句口型 | NPC把目光落在我身上，先听再回答；按信息轻微抬眼、压住步伐或短暂停顿 |
| NPC对白 | 只有该NPC做本句说话口型；受话对象由原剧情明确 | 听者可在画面或画外，反应有动机；不能所有人一起张嘴 |
| 我（心声） | 同一声音身份，更近、更轻；是内心声音，对面的NPC听不见 | NPC不能针对这句点头、接话或露出“知道我重生”的表情 |
| 旁白 | 画外叙述，人物不对旁白做说话口型 | 画面呈现原叙述对应动作；不强制安排听者 |
| 演出 | 实际动作、视线、空间或非语言声音 | 不把“姜维转身迎向魏延”等说明念成台词 |
| 选项 | 用户选中后才发生相应发言或行动 | 预览／悬停时NPC不提前回答 |
| 问题、反馈、结算、告示 | 原文由游戏或后期准确叠加；是否有声音按原设定 | 不能把界面反馈误作NPC的指责或新增旁白 |
| AI动态发言 | 用户确认后的原话与AI当前回应分别流式生成 | 不用示例代替本次原话，预置视频不重复播放动态回应 |

### 必须这样填写的一句

原编号J08；说话人：我；对象：姜维；声音：我的男声从摄影机位置传来、画外发声；画面：姜维站在对面，听见请求后把目光落向我，闭嘴倾听，微收下颌；姜维此时没有说话口型。对白：**请将军在帐外接报。**

随后J08A仍然是我向姜维说明：**敌军尚未攻营，但今夜有变，不能耽误。**姜维继续闭口倾听，注意力转向营前。帐内低咳后，他回望帘子，再转回作决定。到J09“禁令不能犯，军情也不能误。”才由姜维开口。不能让姜维先对自己提出接报请求。

J10B“将军现在便去？”也是我问姜维，姜维只听；J11“我就在这里等他。你把话传到。”才是姜维回答。E09为我向魏延复述军令，姜维和魏延均不替我说；E10才由魏延回应。W04、W05是亲兵对魏延作证，不能让亲兵面对摄影机像给我讲新授权。

## 表演必须有动机

每镜先写当前人物想做什么、刚听到什么发生变化，再选一个能看见的动作。例如魏延原本要赶往中军帐；听见姜维本人答应且亲兵作证，才先停步看亲兵、听完后把路线交给我，转向来路并正常迈步。不要写泛泛的“威严、震怒、电影感”，也不要让他无缘由连续瞪眼、皱眉、甩手、来回走。

听者反应使用少量自然动作，不要求每秒眨眼、机械点头或持续喘气。说话时身体有重心与呼吸，听话时嘴唇自然合拢；只有原句说话人开口。无需每句话切镜，按动作或信息变化切。

## 参考图分工

1. 人物身份图只锁脸、年龄、发型、胡须与衣甲；优先用单人、放松站姿、闭口的身份图。多人旧场景图若作身份参考，明确只取哪个人，不继承其他人物、站位或表情。
2. 场景图锁门帘、帐篷、灯火、道路、桌案和方向；中军帐与将军帐分开。人物不能在两处之间变形瞬移。
3. 当前镜头需要多人关系时，另给站位／构图图，明确谁在画面左、右、近、远以及互相看向谁。身份图和构图图不能互相覆盖职责。
4. 表情和动作要由当前动机决定，不能让一张怒脸身份图控制所有镜头。普通对话优先中近景，听者可以看摄影机位置，但不持续怒瞪观众。
5. 第一视角不等于每镜必须有手和长矛。对话可将手、矛放到画外；仅在醒来辨认自身、握持变化、放松、收矛等有叙事作用时出现。步行时道具可短暂掠过，不固定竖成画面边框。避免一张持矛首帧把整片锁成僵硬站桩。
6. 精确首帧必须符合本镜当前站位与情绪；未制作的构图图只能标待准备，不能把图片描述当成已交付图片。

## 时间、切点与游戏确认

单条生成请求不超过30秒（2026-10-25用户最新要求，覆盖此前15秒上限）。视频生成API已过期，待重生成内容按既有Seedance格式交付独立Markdown，由汇总对话统一提供正文链接，详见[本次交付要求](VIDEO-API-HANDOFF-20261025.md)。按剧情需要确定正整数时长，不强行凑满30秒，不跨互斥分支或玩家交互停点合并；必要行走、起步、落脚、到达与人物反应保留。对白可以比同一角色自然语速快10%—20%，不得吞字、改词或让所有动作一起加速。

先生成完整表演，再依据实际声音与动作裁出用户确认点。预估分镜时间不是实际句末；切点须避开一个字、一次手势和正在落脚的中间。确认前只能展示已发生部分，后半段不得提前自动播放。甲乙自由顺序、用户确认发言、授权、接报和回令分别记录，不能用影片播放状态替代剧情条件。

## 成片检查和返修分类

对每条建立“时间码—原编号—实际声音—画面开口者—受话人—事件”的核对记录。语音识别只帮助定位，错别字和谐音不能直接当作演员念错；说话人更不能仅凭识别文本判断。需要结合原声与对应时段的口型、视线和动作。

- 缺字幕、开头／结尾空余、确认点未切开：通常可以剪辑或补正确字幕。
- 第一句画外音缺失，但听者画面正确：可补录同音色画外音，不一定整片重拍。
- 画面中的NPC替我张嘴说台词、授权对象错误、反应和动作改变剧情：返修对应镜头或重拍；不能只换字幕掩盖。
- 表情僵硬、无动机甩手、到达后又倒回起点、缺少必要同行过程：重新安排动作与参考图；不能只加速凑节奏。
- 素材缺失：保留原文流程作为明确回退，不把别段视频重复利用成“已经补齐”。
