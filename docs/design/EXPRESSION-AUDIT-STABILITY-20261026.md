# 润色生成与审核稳定性（2026-10-26）

用户要求：看起来是格式问题，不应笼统报成内容错误；把内容审核和生成稳定性做好。

## 已确认的问题

旧适配器把 JSON 格式、总判断 supported、五个分项和成功理由全部绑在同一错误里。五项为真而成功理由为空、缺失或过长，也会提示“未能保留原意或依据边界”。截图当次原始审核响应没有保存，不能据此断言历史那次一定属于格式错误。

## 实现

- 审核只要求 intent、actors、facts、items、coverage 五个真正的布尔值。全部通过不强制成功理由；取消 prompt 中重复的 supported 总判断。兼容旧响应，但旧总判断否定而五项通过属于矛盾格式，重新核对。
- 生成 JSON 基本结构异常自动重试一次；审核格式异常针对同一个候选和同一份来源自动重试一次。字符串 true 不强行转换成布尔值。支持带空白、JSON 代码围栏的响应。
- 真实内容错误只自动修正一次。修正使用原始材料与具体问题，生成新稿后重新独立核验，不直接采用修正稿。所有重试可取消，取消后不继续请求或写入会话。
- 最终失败保留输入和旧稿，区分服务格式问题与具体内容类别；会话保存 diagnostic 的类型、问题项、理由和未采用候选，便于排查。未确认前不发言、不发线索、不消费物品、不推进剧情。
- 润色核验不代替 NPC 的玩法判定；本次没有修改物品对话的通关规则。
