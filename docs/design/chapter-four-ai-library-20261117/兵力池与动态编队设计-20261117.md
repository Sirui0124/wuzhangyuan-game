# 第四章：兵力池与动态编队设计

2026-11-17后续：现版开局改为甲队500人＋预备兵2000人，总计2500。其他队伍出征后才创建，最多5队；本段替代下文旧版2000人、0预编队提案。危机度与故事入口、实际参数见实施记录。

2026-11-17更新：用户授权“把数值调整到你认为平衡有趣，然后接入游戏”后，核心闭环已接入游戏内三路军令试玩，待用户审核。实际参数、实现范围和2400局引擎测试见[实施与平衡记录](兵力池接入与平衡验证-20261117.md)。下文保留设计推导；其中行军增援、拆并、自动策略难度目标属于后续方案，不能当作已实现功能。

## 1. 核心判断

建议采用共享兵力池。开局2000名可战兵、0支任务队；确认派遣后才形成队伍并出现在右侧。玩家面对的是“救哪一路、派多少人、做什么、何时撤回”，而非先适应甲乙丙丁固定编制。

三路共用这2000人和5个队伍名额。否则三路分别拥有2000兵会消除调度取舍。五队是同时尚未归营的任务队上限，包括已确认待出发、途中、执行、脱离和返营队伍；已经结束任务且归营解编的历史队伍不占名额。

改版前代码是四队700/800/600/400，共2500人；傅肜与另外两路存档隔离，没有战损，岗位达最低人数后便提供完整效果。此次是对该体系的重设计，不能仅改人数常量或右侧显示。

## 2. 兵力账本与动态编队

### 兵力守恒

`2000 = 营内可战 + 已预留待出发 + 在外可战 + 全部伤员 + 阵亡`。

- 初始营内可战2000，其他为0。救回的原部众与接应兵分账，不能把营救对象当作无限补兵来源；傅肜原部众已全部战死的剧情保留。
- 新编队、营内补编、分派增援，以100人为单位。战损按人计算，因此500人出发、损失37人后应显示463可战，而不是偷偷取整到400或500。
- 营内散数保留：例如回营463人，营内若原有137人，合并为600，可重新派600。可下达的新兵力为`floor(营内可战/100)*100`，零头不是死亡。
- 整队撤回、整队改令以真实现存人数执行，不要求伤后部队重新凑足100。
- 队伍用不可复用的内部ID；显示为“第1队、第2队……”顺次编号。最多同时5支，不把返营后新建的第6队错误判断为超上限。旧命令必须引用原ID，不能命中新队。
- 确认派遣立即预留人数和队伍名额，下一战术轮才出营。取消尚未执行的军令释放预留；多个操作组成一批时一次校验、一次预留，整批成功或整批拒绝，不悄悄只派部分队伍。

### 常用命令

| 玩家表达 | 解释与反馈 |
|---|---|
| 派500人接应沙摩柯 | 新建一支500人的护送队，复诵目标与任务后确认 |
| 再派300人替傅肜断后 | 新建300人掩护队，检查剩余人数和第五队名额 |
| 第2队改去接应张南 | 原队改任务，原岗位停止生效，按真实距离重新计算到达轮次 |
| 第2队撤回来 | 现存可战人员携本队伤员返营，返营途中继续占名额 |
| 给第1队补200人 | 200人增援需要实际行军；占一个临时队伍名额，到达同位置后合并并释放该名额；满5队时提示先召回一队 |
| 派350人 | 提示按100人编队，可选300或400，玩家选择前不自动舍入 |
| 派一些人去救他 | 若对象或人数无法从明确上下文确定，先补充；不得默默默认100人 |
| 全部撤回 | 复诵会撤走哪些掩护岗位及可能后果，确认后全部返营 |

首版不提供在敌前任意拆队或跨地点瞬间合并。合并需同一路、同地点，受合并的队伍原任务撤销；战损、已执行进度、伤员一起合并，不能借合并清除疲劳或刷新效果。该功能可晚于核心闭环实现。

## 3. 右侧军情与对话

开局右侧显示“军情调度”，一行“待命 2000”，下方“尚未派遣”；不预先摆五个空卡片。出现损失后才增加“伤员/阵亡”摘要，可展开查看历史。

派遣后每队一行或两行：`第1队 · 463人` / `护送沙摩柯 · 途中 · 1轮后到达`。存在伤员时显示`伤27`，并明确463指可战人数。常用状态限定为待出发、途中、执行中、撤回中；人数不足、受阻、失联用事件提示，不塞进长期表单。点击队伍只是把左侧传令对象切到该队。

左侧仍保留“派遣队伍：新编队/已有队伍”与“目标：自动识别/三路对象”。人数、任务、急行等通过正文表达；复诵中显示可直接改写的人数及方向、执行轮次、派后余兵和队伍占用。下拉手选优先用于补全缺失字段，与正文冲突时明确指出冲突。

不要求“先派侦察、再下第二种固定口令”。推荐问题用于了解处境，军令解析输出结构化草稿，AI不能直接扣人、造事实或计算伤亡。

## 4. 回合与任务体系

沿用10秒问话/军令共用冷却，以及显式“结束本轮”。冷却恢复发送资格，真实时间、阅读和对话都不自动造成伤亡。只有玩家结束本轮或明确确认等待，才推进三路共同战术时间。技术重试不消耗轮次。

同一轮的顺序固定为：校验已预留军令 → 出营/改令 → 行军和已到位任务 → 结算本轮接敌战损 → 用幸存兵力投影下一轮岗位效果 → 提交三路状态与回执 → 归营释放名额。撤离抽签使用本轮开始执行时的有效岗位；伤亡影响下一轮，不先减少人数又追溯取消已经完成的当轮成果。一个队一轮只做一个主任务。

| 任务 | 首轮建议规模 | 行动逻辑 | 持续价值 |
|---|---:|---|---|
| 查明消息/侦察 | 100 | 通常1轮行军，完成后返营；核实刘备分两次真实回报，保留现有时序 | 情报事实保存，不因侦察队返营消失 |
| 护送沙摩柯 | 400起 | 东沟、再西沟担架，顺序由原剧情确定 | 人多加快运送，但存在道路容量上限 |
| 护送旧营 | 400起 | 先前队，再后队伤兵 | 必须真实完成两段，不能只接前队就算整路成功 |
| 护送傅肜 | 300起 | 一人营救也需要穿越追击区的接应队；须衔接其真实剧情状态 | 不替代核实刘备消息与说服 |
| 掩护/换防 | 沙200、旧营300、傅400起 | 到位后持续牵制，主动撤走即失效 | 保护护送、降低暴露损失，不能同时兼任护送 |
| 压制追兵 | 400起 | 用更大兵力争取撤离窗口 | 后续联调岗位；本轮三路物流模拟只用掩护，不声称测过压制 |
| 撤回/归营 | 现存人数 | 通常1轮返程，绕路或伤员可延长 | 归营解编，可战兵回池，伤员转入营内救护 |

表中“起”是建议有效规模，不是低一人就完全失效的硬门槛。100人护送可以执行，但完成慢、风险高；复诵必须说明“兵少，预计至少多花几轮”，不能让玩家到结束时才发现不可能。

岗位收益按当前可战人数连续变化。同岗位多人合计后再算，达到道路容量后递减，不能通过拆成五支百人队获得五次固定加成。侦察、信号等事实只确认一次，不按队伍数重复降危机。建议规模与公式见实验报告v2；这些数值尚未接入正式撤离判定。

## 5. 战损、受伤与撤退

- 首版采用可战、伤员、阵亡三类，不再增加士气、粮草、装备耐久等独立资源条。按接敌程度和任务暴露逐轮结算；营内待命、单纯阅读不受损。
- 伤员失去本次战斗资格，归营后不在几轮内自动治愈变回可战兵。可在章节结束记录救护结果，避免利用等待刷恢复。由其他剧情提供援军必须有独立来源和一次性事件。
- 伤亡从实际参战队伍扣除；每支队伍记录可战、随队伤员、累计阵亡。战损率不高于当轮可战人数，无负数、无隐形取整损失。
- 返营带回伤员；全队失去行动能力时进入待救状态，伤员不能瞬移回营，也不能凭空消失来释放名额。允许“接回第3队伤员”或确认放弃该队。全员已死亡则队伍结束，名额释放，历史保留。
- 低于原始兵力40%时发出具体告警并建议撤退；是否自动撤退应作为复诵中可选的保全策略，默认建议“尽力保全”，触发后先撤离，不继续接受强攻。玩家明确死守时再次说明风险。
- 正式随机战损建议按人抽样或等价二项分布；本次离线模型用有边界的正态近似，仅用于均值和策略趋势。实验还将所有伤员抽象汇总，不含失能队救援与伤员拖慢行军，因此不能估计极端溃败体验。

## 6. 紧急程度、剧情与胜负

红色数字继续表示前线危机，不能表示队伍剩余人数。兵力、危机、撤离概率是三个量。当前傅肜99不代表立即死亡；本提案同样不将99改成隐藏即死条件。

傅肜既有查明刘备、生死观与战友情冲突、接受继续护主、实际护送/脱险/归营的状态保持分开。兵力充足不自动授予对话成功。现有纯机制允许某些未说服情形下的撤出，是否保留这些分支应按原设计审核，不能在编队改造时悄悄统一成“必须说服”。

建议保留现有危机公式作为第一版联调基线，但把军事岗位事实与新人数曲线衔接。知识与对话分支仍为真实条件触发；军事分支可按有效人数比例贡献，最高不超过既定分支上限。此“连续贡献”是提案，需要单独兼容纯机制与存档，不直接改现有布尔事实真值。统一四舍五入只发生在最终危机显示/公式输入处，避免每个小队分别取整套利。

章节目标分层：先统计三路救援结果，再统计救回人数和接应兵损失。全救且损失低为较好结果；部分救援可有代价结局，不把非完美局一律判游戏失败。具体章节推进必须由主线设计确定；本轮实验只测物流完成，不能决定谁死亡或是否允许进下一章。

危机长期高位且无进展时应报告具体缺口（撤路未通、掩护不足、队伍被占满），允许撤回重配。不能为了制造难度偷偷让后台时间流逝。若后来采用局部撤离窗口，必须提前军报告知并给出可行动的轮数，另行设计失败分支；本轮测试的轮次预算只用于比较，不作为已确定的剧情倒计时。

## 7. 难度设计与抗固定解

三路需求应不同：沙摩柯重运送伤兵，旧营重前后队衔接，傅肜重后阵掩护与对话条件。五队上限使“三路各护送+掩护”无法同时完整配置，玩家需要轮换、撤回、暂缓一路或接受较慢的无掩护接应。

第一轮实验暴露了统一200掩护阈值下600护送+200掩护几乎独占最优。第二轮按路增加掩护需求并限制护送拥挤收益，检查投入与损失的取舍；数值结果详见报告，不能预先宣布已达平衡。

难度优先改变敌方暴露、道路任务量、已预告的窗口长度；2000初始兵和100人编队规则在各难度保持一致。普通难度需容许至少一次错误派队与召回，困难增加三路次序取舍，不能提高理解中文的门槛。10秒冷却只影响节奏，不作为核心难度调参。

## 8. 实现与验证分界

建议顺序：共享资源账本与动态队伍 → 原子预留/取消/归营 → 左侧解析与右侧列表 → 实际战损/岗位持续效果 → 三路剧情接入 → 真玩家试玩。新schema与旧四队存档分版本保留；既有2500人局不能静默缩水为2000，也不能用新数值伪装旧局通过。

必要接口包含`reserveAvailable/reserved/wounded/dead`、动态`teams[]`（稳定ID、可战人数、伤员、任务、位置、到达轮次）、`pendingOrders`和统一`round/revision`。解析不再使用固定甲乙丙丁联合类型，前端不得另算一份兵力。现有旧营/沙摩柯预设与傅肜独立会话必须在共享兵力测试前整合，否则UI显示一个兵池，后台仍各扣各的会制造虚假资源。

验收至少覆盖：超支与第六队拒绝、非百人数确认、战损后整队改令、多人多队批次原子性、已确认未执行占用资源、取消释放、归营解编、增援途中占名额、失能伤员不瞬移、不同位置不合并、同ID重试不重复扣人、刷新不重掷、原队ID不命中新队、AI失败保留草稿、三路共享存档版本。此次脚本只覆盖其中基础账本与策略模拟，其余是后续接入验收，不写成已通过。
