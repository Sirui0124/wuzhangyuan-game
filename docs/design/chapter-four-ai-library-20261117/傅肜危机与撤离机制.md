# 傅肜危机与撤离机制

2026-11-17 · v3 · 傅肜已接入8956独立试玩的真实AI、派队与回合结算，待用户试玩review。其他人物仍为预设演示；未接入正式主线章节运行器。实际范围与验证见[接入记录](接入与验证-20261117.md)。

玩家用自己的话与傅肜交涉，通过接应行动降低他的危机度，每个战术轮有一次脱险判定。99是最危急，0表示没有当前危机。低于10的有效撤离判定设为100%，避免玩家已经做足准备，却因极小概率反复失败。

本版按用户最新要求替代旧稿“傅肜对话完全不影响数值”的约束。说服只改善撤离意愿，实际接应仍贡献更大；普通关心、闲聊和重复劝说不反复记分。其余人物暂不套用本数值。

## 角色与文风

傅肜深受刘备恩遇，断后是为拖住吴军、力保刘备。吴军谎称刘备已死，身边弟兄又全部战死，使他想要殉国，不愿独自逃走。刘备实际未死，原部众战死是既定事实，新接应队不是原部众。

说服需分别回应两层动机：用真实且已送达的证据澄清刘备未死，再回应独活愧疚，让他认可活着继续护主、亲自说明这一战的意义。不能仅用“有人接替”“一起撤”就完成说服。完整阶段对白见[傅肜剧情](傅肜完整剧情与自由对话.md)，生成Prompt与语义分支见[JSON](furong-rescue.design.json)。

我：刘备没死，吴军骗你的。

傅肜：你从哪儿得的消息？

我实际出示并核验有效消息后，傅肜才会承认误信；这仍未解决弟兄皆死的愧疚。

傅肜：陛下还在……可跟着我的人，一个也没剩下。我把他们留在这里，自己回去？

## 危机怎样降低

危机按当前有效因素重算，而不是每看到一次台词就扣一次：

`C = clamp(99 − 各组有效降幅之和 + 持续受困压力, 0, 99)`

| 分支 | 条件 | 降幅 | 作用与限制 |
| --- | --- | ---: | --- |
| FU-B01 愿意活着继续尽责 | 已核实且送达刘备未死的证据，并通过回应丧友愧疚的说服 | 12 | 改善意愿，同一承诺只算一次；撤回方案则失效 |
| FU-B02 探明撤路 | 有仍有效的侦察回执 | 10 | 知道能从哪里走；不靠玩家自称 |
| FU-B03 打开替代撤路 | 绕行任务已完成、路线仍可通行 | 20 | 与探明撤路同组，只取20，不累计成30 |
| FU-B04 有人接替断后 | 接替队已到位、完成交接且仍掩护 | 24 | 降幅最大；仅出发或下令不算，撤走则收益失效 |
| FU-B05 压住追兵 | 真实战斗回执确认压制仍有效 | 18 | 利用追兵暂退的窗口；敌军恢复即失效 |
| FU-B06 确认刘备已脱险 | 可信回执确认刘备已脱离当下追击，且已送达傅肜 | 18 | 傅肜留下的责任已经部分完成 |
| FU-B07 护送队接上 | 护送人员与任务对象会合，具备护送能力 | 16 | 新接应队确实具备护送傅肜的能力；原部众已全部战死 |
| FU-B08 约好撤离时机 | 接受继续尽责，且确认信号已实际送达 | 10 | 避免前后互等；只有玩家口头说了不算 |

真实队伍不能同时占多个互斥岗位。接替、护送、压制是否能同时成立，须由战场适配层根据不同队伍或真实的先后行动判定；不能把同一队“已到达”复制成三个因素。探路、换防、信号等尚未制作的动作不能在UI假演示中冒充完成。

条件失效时相应降幅消失，危机会回升。再次恢复同一掩护只是恢复原有24点，不会永久再减24。侮辱、闲聊、正常质问不扣分，不触发死亡。

## 每轮撤离概率

设本轮行动结算后的危机为C，脱险概率为：

```text
C < 10：p(C) = 1
10 ≤ C ≤ 99：p(C) = 0.99 × ((99 − C) / 89)²
```

| 危机度 | 本轮脱险概率 |
| ---: | ---: |
| 99 | 0% |
| 90 | 1.01% |
| 80 | 4.51% |
| 70 | 10.51% |
| 60 | 19.01% |
| 50 | 30.01% |
| 40 | 43.51% |
| 30 | 59.50% |
| 20 | 78.00% |
| 10 | 99.00% |
| 9及以下 | 100% |

高危时仍需改善局势；越接近安全区，准备的效果越明显。这是一条本项目初版平衡曲线，并非从崇祯模拟器恢复出的算法。99和低于10的边界依用户要求设定，指数2、各分支降幅与压力参数是本轮设计值，尚待试玩评估。

本轮未脱险，仅代表这次没能撤出，不意味着死亡。结算后持续受困压力加2，最多20，作用于下一轮；已展示并用于本轮抽签的概率不追溯改动。玩家可以等待再试，但长期只等待会更难，继续改善条件更有利。全因素成立时，即使压力达到20，危机仍为1，能确保最终脱险。

失联时没有有效撤离判定，显示“暂时失联”，不把最后已知危机当实时情报。恢复联系后按新的有效事实继续。危机99不自动判死，本设计未新增死亡倒计时。若整章另有已授权的结局期限，适配时先处理终局资格，不允许已结束任务重新抽签。

## 一轮怎样推进

采用独立战术轮，沿用UI负责人的建议。确认军令先加入本轮行动批次；玩家可安排多队，最后点击“结束本轮”，或明确选择“等待一轮”。同一轮三支队伍行动，只给傅肜一次判定。10秒发送间隔只控制发送频率，不代表一轮。

结算依次完成：校验存档与轮次版本、处理本轮真实行动、投影有效事实、计算危机和概率、抽取一次随机数、原子保存结果与随机状态、展示战报和人物回应。AI只解释已经发生的结果，不能自行说抽中了。

问话、草稿、反复劝说、刷新、模型超时重试、切换对象及冷却结束都不抽签。有效说服可以更新危机预览，但仍要结束本轮才判定。没有任何行动也可明确等待，不强迫玩家为了推进而乱下军令。

随机数由游戏程序产生。一次结算以存档场景ID、角色ID和战术轮ID唯一标识；重试返回原回执，提交不同内容到已结算轮次会被拒绝。随机状态与结果随存档保存，刷新不获得新机会。这里防的是正常刷新重抽，不承诺防止玩家直接篡改本地文件。

## 三种脱险路线

这些是组合示例，不是三句固定口令，也不是缺一个因素就完全不能脱险。

| 路线 | 主要准备 | 无额外压力时的危机 |
| --- | --- | ---: |
| 换防接回 | 接受继续尽责、替代撤路、接替断后、刘备脱险确认、护送就位 | 9 |
| 压制后撤 | 接受继续尽责、替代撤路、压住追兵、刘备脱险确认、护送就位、撤离信号 | 5 |
| 常规接回 | 接受继续尽责、探明原撤路、接替断后、刘备脱险确认、护送就位、撤离信号 | 9 |

例如第一轮先说服并完成探路，危机为77，本轮约6.05%机会脱险。若没撤出，下一轮压力为2；接替和护送再到位后，危机降至39，约44.99%。之后确认刘备脱险、送达撤离信号，可以继续压低危机。判定随玩家实际准备发生，不要求照示例顺序操作。

成功判定指傅肜与实际参与撤离的新接应人员已经脱离险境，本次撤离不新增伤亡。它不复活此前伤亡，也不替其他路线宣布获救。“已脱险”和“已归营”分开：成功后危机显示0，停止抽签，保留护送归营流程；营门回执到达后才说已归营。随机成功不是一条口头承诺，必须生成一次权威撤离事件。

## JSON与程序的分工

- [furong-rescue.design.json](furong-rescue.design.json)包含人设、文风Prompt、参考对白、逐阶段历史轮数、语义分支正反例、8个危机因素、概率参数、轮次与UI约定。
- [furong-rescue.ts](furong-rescue.ts)是可独立运行的纯机制：校验配置、重算危机、计算概率、结算轮次、保存可重放随机状态、输出只读CrisisView。
- [furong-rescue.test.mjs](furong-rescue.test.mjs)验证数学及状态边界，不模拟真实模型理解质量。
- [UI接口对齐](UI-接口对齐-20261117.md)由【调整第四章队伍界面】维护。本模块已经按其建议输出crisis、withdrawal、phase和lastResolution，界面不复制公式。

分类器只输出语义结果与原句证据，不输出危机减多少、抽签数或是否已脱险。程序只允许经校验的说服结果更新withdrawalAccepted；刘备生存与安全事实必须由真实证据及送达记录投影，其他事实来自行动账本。回应器读取已校验结果和角色Prompt，独立生成自然台词。

纯模块接收的facts是宿主信任边界，不是前端输入接口。receiptIds仅用于绑定与追踪，不能仅凭一个ID就认定回执真实。接入方必须核查账本归属、事件类型、队伍岗位、时序、事实有效期与角色可知范围，并原子保存结算；本轮样例没有实现生产存档、联网鉴权或战场动作执行器。

最后一次回执里的probability是实际抽签概率；CrisisView规划态里的概率已包含未脱险后的压力，是下一轮预测，两者不能混标。本轮变化原因列表是当前有效因素解释，不是每次刷新又减一次的增量。抽签数和种子只留开发日志，不交给角色或常驻界面。
