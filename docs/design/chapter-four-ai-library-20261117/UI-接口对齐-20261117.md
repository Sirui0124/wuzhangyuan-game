# 第四章 UI 与危机机制接口对齐

2026-11-17。依据用户在“设计傅肜第四章AI剧情库”中明确授权实际接入并与本界面对话配合的要求，8956前端现已接入傅肜独立营救会话、AI对话、军令入列、战术轮结算和危机展示。状态：已实施、开发验证完成，待用户体验；未声称接入8812正式章节。

当前适配基准为`furong-rescue.design.json`的`2026-11-17-v3`、`fu-runtime.mjs`的会话契约和`src/fu-client.ts`的类型。旧接口建议已由以下实际约定替代，历史版本由Git追溯。

当前8956界面保留三路入口、输入框上方的传令铜牌、右侧军情调度简报。傅肜使用独立服务端会话，沙摩柯和旧营仍为预设演示，两类队伍与记录不共用。傅肜10秒发送间隔由`session.nextSendAt`提供，只限制问话和确认军令，不阻止“结束本轮”。旧傅肜延时队列保留但不再执行，旧日志仅在说明窗只读查看，不作当前事实。

## 只读视图接口

机制模块提供一个只读快照，UI只展示，不自行计算概率或抽随机数：

```ts
type CrisisView = {
  schemaVersion: 1;
  scenarioId: string;
  frontId: 'fu' | 'sha' | 'camp';
  revision: number;
  tacticalRoundId: string;
  phase: 'planning' | 'resolving' | 'resolved';
  crisis: { value: number; delta: number; reasons: string[] };
  withdrawal: {
    probability: number; // 0..1，由机制模块返回
    eligible: boolean;
    blockers: string[];
    status: 'holding' | 'eligible' | 'withdrawn';
  };
  lastResolution?: { roundId: string; resolutionId: string; outcome: string; probability: number; crisis: number };
};
```

按2026-11-17用户最新要求，危机区进一步简化为傅肜地图军旗上方的红色数字；其他两路使用独立演示数值99，演示归营后为0，不借用傅肜危机或新增战斗算法。右侧仅保留四队人数、状态、结束本轮和发送间隔，移除全部军令配置表单；军侯复诵和确认均在左侧输入区。`lastResolution`中的当轮`probability`、`crisis`与下一轮预测仍由接口分别保存，当前不额外展示这些指标。UI不复制公式或抽随机数。服务未连通时显示读取/错误状态，失败保留原文，不回退预设回应。

## 行动与轮次

- 当前传令草案结构为`{unit, action, target, men?, rush, via}`。用户手选的队伍/目标与自然语言冲突时先提示；缺信息不任意补派。复诵完成并确认才是发送指令。
- 每次变更请求附`scenarioId`、稳定`requestId`和`expectedRevision`，军令批次与行动回执由服务端维护。请求不明时保留同一个ID重试，不生成新请求重复执行；UI不凭AI对白记分。
- “结束本轮”为独立动作，前端提交`trigger: endRound`。确认军令只入列，聊天不推进。重复点发送、刷新与重新展示均不增加抽签；同批多支部队不各抽一次。
- 机制模块以`scenarioId + tacticalRoundId`保证一次结算，存档保存`resolutionId`、随机结果和已消费回执。UI请求超时后先查结算状态，不再自行重抽。结算中按钮锁定，刷新后按快照恢复。
- 当前发送冷却`nextSendAt`与上述轮次、结算ID分开保存。冷却到零只恢复发送权限，不改变危机、轮次或撤离概率。

## 分工

AI剧情库对话维护人设、分支、纯机制、概率与服务端事务；UI对话维护客户端、显示、手选/自然语言传令和异步状态。实际接入为`POST /api/fu/session`、`/chat`、`/orders`、`/round`，返回完整会话。源码分别为交互稿的`fu-runtime.mjs`、`fu-ai.mjs`、`src/fu-client.ts`和`src/fu-view.ts`。

成功撤离只显示“已脱险，待归营”；仍可点击“护送归营”。归营后锁定轮次、隐藏不再适用的派遣配置，继续允许人物聊天；顶部明确营救结束，地图旗标位于接应营。已脱险尚未归营时用独立状态标记，不虚构具体途中位置。

## v3人设与字段适配记录

2026-11-17，接机制方修订通知后核对源文件。傅肜受刘备重恩，断后保护刘备；吴军诈称刘备已死，原有部众全部战死，构成其殉国念头与独活愧疚。新接应队与原部众必须区分，界面后续不使用“把原有弟兄一起接回”作为撤离理由或成功说明。

- `FU-B01`：可信反证已实际送达，并回应丧友愧疚后接受继续尽责；降幅仍为12。玩家口头说刘备活着不等于事实核验通过。
- `FU-B06`：确认刘备已脱险；降幅仍为18，不沿用旧“后队撤过”的说明。
- 移除的`rearColumnCleared`不再映射到UI；改为`liubeiAliveVerified`和`liubeiSafeConfirmed`。活着与已脱险是两个事实，显示依据时不得混写。
- v2的`withdrawalAccepted`不视为v3通过；后续接入必须采用机制方的显式迁移或新开审阅场景，不静默清空正式存档，也不把旧说服结果重新显示为已通过。
- 只读`CrisisView`结构沿用。数值曲线与各分支降幅未变，不因人设修订重写UI概率公式。数据仍区分本轮实际概率与下一轮预览；当前界面按用户要求仅保留危机数值和“已脱险待归营”等必要状态。

开发验证：本UI对话完成严格构建、7组解析检查、23项旧演示回归和6组傅肜受控API前端检查；覆盖保留原文、同ID重试、刷新不重复结算、真实/演示隔离、手机独立军情入口与轮次按钮可达、已脱险到归营。机制方另完成真实模型浏览器闭环，记录在`outputs/furong-playtest/browser-live-verification.json`与`final-display-verification.json`。受控接口检查不代表真实模型质量，开发检查也不代替用户体验认可。
