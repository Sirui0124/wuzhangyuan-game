## 每次同步流程

1. 使用飞书 CLI `sheets +workbook-info` 读实时页签，再以 `+csv-get --output-path` 读取完整内容，核对 `complete`、`has_more` 与修订号。不能用旧缓存宣称同步完成。
2. 按表头读取：编号、说话人、一句文案、文案说明、人工线索、线索编号、人工逻辑、规则衔接。人工列保持可读，不用内部字段替换它们。
3. 将新描述解析为：`id / sourceRow / condition / inputs / operation / outcome / retry / forbiddenEffects`。新行为明确建映射；未知描述不作为代码执行，也不能默默忽略。
4. 修复空ID、重复ID和断链。分支必须独立ID；只改有依赖的单元格。预览和正式发言、事实和推测分开。旧规则与用户本次修改冲突时，本次明确修改优先，连带更新旧规则。
5. 更新内容JSON、流程和必要运行逻辑；验证分支、证据来源、生成取消、存档和完整剧情。普通文案变化不应修改无关资源或 `.meta`。
6. CLI写回前比较每个目标单元格的原值，发现并发变更停止覆盖该稿。写回用 `+cells-set --writes @file`，只发value，保留样式和用户备注。再读取三页，逐格比对预期内容。
7. 区分“已同步”和“用户已通过”：本轮润色标记待review，不替用户审批。

本轮执行脚本是 `tools/sync-chapter-one-plan.py`：默认编译与输出可审阅差异；`--publish` 才用 CLI 写回并完整回读验证。它是本轮具体映射稿，不是可以无条件重放到未来任意版本的通用迁移。以后新增自然语言意图，先补上本表对应规则和必要测试，再生成新映射稿。
