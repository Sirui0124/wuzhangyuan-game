# 自然语言到游戏规则

本地现行维护稿。用户描述意图，执行者明确来源、条件、结果和验证，不要求固定口令。章节条件和具体数值留在各章节设计，本文不复制历史实施日志。

| 用户表达 | 执行含义 |
|---|---|
| 听到这里获得线索 | 指定内容、来源和实际取得时点，预览不授予线索 |
| 已有线索才显示／置灰 | 分开设置可见性与可操作性，不擅自互换 |
| 二选一／任意顺序交谈 | 明确互斥、完成标记、汇合点和各自线索来源 |
| 开启思绪画布 | 明确问题、必要依据、容量、唯一答案及后续行动 |
| 润色我这句话 | 保留意思与确定程度，不补事实、授权或过关答案；确认后才发言 |
| 补充刚才没说完的 | 按该 NPC 节点配置读取最近 N 轮完整问答，加本次输入；允许补充、更正和撤回 |
| 对方根据剧情回应 | 本幕知识、阶段、已校验分类及回应意图共同约束生成，不自行更新剧情 |
| 没通过让我再试 | 按该节点流程保留有效状态与草稿，技术失败不当剧情拒绝 |
| 拿物品／出售 | 独立物品账本、明确获取条件与售价，确认后一次入账；不自动等同授权或证据 |
| 关闭 AI／手机 | 按各模块开关处理；请求失效，保留真实进展，不用技术故障伪装剧情结果 |
| 复活／重开／读档 | 按章节重置及继承规则执行，旧请求和不再有效的许可不能复用 |
| 视频后直接继续 | 已确定的演出可自动衔接，选择、阅读、发言与实际行动仍按交互配置等待 |
| 点兵点、看完人物故事后才解锁 | 发现、演出完成、末尾选择、解锁联络与实际派兵分开；“先看其他人”不等于放弃营救。第四章架构待实施，见[兵点初见与人物解锁](chapter-four-ai-library-20261117/兵点初见与人物解锁架构.md) |
| 从兵池派N人、再派一队 | 区分新建队伍与给已有队增援；复诵确认后预留兵力和名额，执行时转为在外兵力；具体章规则见下方设计入口 |
| 战损后整队撤回／改令 | 按真实剩余人数执行，不按编队步长抹零；归营与释放名额需实际事件，不通过改写队名刷新 |
| 按最新文档同步游戏 | 读取本地当前设计，比较并发修改、更新配置和代码、验证并报告；没有自动监控 |

新增需求先记录映射、再实现、再验证，分别报告；只有会改变玩法结果的歧义才确认。玩家可见文案称“我”，不机械替换内部角色标识。规范见 [协作原则](COLLABORATION-PRINCIPLES.md)、[全局机制](GLOBAL-GAME-RULES.md)、[AI 对话架构](AI-DIALOGUE-ARCHITECTURE.md)。
