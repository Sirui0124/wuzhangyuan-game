# 玩家原话润色与 NPC 分类回应

2026-10-22。已接入桌面浏览器完整游戏，真实接口验证使用本机已配置的 `deepseek-flash`。本稿记录实现与验证，台词风格仍待用户 review。

## 实际行为

玩家在语言组织页写自己的话，点击「润色表达」，先看到可编辑预览；只有点击确认发言后，才调用 NPC 判断和回应。非空原话逐意保留，允许只说一个短句，允许表达不周全，不替玩家补齐过关答案。

原话中的事实必须有已选依据支持。无依据的授权、敌情或保证会提示修改，原话和选择保留。第一人称未来行动如“我去报”是提议，不是已经完成，也不需要先虚构他人授权。

NPC 使用玩家实际说出口的当前文字及本次交涉历史判断；全部已得线索仅用于核真，不能当作玩家已经说过。当前明确纠正覆盖旧说法。润色草稿、未确认重点不会进入 NPC 判定。

拒绝时，魏延的 AI 台词在实际回应页显示；原话、重点、线索和回应保存，刷新后可恢复，玩家主动选择重新组织。接受时，AI 台词用于实际剧情节点 A-40B 或 W07，保留原节点的事件条件。接受转呈不等于军报已经送达，接受同行也不等于接报、发令或回令闭环。

## Prompt 分工

实现：`GameStarter/web-demo/src/expression-agent.ts`。

1. **润色生成**：输入阶段、已选证据及递归原话、玩家原话、上一回应。只生成措辞，不补新意思。输出 `status/text/evidenceIds`；无法忠实且有据地保留原话时返回 `needs_revision`。
2. **润色核对**：独立核对原意、称谓、否定、疑问、不确定性和事实来源。普通未来提议不当成虚构事件。通过才展示预览。
3. **语义提取**：从实际发言提取十项布尔条件，每个为真的条件必须附上玩家实际说过的连续原文。程序验证引用确实存在，再按当前章节规则映射分类。
4. **疑似无据断言核对**：只有提取器怀疑虚构时执行。隔离被怀疑的那句话，使用已得证据核验，避免周围的辱骂或语气导致真实承诺被误判为虚构。
5. **NPC 措辞**：程序根据分类给出本轮允许的回应意图，由 AI 自然化。此生成器不接收线索库存，只接收角色、当前实说和允许表达的意思。不得新增线索、安排、授权或已完成事件。
6. **NPC 措辞核对**：比较允许的意思与候选台词是否同义，检查行动人、安排和确定性。失败最多重新生成一次，再失败则显示服务异常，保留玩家发言，不冒充剧情拒绝或成功。

正常润色需要两次模型调用；NPC 通常三次，疑似事实核对或有限重试会增加调用。所有调用沿用已有代理和取消信号，不增加前端密钥。没有无限重试。

结构校验：`GameStarter/web-demo/src/npc-dialogue.ts`。严格检查必填字段、额外字段、版本、人物、阶段、枚举、文本长度、实际已得证据 ID 和分类/接受状态一致性。语义提取结构格式错误最多重试一次；网络失败直接交给现有重试界面处理。

## 标准输出

正式契约：`content/schema/npc-turn.schema.json`。下面是本轮浏览器真实调用保存的对象：

```json
{
  "schemaVersion": 1,
  "npcId": "weiyan",
  "stage": "first",
  "classification": {
    "code": "ok",
    "disposition": "accept",
    "reason": "本次已说内容满足当前交涉条件。",
    "evidenceIds": []
  },
  "reply": {
    "speaker": "魏延",
    "text": "好，你即刻转呈，莫误了军情。"
  }
}
```

`classification.reason` 是简短的程序可核验结果说明，不是模型思维过程。`evidenceIds` 表示核验分类用到的依据，允许为空；纯未来提议不要求编造一条事实引用。内部语义检查与原文引用用于得出分类，最终对游戏返回上面的固定结构。新运行时不接受旧式单字符串 `ok`；无 NPC JSON 的旧合法存档仍可读取。

| 阶段 | 分类 | 含义 |
| --- | --- | --- |
| first | ok / R1-RETRY | 当前转呈提议成立 / 需要修补 |
| authorized | P2-F1 | 无依据的断言，或未说明本人接报承诺 |
| authorized | P2-F2 | 压报、拖延 |
| authorized | P2-F2B | 强闯 |
| authorized | P2-F3 | 辱骂、威胁 |
| authorized | P2-F4 | 未说清敌军前后变化、随军换向及可能试探的判断 |
| authorized | P2-F5 | 未交代及时、当面、不入帐的交接安排 |
| authorized | ok | 本次交涉条件成立 |

这张表是第一章当前条件的程序映射，不提升为其他章节的通用规则。程序确定分类后，措辞生成不能更改分类。

## 真实接口结果

最终一次完整回归：10 条润色 + 14 条 NPC 用例，63 次真实模型调用，全部符合预期；另有浏览器真实交互 13 次调用。此前诊断迭代另计，不能把这 76 次当成整轮工作的总调用量。

| 玩家原话 | 实际润色结果或处理 |
| --- | --- |
| 我去报，你别闯。 | 将军，我去报，您先别闯。 |
| 要不让我替您马上递个话，成吗？ | 将军，要不让我马上替您递个话，成吗？ |
| 我来递报，不过我不敢保证什么时候能有答复。 | 将军，我来递报，不过我不敢保证什么时候能有答复。 |
| 我也拿不准，或许他们是在试探。我想先听听军报。 | 将军，我也拿不准，或许他们是在试探。我想先听听军报。 |
| 将军，先别惊扰丞相，等一等吧。 | 原意保留，不擅自追加转呈解法 |
| 姜维已经答应接报，丞相也准您进去。（首轮） | 提示原话中有无依据的事实或承诺，保留输入 |
| 营门尚未失守，您不必着急。（未取得营门情报） | 拦截，不用叫嚷情报推导营门安全 |
| 他们肯定知道丞相病了，我保证他们等会儿就退。 | 拦截，不替玩家删改承诺来通过 |

NPC 14 条覆盖：口语与短句转呈、拖到明早、虚构授权、提示注入、完整二轮表达、缺少授权、压报、强闯、威胁、没讲敌情、没讲交接、纠正前言、分多次补充。其中：

- “先别吵醒丞相，等明早再报。” → `R1-RETRY`，回应“军情不能耽搁，眼下这急报怎么办？”
- 已说姜维承诺与交接方案，但没说敌情 → `P2-F4`，回应“敌情究竟有何变化？你为何这样判断？”
- 完整且有据的二轮表达 → `ok`，回应“带路，我亲自去问个明白。”
- 对前次“肯定知道病情、等明天”的说法明确纠正，补齐本轮条件 → `ok`，旧错误不会永久锁死交涉。

本次调用环境中，10 条润色平均约 1.37 秒（含直接拦截），14 条 NPC 平均约 2.99 秒，最长约 4.14 秒。这是本轮测量，不是响应时限承诺。

初始真实测试暴露过：润色追加未说线索、将已得线索当已说、NPC 交换行动人或补等候安排、辱骂导致真实承诺被误判。当前分步流程及约束是在这些实际失败上修正的。有限样本通过不代表任意表达都必然正确；校验未通过时保留输入、允许重试，不静默放行。
