# 逆转五丈原｜全局游戏机制规则

版本：2026-10-22。由“规则与状态”审查整理；适用于各章节共用的机制边界。这里不保存某一场对话的判定顺序、人物名称、固定线索编号或一次性修复记录。具体章节条件在章节策划表和程序中维护。

## G01 事实、推论与实际事件分开

线索在指定来源实际发生后取得，不能从未来对白、生成预览或相似文字中补发。推论须能回溯到已获得的原始依据；行动提议、人物实际同意、行动实际完成分别记录，不能互相代替。

## G02 推理保留依据与不确定性

只使用本次参与的有效线索和推论来源。局部成立的推论可以保留，不因为没有回答另一个问题就判成错误。不能把猜测升级为确定事实、敌方内心或必然结果。具体推理入口、按钮和完成目标属于交互方案及章节配置，不作为永远不变的全局规定。

## G03 推理和表达使用同一份已得资料

线索推理和语言组织可以复用已有依据与推论；打开、关闭或切换面板不应凭空新增或丢失真实事实。是否采用浮层、分栏或连续时间线由当前界面方案决定，不强制所有章节使用某一固定布局。

## G04 AI只组织表达，玩家确认后才发言

输入包括实际选中的依据、可选表达重点、交谈角色和当前情境。保留玩家主要意思；表达重点可以提出未来行动，但不能创造他人的承诺、权限或已发生事实。生成结果为可编辑预览，引用需核对；玩家确认后才记录发言并判定回应。AI生成文本本身不能直接更改剧情状态。

## G05 请求失效与异常恢复

更换依据、重点、手工改稿、切换相关模式、取消、读档或重开时，应使不再适用的生成请求失效。迟到结果不能覆盖新输入或推进剧情。服务异常与剧情拒绝分别处理，保留可恢复输入，允许重试。参考句与AI生成结果明确区分。

## G06 按语义和事实判断

接受意思相同的不同说法，不要求固定口令、全选线索、长篇输入或恭维。具体成功条件由当前剧情规定；直率、短句、少敬语本身不构成失败。人物反应须基于实际说出的内容和已有事实，不能读取尚未确认的草稿。

## G07 修补不重置真实进展

允许在当前交涉或推理过程中补充依据和改写表达，不因一次失败自动清空真实授权、收录或已发生事件。撤回推理时按依赖关系处理推论；不能倒改已发生的剧情。重开、回溯和跨周目继承必须遵守章节明确设定，不能默认继承全部线索。

## G08 存档与显示契约

恢复存档时核对内容版本和事实来源；不静默补造缺失剧情。待完成的异步请求不能在读档后被当成已完成。内部标识、占位符、分类和错误细节不作为角色对白展示。文档示例不自动进入正式对白队列。

## 维护范围

本文件记录机制约束，不保证每个章节、每个端都已实现或验证。具体实现和验证记录分别维护。用户的新要求优先；与旧设计或当前代码冲突时记录差异，不能只因为代码现状就擅自改变创作方向。

飞书CLI用法、表格八列、审阅状态、自然语言填写方式属于《策划文档与游戏开发协作原则》，不属于游戏运行规则，不在这里重复保存。

## G09 出示异物与通用失败结局

手机购买的物品只有在表达沟通中实际出示，并随玩家确认发言提交后，才判断是否触发“妖孽现世”：AI须同时判断其实际可见表现严重违背当时常识，且玩家结合当前原话与此前相关解释仍不能自圆其说；二者缺一不可。仅有现代来源、陌生名称、稀奇外观、缺件或普通说服失败均不够。合理解释或证据不足不触发；未出示的库存、未确认草稿、润色预览与购买本身不触发。

触发后先显示对方起疑并叫人拿下的回应，再进入被当作妖孽抓走的失败结局；不得记为交涉成功、收礼、完成任务或解锁下一章。异常响应保留原话与物品供重试，不冒充剧情判定。可回溯到本次交谈，保留此前真实线索、购买记录和余额；这次失败不消耗物品。结局机制通用于已接入的物品表达环节，具体接入与验证记录另存，不代表尚未实现的章节已验证。

## G10 持续受阻时提供可选择的帮助

交涉应沿用本轮已说清的内容，反馈只指出当前具体缺口，不要求反复完整复述。可选信息与必要条件须在章节设计中区分，不将可漏收材料变成未说明的通关门槛。持续受阻应提供经验证、符合已得事实的可选帮助路径；采用不自动发言，仍由玩家确认，不补造线索或他人授权，不按尝试次数自动通过或惩罚。技术故障与剧情解释分别处理。触发时机、帮助内容及适用节点由各章节配置，未接入章节不视为已经实现。
