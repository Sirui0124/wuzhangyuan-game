## 首版怎样玩

主界面是一张有四路军情的地图。玩家先点击人物提示，逐句读一段图文场景；可以自由问一两次，也可以直接继续。了解情况后选择行动，核对所需队伍与船队，确认调遣才出发。问讯由营中报信者回答已知情况，不把远处人物写成已经与接应队见面。阅读、问讯和思考时全场暂停；关闭军情保留内容，不自动发令。

地图保留四路人物位置、短军情、队伍行程与渡口占用。五支队伍共用2500人的初始编制与一支船队；每路实际占用哪些队伍、哪些人员已经归营都要可见。各路内容分开阅读，兵力、船队和时间统一计算。确认方案、执行接应与实际归营分别记录。

| 人物 | 首个困境 | 玩家实际改变什么 |
| --- | --- | --- |
| 傅肜 | 前队已经回营，后阵仍须有人守。 | 接应队与原断后部队交替撤离，末队归营才结束。 |
| 黄权 | 江北仍有组织，但当前归路与接收未落实。 | 先派船核实两岸联络；收到实际回报后，再决定何时派船渡运。 |
| 程畿 | 江上追兵逼近，他仍照应同行者。 | 由船工带船接人，接上同行者后护送末船归营。 |
| 沙摩柯 | 失散者与已集结的人可能再次错过。 | 向导带队寻找，沙摩柯守集合处认人；搜索队会合后共同撤回。 |

四个人物提示开局即可查看，每人先保留一个主要困境。先呈现一件具体发生的事，由人物的处境引出需求；不能让信使朗读动作清单。路线、船队占用和已知风险随当前操作显示。五队各500人仅是技术夹具配置，尚未建立与救援规模相称的玩法依据，不据此微调个位数伤亡。派出、归营、伤员和被救人员分账。

当前一项行动占用一支接应队；两条水路还共用船队，不能同时调遣。每路先有一项完整、可执行的行动，也可回地图继续了解别路，不用无效兵力下拉和同义选项制造选择。地图分别显示交接、寻找、会合、渡运及归营，行动实际推进后才有回报。黄权首次联络完成不计获救。首版先验证这五次调遣的完整流程；危机失败、战损与分兵平衡属于下一轮，不把时钟或旧危机数当成已经实现的失败系统。

## 三版怎样比较

| 版本 | 玩家怎么操作 | 主要验证 |
| --- | --- | --- |
| A 图文问讯后选择 | 看场景和短对白，可自由问两次，再决定是否调遣；存在不同可行办法时才增加选项。 | 是否理解人物处境，愿意投入接应力量。 |
| B 图文问讯后看AI提案 | 了解情况后，由AI提出可编辑的安排。 | 是否省去输入负担，又能作出自己的安排。 |
| C 图文问讯后自由下令 | 了解情况后，自己描述安排，核对后再确认。 | 是否值得为表达不同思路多花输入时间。 |

先把A的一段故事写通，再用同一段对照B/C。三版共用军情、支持能力与结算；问讯只补充了解，不替玩家选择方案或派兵。开放问题成功回答最多两次，技术故障不扣次数；重要风险在选择前明确交代，不能藏成必须问中的答案。B/C仍为有限行动范围内的实验，不据此声称策略空间更大。不得通过换动作顺序凑三个选项，或让AI替缺失的剧情和后果随意编造解释。

测试分两步：先比较同一军情的三种入口；再在相同入口下改变兵力、船队占用或先前安排，检查事件与选项是否随事实改变。首轮找5位玩家轮换A/B/C顺序，单列第一次体验，记录理解与决策时间、AI等待、求助与重试、意图是否按预期执行、趣味评分及继续玩意愿。若自由输入只是把同一正确句换个说法，不算更深的交互。
