## 本作的统一写法

NPC 先回答对方眼前的问题，用符合身份的自然白话说完整意思。事实明确就说事实，未知只说明不知道的那一处。后台限制用于守住事实，不能逐条念给玩家。避免用“不是……也不是……”“不是……而是……”铺垫答案，避免对仗、口号、抽象道理和固定追加的反问。回答已完整就收住；本幕确有追问要求时仍按原规则追问。

这不是禁用“不是”或一切对比。玩家明确问是不是、人物纠正误解或拒绝要求时，正常保留否定。不能靠删词损失事实，也不对输出做机械截句或替换。

魏延急于传报，直接问具体差事；马谡自信、愿意听理由，按当前顾虑回应；傅肜的悲愤来自误信死讯与丧友，避免每轮重述忠义宣言。人物情绪随已确认状态改变。

润色保留行动人、对象、否定、疑问、承诺、条件、先后及不确定程度，只整理语序、称谓、衔接和重复。原话清楚时可以少改，不设最低字数，不增加具体步骤、建议或过关方案。原话已有的真实对比保留含义，不为了避句式强改立场。

## 正文与当前场景（2026-11-18后续纠正）

最终发言以玩家确认时的输入框正文为准。引用标签、已收集线索不代表已经说出；正文删除或改错后，不能从引用标签、事实库或润色前草稿中补回。实际已确认的历史发言继续按本幕窗口处理，最新否定、更正、撤回优先。第一章分类器仅接受历史玩家原话及本次正文的逐字引文作为判定依据。

第一章润色采用通用规则和节点情境分开输入。规则见 `GameStarter/server/chapter-one-http.mjs` 的 `polishSystem`；场景配置来自正式 JSON 的 `aiScenes.weiyan_final.polishContext`，不会根据玩家引用了哪条线索而切换剧情场景。

| 输入 | 实际来源 | 用途 |
| --- | --- | --- |
| draft | 当前输入框正文 | 唯一改写对象，保留玩家删改后的含义 |
| 说话人、听话人、地点 | 服务端重放阅读记录后，取当前节点所引用的 aiScenes 板块内 polishContext | 理顺身份、称谓和口吻 |
| question | 当前交涉最近一轮 NPC 回应；尚无问答时取该节点最后一句 NPC 对白 | 理解当前问话和指代，过滤演出说明 |
| 引用标签、全部线索、成功条件 | 不传给润色模型 | 防止补回删掉的内容或代填解法 |

润色不纠正玩家写错的剧情事实；对错留到确认说出后由人物评估。生成后的独立核验仍检查是否改变正文含义，失败时保留原稿。借用《崇祯模拟器》逐句改写的职责边界，不采用其完善计划、四类诏书格式或最低字数要求。

本次实施与验证范围为正式第一章：构建通过，分支及正文边界测试11项通过。真实接口抽查4条判定、2条润色：保留标签但删除军情正文时追问；把“未攻营”改成“已攻进营”时不通过；改为自行转呈时走自行转呈；完整请伯约听报时才采用相应安排。润色未补回被删的伯约，也未把玩家写错的“已攻进营”改成正确军情。请求使用独立阅读记录，不写玩家存档；结果见 `outputs/body-only-polish-20261118/live.json`。小样本通过不代表所有模型输出均可靠，也不代表其他章节旧润色入口已同步该契约。

## 傅肜专项

用户指出的原句：“不是自家军侯传的话，也不是传令兵回报。你问这个，是听到别的说法了？”

内部来源输入原先同时包含正确来源与排除项，容易被模型转述为台词。现改为只陈述“傅肜听见吴军喊话，声称刘备已经遇害”。事实保护仍留在规则层；未获反证时，傅肜不知道那是诈称。

问来源时可答：“是吴军喊的，说陛下已经遇害。”只有玩家实际提出别的消息，或本轮确需核实，才追问来源。示例只适用于该场景，不能成为其他角色的新事实。
