# 已选线索与补充输入共同组织对白

## 用户修正与根因

2026-10-25 用户指出，已经选择“帐前禁令”和“魏军探问丞相与发令者”后，生成不应只有“将军，我替您转达”。需要核查实际 prompt 是否收到两条线索。

已核对请求链：`buildExpressionInput` → `expressionAgents.generate` → `GameApi.respond` → 本机代理。两条线索确实进入生成请求的 `selectedEvidence`（C06、C05），补充输入在 `playerIntent.words`，魏延当前追问在 `conversation.listenerTurn`。旧结果却是 `evidenceIds: []`。

原因是旧分类将任何非空补充输入都当成“只润色玩家原话”；生成与核验同时限制加入线索含义。上一轮只修正了称谓与原样返回反馈，未解决这个语义错误。

飞书协作原则在线修订 35 已读取，正文与本地镜像一致：其中既有“所选线索／推理结果＋少量表达重点组织台词”，也有单独“只润色原话、别补线索”的用法。按此次明确修正，两者分开适用，不能因填了补充输入就禁用已选材料。

## 当前实现

| 输入 | 调用方式 |
| --- | --- |
| 选线索＋补充输入 | `compose-selected-with-intent`：所选事实与补充提议一起组织 |
| 只选线索 | `compose-from-selected`：组织选中事实，不代填玩家行动 |
| 不选线索，只填输入 | `polish-player-words`：忠实润色输入，不补剧情事实 |

- 生成要求覆盖每条已选含义，允许合并重复意思；不能只念补充输入或只列引用编号。
- 程序核验返回引用是否覆盖选中编号；独立审核新增 `coverage`，检查这些含义是否实际进入台词。遗漏会明确失败并保留原稿，不显示“润色完成”。
- 审核仍保留原意、主客体、时序、事实与物品边界，不增加未选线索、敌军动机、病情、行动完成或授权；生成结果也不会自动确认说出。
- C06 由仅传卡片标题，补充为已读来源对应的禁令含义。A-17 只提供首轮告示内容，D02 提供本轮口谕；只有 D05/D06 实际已读时才包含甲的递报职责和权限。不把第二轮事实提前给第一轮。
- 没有补充输入时继续禁止代填转呈、通报、等候、请示等行动。此次实测发现模型会添加“请将军稍候”，已补强生成及审核的范围提示并追加针对性复测。
