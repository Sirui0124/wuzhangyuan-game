# 斥候回答后的黑屏与线索衔接修复

用户反馈：选择“营门失守了？”、听到“前哨守得住”后进入黑屏，重启没有剧情选项；应收录证据并继续。

## 复现与原因

独立Chrome上下文从真实第一轮流程生成检查点。旧版结束该片段后，剧情仍为 `dialogue / A-23`，仅有C06，T02未入库；视频元素的src已被播放器释放。页面仍要求额外点击右下角“继续”，画面则已变黑。现场截图中的版本更新提示也占用右下角。未读取或改写用户浏览器存档。

## 修复

- 两个斥候选择分支播完后按现有行序提交，回到原探索行动；选A收录T02“营门尚未失守”，选B不获得此事实，显示原有“迎上魏延”行动。
- 兼容“影片已完成、剧情行尚未提交”的旧档，读取完成标记后执行同一段安全推进。未修改剧情/影片版本，不清空旧进度，不重置开局。
- 仍需显式确认的其他剧情影片，释放解码器时保留实际已解码画面，避免等待继续时出现黑底；不自动替玩家确认其他剧情。

## 验证

类型检查、架构检查与构建通过。现有剧情、六线索和影片映射测试38项通过。

`tools/migration/scout-film-handoff-smoke.mjs` 实际Chrome覆盖两分支的自然结束、跳过、已播放完成旧档，共6种情况；确认T02只在选A完成后取得一次，恢复后线索/已读记录不重复，能点击“迎上魏延”进入下一影片。额外检查魏延片段仍等待确认且保留非黑色实际画面，确认后进入表达。无页面脚本异常。

证据位于 `outputs/scout-handoff-20261025/`：`before.json`、`before.png`、`checks.json`与6张修复截图。本机8812提供的播放器与剧情影片模块已与最终构建核对一致。Cocos/原生端未验证，用户实际存档效果待试玩。

共享播放器转场Chrome检查也通过：延迟加载期间保持实际画面、解码后撤去覆盖、倍速和静音保持、跨组自然结束、等待中跳过及迟到回调清理。原测试使用了已不存在的第三段开场，已改用当前有效片段，并在菜单实际就绪后运行播放器检查。报告 `outputs/cinematic-transition/checks.json`。
