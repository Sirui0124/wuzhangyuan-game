# 五丈原白模：因果、状态与格式

## 试玩与检查

入口：http://127.0.0.1:8811/?white=1 。右上「证据与记忆」查看本轮物品、证据来源和旧轮记忆；「因果与条件」检查当前节点、每个选项的前提、行动耗时、对白确认效果、flag 当前值、结算规则及状态变化记录。面板只读，运行条件来自同一个叙事引擎。

## 单一内容格式

唯一剧情源为 `content/chapters/wuzhang/chapter.json`，保持 `schemaVersion: 1`，契约为 `content/schema/narrative.ts`。打包单向复制到 Cocos resources，保留资源 `.meta`；浏览器构建也从唯一源复制，不从界面反写剧情。

| 对象 | 写作与运行职责 |
| --- | --- |
| DialogueNode | 地点、人物、话题、触发方式、availableWhen、复读策略、对白和后续节点 |
| Line | 稳定 ID、说话人、文本、when 和 effects；确认到这句才结算 |
| Choice | visibleWhen 决定显示；enabledWhen 决定可选；lockedText 说明缺什么；actionId 对应注册行动 |
| FreeInput | 意图、输入提示、证据选择、judgeId 与五类固定 outcomes |
| JudgeDefinition.acceptanceCases | 语义通过仍须匹配本轮事实；无法绕过证据和许可门槛 |
| Action | availableWhen、耗时、注册效果；阅读和切换地点不自动耗时 |
| PromiseDefinition | 承诺与等待预算；首次耽搁警告，再次耽搁破约 |
| EventRule | 根据显式条件触发结果和后续剧情 |

Condition 只用 all / any / not / flag.equals / evidence.held或presented / intent；Effect 只用 setFlag / grantEvidence / startPromise / fulfillPromise / breakPromise。新内容没有增加另一套条件表达式或脚本命令。

## flag 与物品获取在哪里

| 状态或物品 | 取得或变化的契机 | 后续作用 |
| --- | --- | --- |
| 告示 entry_notice | 确认 notice.read 的取证台词 | 证明禁令限制进帐，不等于可耽搁军报 |
| 守卒说明 guard_statement | 确认 guard.ask_urgent 的取证台词 | 说明报名候见与擅定接报办法的区别 |
| 斥候敌情 scout_statement | 确认 scout.scope 的取证台词 | 敌兵逼近、营门尚守、来意未明；不能夸成破营 |
| loop.inferred_plan | guard.connect_evidence 选择正确关联判断并确认回应 | 解锁接报交涉；选错有反馈，无正确 flag |
| 姜维传报凭条 approval_note | 乙实际递话后确认 jiangwei.approval | 本轮授权证据；持有后还须向魏延出示 |
| loop.jiangwei_approval | 同一许可确认 | 第二轮获准接报的事实条件 |
| 病势线索 illness_trace | 耗时调查并确认对应回复 | 提供可选旧事线索，不替代军报传递 |
| memory.knows_illness | 同一病势回复 | 跨轮保留认识；物品仍须本轮重取 |
| loop.report_status | 实际交报、收回话、如实转达 | 记录执行进度；答应方案不等于已经送达 |
| memory.seen_execution 等 | 第一轮结局确认 | 回溯后解锁侧帐及新的行动可能 |

物品统一登记在 evidence，获取统一写 grantEvidence。库存保留获取节点和触发记录，可从检查面板追溯；NPC 认知在实际出示后更新，不能以“玩家知道”替代“NPC 知道”。姜维回话是执行记录，不另发道具。

loop flag、证据、许可、承诺、NPC 认知随回溯清空；memory flag 保留。旧轮证据只读，不可出示。第二轮必须重新调查、关联、获取当轮许可。

## 两轮因果与失败

第一轮：调查三类线索 → 关联判断 → 与魏延约定帐外接报 → 甲说明越职责任 → 玩家实际递报 → 灯守住、玩家处斩 → 确认乙的线索 → 回溯。此处处斩属于架空游戏情节。

第二轮：重取线索并关联 → 向乙举证 → 实际递话 → 姜维许可 → 向魏延出示凭条与敌情 → 请乙到场 → 准确交接军情 → 取回姜维回话 → 如实转达 → 保灯生还。许可之后仍需执行，不能一步跳结局；病势未被治愈。

误报敌情、淡化敌情、擅添出营令、另查病势都显式消耗等待机会。第一次反馈并警告，允许纠正；第二次破约。普通灯灭不解锁乙，避免所有失败都得到同一奖励。

## 扩展规则与文稿差异

新增节点先登记稳定 ID 与 flag / evidence，再写获取台词 effects、选项条件和对应 Action。预设表达与 AI acceptanceCases 必须检查同一事实。每条关键路线需检查获取前后、持有与出示、执行前后、回溯重置，以及失败是否能恢复。UI 仅显示引擎提供的状态。

本次相对先前编辑稿增加三证关联判断、军报核对、回话核对、病势调查及明确的误传代价，并修正守卒权限和姜维回话时机。`五丈原_完整剧本与逻辑_编辑稿.md` 保留用户编辑，未自动导出覆盖；早期文稿不应视作与当前可运行 JSON 完全同步。后续逐段 review 以试玩当前节点及其原始 JSON 为准，再人工确认是否回写编辑稿。
