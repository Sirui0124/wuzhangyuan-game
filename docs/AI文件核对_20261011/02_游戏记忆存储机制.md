# 游戏记忆与存储机制 · 现行代码核对稿

提取时间：2026-10-11 17:28:53（北京时间）。本文件说明当前五丈原的实际实现，并附核心代码原文。它是供审阅的副本；本次没有读取玩家本机存档内容、没有修改游戏或清空存储。

## 1. 当前机制的结论

当前五丈原配置有专用 `restart` 规则。复活或重来本关时，仅保留 `progress.tutorial_completed`（教学已完成）标识；重新建立一轮状态。本轮证据、许可、NPC 状态、行动、判定反馈、事件历史、已读对白与草稿都会清空。已经收集的结局、地图进度和独立保存的设置仍留在各自存储中。

魏延没有跨轮记忆库。两次分类请求不传旧对白或玩家记录，也不复用模型会话；第二次只额外传当前姜维许可是否成立。玩家的“记忆线索”是当前轮已确认对白，最多八条，供玩家选择后交给润色助手；不会自动成为证据。玩家确认最终草稿后，稿中文字才作为本句对白参与魏延判定。

**重点区分三种操作：**刷新或继续游戏恢复同一轮稳定存档；终局后“回到存档”恢复同一轮终局前状态；复活或“重来本关”新建一轮并清空本轮资料。

## 3. 叙事状态保存什么

来源：[GameStarter/assets/scripts/narrative/state.ts](../../GameStarter/assets/scripts/narrative/state.ts:10)。这是当前状态结构原文：

```ts
export interface RuntimeState {
    schemaVersion: 1; chapterId: string; contentVersion: string; loopId: string; revision: number;
    checkpointNodeId?: string;
    presentation?: { actorId: string; sceneId: string; evidenceIds: string[] };
    sceneId: string; flags: Record<string, Value>;
    evidence: Record<string, { loopId: string; nodeId: string; sourceEvent: string }>;
    promises: Record<string, PromiseState>; visited: string[]; visitedEver: string[];
    committed: string[]; actions: string[]; firedEvents: string[];
    history: HistoryEvent[]; feedback: Record<string, JudgeResult>; seenMedia: string[]; drafts: Record<string, string>;
}
```

`history` 记录事件 ID、轮次、人物、行为、证据 ID 和状态变更，未设计为完整对白聊天日志。对白正文主要由界面 `ui.readings` 保存；`ui.topicReadings` 保存已读话题及其内容签名；`ui.drafts` 保存编辑草稿。引擎的 `state.drafts` 则在提交自由输入时写入原话。

`flags` 保存剧情事实；`evidence` 为每件证据附上所属轮次与来源；`presentation` 保存当前人物、场景和实际出示的证据。持有证据和实际出示证据是两个状态。

`rewindState` 原代码：[GameStarter/assets/scripts/narrative/state.ts](../../GameStarter/assets/scripts/narrative/state.ts:29)。

```ts
export function rewindState(chapter: Chapter, old: RuntimeState): RuntimeState {
    const fresh = createState(chapter, old.contentVersion);
    if (chapter.restart) {
        for (const id of chapter.restart.preserveFlagIds) fresh.flags[id] = old.flags[id];
        fresh.revision = old.revision + 1;
        return fresh;
    }
    for (const f of chapter.initialFlags) if (f.scope === 'memory') fresh.flags[f.id] = old.flags[f.id];
    fresh.history = old.history; fresh.visitedEver = old.visitedEver; fresh.seenMedia = old.seenMedia;
    fresh.drafts = old.drafts; fresh.revision = old.revision + 1;
    return fresh;
}
```

注意 `chapter.restart` 分支会提前返回。下方通用分支中“保留 memory、history、visitedEver、seenMedia、drafts”的逻辑用于没有专用 restart 的章节，当前五丈原不会走到它。不能用这段通用代码认定当前游戏会保留上轮对白和草稿。

教学牺牲节点 `tutorial.execution` 写入教学完成标识；玩家点击“继续”调用 `engine.rewind(true)`，进入 `player.revival`。普通重玩调用 `engine.rewind()`，教学完成后进入 `player.investigation`。引擎还生成新的 `loopId`，撤销待处理请求及当前交互，迟到响应不能提交。

## 5. 已听对白怎样成为“记忆线索”

玩家主动选择的线索只给润色请求，调用处原文：

润色助手收到原稿、目的、语气、补充信息、所选线索和实际出示证据；润色 Prompt 明确“记忆线索只是玩家选中的已听对白，不能凭它新增证据”。来源：[GameStarter/web-demo/src/reply-composer.ts](../../GameStarter/web-demo/src/reply-composer.ts:12)。

润色结果先填入可编辑草稿，不自动提交判断。取消、切换、关闭或生成中修改原稿会阻止迟到结果覆盖；程序检查取消状态、引擎实例、编辑框标识和草稿修订号。

## 7. 自动存档与稳定边界

自动存档把引擎序列化字符串和界面记录放在同一个本机条目中。若结果仍为 `none`，同一份内容还写入终局前重试档。

```ts
function cache(stableSave?: string) {
    if (mainMenuView) return;
    if (preserveOldSave) { saveWarning = '旧存档备份失败，已保留原档；当前进度暂不覆盖保存。'; return; }
    try {
        const save = stableSave ?? engine.save(); lastSaved = new Date().toISOString();
        const stored = JSON.stringify({ save, ui, savedAt: lastSaved });
        localStorage.setItem(KEY, stored);
        // Keep a playable checkpoint even after the terminal autosave is written.
        if (engine.snapshot().flags['loop.result'] === 'none') localStorage.setItem(RETRY_KEY, stored);
        saveWarning = '';
    } catch (e) {
        // An unfinished conversation intentionally stays at the previous stable save.
        if (!(e instanceof Error && e.message.includes('boundary'))) saveWarning = '浏览器未能保存；本页仍可继续试玩。';
    }
}
```

来源：[GameStarter/web-demo/src/app.ts](../../GameStarter/web-demo/src/app.ts:114)。AI 等待中、未确认台词、未完成回应或有待接续剧情时通常不能保存，继续使用上一个稳定档；魏延举证完成且已到自由输入边界时是允许保存的检查点。

引擎 `save` / `load` 原代码：

```ts
    save(): string {
        const checkpoint = this.session && this.session.phase === 'opening' && !this.currentLine() &&
            ([...(this.chapter.readOnlyCheckpointNodeIds ?? []), 'weiyan.negotiate', 'tutorial.weiyan.negotiate'].includes(this.session.nodeId)) ? this.session.nodeId : undefined;
        if ((this.session && !checkpoint) || this.pending || this.pendingNext) throw new Error('Save only at a completed interaction boundary');
        const saved = cloneState(this.state);
        if (checkpoint) saved.checkpointNodeId = checkpoint;
        return JSON.stringify(saved);

    load(json: string): void {
        const restored = validateState(this.chapter, this.contentVersion, JSON.parse(json));
        const checkpoint = restored.checkpointNodeId;
        const context: InteractionContext = { actorId: restored.presentation?.actorId ?? null, evidenceIds: restored.presentation?.evidenceIds ?? [], intentId: null };
        if (checkpoint && !evaluate(this.node(checkpoint).availableWhen, restored, context)) throw new Error('Unavailable saved checkpoint');
        if (checkpoint && ['weiyan.negotiate', 'tutorial.weiyan.negotiate'].includes(checkpoint)) {
            const required = checkpoint === 'weiyan.negotiate' ? ['entry_notice', 'scout_statement', 'jiangwei_authorization'] : ['entry_notice', 'scout_statement'];
            const noticeFlag = checkpoint === 'weiyan.negotiate' ? 'loop.weiyan_notice_presented' : 'loop.tutorial_notice_presented';
            if (context.actorId !== 'weiyan' || !restored.flags[noticeFlag] || required.some(id => !context.evidenceIds.includes(id)))
                throw new Error('Saved negotiation requires actually submitted evidence');
        }
        delete restored.checkpointNodeId;
        this.invalidate(); this.state = restored;
        if (restored.presentation) { this.selectedActor = restored.presentation.actorId; this.selection = context; }
        if (checkpoint) {
            const node = this.node(checkpoint);
            this.selectedActor = node.characterId; this.selection = { ...context, actorId: node.characterId };
            this.startNode(node, this.selection); this.session!.index = node.lines.length;
        }
    }
```

## 8. 读档、草稿与兼容备份

页面恢复函数原文：

```ts
function restore(sourceKey = KEY, includeDrafts = true) {
    const stored = JSON.parse(localStorage.getItem(sourceKey) ?? 'null');
    if (!stored?.save) return false;
    const previousVersion = JSON.parse(stored.save).contentVersion;
    if (previousVersion !== manifest.contentVersion) {
        // Keep the exact original save and the separately persisted drafts before any new autosave.
        const backupKey = `${KEY}:compat-backup:${previousVersion ?? 'unknown'}:${Date.now()}`;
        try { localStorage.setItem(backupKey, JSON.stringify({ stored: localStorage.getItem(KEY), drafts: localStorage.getItem(KEY + ':drafts') })); }
        catch { preserveOldSave = true; throw new Error('旧存档备份失败，原档仍保留；当前新进度暂不覆盖保存。'); }
        localStorage.removeItem(KEY + ':drafts');
        throw new Error('剧情版本已更新；旧存档和草稿已完整保留在本机兼容备份，新版从开场开始。');
    }
    engine.load(stored.save); if (sourceKey === RETRY_KEY) resetCampaignView();
    discoverySnapshot = engine.snapshot(); uiLoopId = discoverySnapshot.loopId;
    ui = { scenes: [discoverySnapshot.sceneId], people: [], readings: [], topicReadings: {}, drafts: {}, largeText: ui.largeText };
    if (stored.ui && Array.isArray(stored.ui.readings) && Array.isArray(stored.ui.scenes) && Array.isArray(stored.ui.people) && stored.ui.drafts && typeof stored.ui.drafts === 'object') ui = stored.ui;
    ui.topicReadings ??= {};
    ui.readings = ui.readings.filter(r => r.loopId === uiLoopId);
    ui.topicReadings = Object.fromEntries(Object.entries(ui.topicReadings).filter(([, r]) => r.loopId === uiLoopId));
    // Upgrade earlier stable saves from the actual confirmed-line history.
    const state = engine.snapshot();
    const confirmed = state.history.filter(h => h.loopId === state.loopId && h.kind === 'line').flatMap(h => chapter.dialogues.flatMap(n => allLines(n).filter(l => l.id === h.target).map(l => ({ n, l }))));
    for (const n of chapter.dialogues.filter(knowledgeTopic)) {

        if (visibleLines(n).length && visibleLines(n).every(l => rows.some(x => x.l.text === l.text && x.l.speakerId === l.speakerId))) {

        if (ui.topicReadings[topicKey(n)]?.loopId !== state.loopId) ui.topicReadings[topicKey(n)] = { loopId: state.loopId, nodeId: n.id, signature: topicSignature(n), lines: followup.map(x => ({ loopId: state.loopId, speaker: name(x.l.speakerId), text: x.l.text })) };
    }
    try { const storedDrafts = JSON.parse(localStorage.getItem(KEY + ':drafts') ?? 'null'); if (includeDrafts && storedDrafts?.loopId === uiLoopId) ui.drafts = { ...ui.drafts, ...storedDrafts.drafts }; } catch { /* keep current stable save drafts */ }
    hintsOpen = false;
    lastSaved = stored.savedAt; actor = engine.interactions().actorId; selected = []; panel = ''; responseLocked = false; technicalError = '';
    replay = null; reading = null; evidenceReply = false;
    // Earlier versions could save before completing the intro after closing its first line.
    // Reopen that narration so the player can read or skip it and unlock the first destination.
    if (!state.flags['progress.tutorial_completed'] && !state.flags['loop.seen_intro'] &&
        state.flags['loop.result'] === 'none' && state.sceneId === 'camp_gate' && !engine.interactions().nodeId) selectPerson('player');
```

来源：[GameStarter/web-demo/src/app.ts](../../GameStarter/web-demo/src/app.ts:646)。它恢复稳定状态，只保留存档轮次对应的界面对白和话题记录；分开保存的草稿也必须 `loopId` 一致才合并。旧档话题记录可以用实际确认的 line 事件重建。

内容版本不同，先备份完整旧主档和分开存储的草稿，再从新版本开场开始；备份失败时停止覆盖主档。`validateState` 本身只接受兼容版本，不会语义迁移旧资料。

终局前重试档要求轮次等于当前轮且结果为 `none`；“回到存档”使用 `restore(RETRY_KEY, false)`，随后删除分开保存的草稿条目，保留重试稳定档内原有的界面草稿。回到存档恢复的是旧状态，没有重新一轮，因此证据和许可可以随该检查点恢复。

## 9. 本次重点核对项与证据边界

- 当前复活清空历史对白和草稿，只保留教学完成标识。若产品希望主角复活后仍可查看上一轮对白或自己的方案，目前未实现。
- 记忆线索会进入润色请求，可能经玩家确认的最终草稿影响本句判断；它没有独立证据资格。
- 魏延仍有本轮剧情 flag，例如是否已经看过许可，它们影响固定剧情；分类模型本身不读取这些对白历史，只读取许可布尔值及实际证据。
- `assets/scripts/narrative/README.md` 中仍有“rewind 保留 memory、历史日志、草稿”的通用或旧描述，不能覆盖本文件所核对的五丈原专用 restart 分支。
