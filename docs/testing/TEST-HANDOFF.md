# 第一关合成玩家测试交接标准

版本：2026-10-26。用途：把在线画像交给独立 subagent 完成真实屏幕试玩，留下可核验记录。模拟角色不是真实消费者，也不是人口比例样本；H 档与模型配置不构成 IQ 或科学智力排序。年龄、性别不决定模型。

## 文件与职责

- 权威画像：[原配置表](https://my.feishu.cn/sheets/RuuwsyCMzh5lGetfbyCcz0sxnTc)，角色配置 `0CKUXL`、参数字典 `1WTGOu`、试玩指令 `2xnOnB`。
- [玩家任务模板](PLAYER-TASK-TEMPLATE.md)：协调者填完后复制给玩家，不附项目 README、策划、攻略或本轮其他玩家结果。
- [单次运行 Schema](run.schema.json) 与 [空运行模板](run.template.json)：一名角色一次独立首次游玩一份 `run.json`。
- [操作日志 Schema](step.schema.json)：`steps.jsonl` 每行一个已发生的观察或操作；空日志允许为零行。不要用示例点击填充真实日志。
- 每个实际 run 建议存放于 `outputs/user-testing-20261026/runs/<run_id>/`，其中保存 `run.json`、`steps.jsonl`、`report.md` 和确实取得的证据。不要生成 ZIP。

协调者可以阅读启动文档与版本信息，负责账号、模型可用性、存档隔离、UI 控制权和证据保全。玩家只获自己的行为参数、入口、工具范围、停止条件及报告格式。玩家不得读源码、存档内部状态、网络返回的隐藏字段、策划答案、未来剧情或其他角色报告。

## 每步怎么记录

日志只写可观察事实和简短决策理由，不索取、输出或保存私有思维链。每步包含：真实 UTC 时间、当前可见内容、证据引用、操作对象与输入、实际结果、是否成功或未知、下一步所依据的一句理由。批量连续点击只在每次结果均确实观察、可追溯时拆成真实步骤；不能凭预想补齐。

工具报错不等于点击未发生。结果未知时先观察当前屏幕；不可盲目重放。工具拒绝、等待审批、执行结果未知分别写 `denied`、`pending`、`uncertain`，保留目标、原因、已完成部分与最小恢复动作。

若工具明确要求本轮停止，停止其明确范围内的 UI 操作，不改用另一自动化途径绕过该限制。没有提供恢复步骤时，最小恢复动作写“待工具支持方或用户确认可行恢复方式”，不可声称重开浏览器、另开对话或改权限必能解决。首次接触游戏前被基础设施阻断时，状态为 `infrastructure_blocked`，玩家开始/结束时间、执行版本均为 `null`，步骤数为 0，四项反馈均为 `not_tested`、分数为 `null`；报告叫“准备完成／未执行”，不叫试玩反馈。实际模型仅在有成功调用证据时填写，否则为 `null`。准备期版本快照可在 `game.version_evidence` 中引用，不填写为 `build_id_start`。

所有时间必须真实记录；没有可靠记录的开始、结束、每步时间或时长均为 `null`，禁止估算或事后编造。已记录的开始、结束时间使用 UTC。总墙钟时长包含模型与工具等待，必须标注，不能称作玩家思考时间。未独立测量的模型等待、操作耗时、阅读时间全部留 `null`；不要估算“玩家花了几分钟”。耐心以表中行为参数和预先写明的无进展尝试预算执行；系统硬上限触发写“测试预算结束”，不得写成角色厌烦。

## 停止与反馈

终止分类：可见章末证据确认第一关完成；有具体行为与耐心依据的角色主动退出；真实游戏阻塞或工具/浏览器/隔离/模型失败。首次死亡或回溯不是通关，不得仅因此结束试玩；应依据可见进展与角色耐心继续。若协调者停止或测试预算用尽，单列为行政或预算停止，不冒充通关、角色退出或游戏阻塞。只看到某结局时报告该结局，不推断全部支线或全收集。

每名角色交付剧情、交互、画风、整体体验四项。每项均写实际体验范围、具体观察、证据、喜欢之处、困惑之处、建议；没有某类发现可写“本次未观察到”，不能为了齐全捏造。可选 1–5 分仅代表此合成角色在已测范围的主观评分，不汇总成真人满意度。未实际接触的项目标 `not_tested`、分数为 `null`。

画风必须实际看到截图或视频画面后评价；只读 DOM/对白不可评价画风。音频只在确实听到且能核对内容时标已测试，否则固定“音频未测试”。截图不能证明听过声音；视频首帧不能证明完整看完视频。

## 汇总与验收

按实际执行人数、完整体验人数、主动退出人数、游戏阻塞人数、模型阻塞人数和基础设施阻塞人数分别报告，列明未玩角色。不要以准备了十份配置声称完成十人试玩。

问题表列出：问题 ID、严重程度、涉及 run/角色、可见触发、复现步骤、预期/实见、证据、来源分类、模型能力效应判断和下一轮验证。来源分类使用 `game`、`model_execution`、`infrastructure`、`uncertain`；单名角色卡住只能记候选问题。模型效应用 `likely`、`not_established`、`not_applicable`，不可仅凭模型名称归因。

先验收 JSON/JSONL 可解析并通过对应 Schema，再检查：真实 C ID 与在线快照一致；模型调用证据一致；所有日志与反馈引用存在；画风引用实际图像；终止状态有证据；未执行角色没有伪造时间、点击、分数或通关。最后核对在线表仍为 100 人、原列/公式/下拉未被覆盖，新列配额与 effort 正确，读取回执或截图可追溯。自动验证和本轮模拟反馈均不代替用户审核。

时间字段仍须填写；`null` 表示未采集，不能估算补齐。字符串保留 `date-time` 格式要求。PowerShell `Test-Json` 默认不强制检查该格式，使用它验收时还须核验非空时间的 RFC3339 写法与实际日期有效性，不能只凭结构校验通过就认定时间有效。
