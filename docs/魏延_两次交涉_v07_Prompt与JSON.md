2026-10-11。规则已落实到 GameStarter/assets/scripts/narrative/weiyan.ts。仅使用本次实际出示的证据与当前玩家原话，不加入魏延记忆。分类、理由和规则均为 NPC 内部能力，玩家只看魏延对白。

## 输出契约

最终魏延回应是一个 JSON 对象，恰好两个字段；「决策分类」只能取「帐外等候」「坚持入帐」「震怒处斩」之一，「回应的话」必须与该决策及本句玩家表现一致。例如第二轮合理方案：

```json
{"决策分类":"帐外等候","回应的话":"你既要立刻请姜将军出来听急报，便速去。好，我暂不入帐。你立即从帐外请姜将军接报，莫误军情。"}
```

不是按文采、敬语或某个关键词打分。「语气合适」表示仍在认真解决急报，没有本人严重辱骂、杀害威胁或主动投敌毁报。直白、急躁、不说敬语和普通质疑本身不会导致失败。

## 两轮判定条件

|项目|第一次：教学|第二次：重新调查|
|---|---|---|
|硬性证据|实际确认禁令，再实际出示斥候证词|实际确认禁令，再实际出示斥候证词、姜维接报路线两张不同卡|
|证据意义|禁令在先；营门未失守，可短暂等接报|同前，另有守帐卒证明姜维在帐内，可从帐外请他接报|
|玩家必须说出的办法|承担立即代传承诺即可，例如“军情我会转呈，将军放心”；不先要求正确接报者和回令|有暂缓理由；自己或现场守帐卒现在从帐外请姜维出来接急报；魏延短暂等候|
|不强求的内容|特定角色姓名、固定措辞、预先许可、华丽文案|三张证据逐字背诵、固定措辞、四步手续、预先许可|
|帐外等候的剧情结果|接受代传承诺；急报交给甲却无有效处置与回令，次日虽未酿祸仍被处死|接受；后续立即接报，通关|
|坚持入帐|缺证据、只要求等候、只说可找人、无即时接报办法、拖延、捏造军令或否定急报|同前；只说「你可以找姜维」或「我马上请姜维」但未说明接急报，仍不合格|
|震怒处斩|玩家本人当面严重辱骂，明确威胁杀害魏延，或主动投敌/毁军报|同前；即使夹带合理方案也优先处斩|

引用他人骂话、否认威胁、劝阻烧毁军报均不是本人挑衅。荒谬办法通常是入帐失败；不把所有「很离谱」的话都判处斩。

判定顺序：本人严重挑衅 → 实际证据齐全 → 当前原话是否有立即接报办法 → 对应三种选择。证据齐全不代表玩家已经提出办法；模型不得自行补齐。营门未失守不代表急报不重要或可以明日再报。

## 实际调用结构

保留两步调用：先分类，程序核验原话与实际证据，选定预写剧情；再生成以上两个中文字段。内部分类 JSON 另含 requestId、choice、planQuote、reason，供程序校验，不是额外的玩家内容类型。planQuote 必须逐字来自玩家自己的当前输入，并包含实际接收或传递急报的表达；仅请人、找人不算。程序额外核验原话是否涉及传报动作，再由模型判断执行者、时机、路线、否定语义与语气；不是按词语数量评分。

生成步骤必须回传程序已选定的「决策分类」，保留预写结论。JSON 多字段、错分类、丢失结论、超时或危险措辞均回退预写结论，不改变已选剧情。分类请求异常保留草稿供重试，不算剧情失败。取消后迟到结果不生效。

## 第二次完整判定 Prompt（与源码一致）

