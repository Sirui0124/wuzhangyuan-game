# 时间倒流：人物与 UI 元素拆解 v01

本版已由[人物与 UI 元素拆解 v02](时间倒流_人物与UI元素拆解_v02.md)替代。v02 已同步《五丈原_教学关卡剧情本_v02》的两轮路线、场景与人物选择、传令卒乙举证及分项结算；本文件保留为前版设计记录。

本稿依据《时间倒流_互动叙事引擎_核心架构与流程_v01》拆解表现与交互，供共同定义玩法使用。尚未开发，也未确定最终美术。用户已明确主布局；具体交互、比例与角色造型均为设计建议。

## 已明确的界面方向

剧情画面是视觉主体，中下方显示对话与选项。右侧放「出示证据」按钮，点击后以浮层展开相关物品。常规入口保留设置、存档、帮助三个按钮。整体简约，参考《隐形守护者》《盛世天下》的影像叙事感，UI 的历史感更重。

## 整体视觉建议

人物采用电影写实方向，普通调查由场景与人物静帧承载，关键事件使用视频。人物尽量融入现场的光线和空间；同一角色的对话、证据插图与结果视频需要保持面容、服饰和光线连续。

五丈原以秋夜军营为视觉基础：旧帆布、粗木、麻绳、铁器与油灯。背景整体冷暗，人物面部和手部由灯火照亮，灯是剧情中持续可见的物件。人物肤色自然，保留疲劳、风尘与材质磨损。服饰依据角色职责区分，正式制作前另做时代服饰核对。

UI 使用墨黑半透明底、绢纸色文字、少量暗朱砂强调。标题可用有书写感的字，正文和输入区用易读宋体或清楚的正文中文字体。纸纤维、墨线、印记只在面板边缘和小面积标签中出现，避免遮挡画面和正文。初始色板建议：墨黑 #171917、绢白 #E7DDC8、朱砂 #954638、黯金 #AA9064。

历史感优先来自符合军营情境的简牍、文书和木牌。口述证据以来源与原话为主体，不能把所有证据都画成玩家持有的实物。

## 人物与场景元素

| 元素 | 在玩法中承担什么 | 美术与表演重点 |
| --- | --- | --- |
| 玩家 | 询问、举证、提出安排；具体历史身份待定 | 默认第一人称，先保证观察与交涉体验；身份会影响服饰、称谓和权限 |
| 魏延 | 关键交涉对象，必须让紧急军情得到处理 | 神态急迫、警戒；表演体现履职压力，不能用阴险反派造型暗示蓄意害人 |
| 姜维 | 传报与执行链的重要人物 | 状态稳健、专注于军务；接报后的回应用于确认行动落实 |
| 守卫 | 告知禁入安排和帐外规则 | 朴素军装、职责明确；通过动作或台词让玩家理解限制 |
| 前哨小兵 | 提供敌军出现的口述 | 奔走后的呼吸、尘土与紧张；叙述保留未知情况 |
| 诸葛亮 | 目标人物与情感核心 | 病中疲态、灯火与帐内静默；正式出场时机由剧情确定 |
| 帐外／前哨／帐内 | 调查、交涉与结果的空间 | 地点特征清楚、光线连续，避免用大量 UI 文字解释位置 |
| 主灯、传报木牌、禁入安排 | 关键物件及信息载体 | 分别表达世界状态、有限用途、已知规则；不把木牌视觉设计成最高军令 |

## 一套主界面，按情境展开

以下比例以桌面 16:9 为讨论起点：上方约 70% 保留人物与场景，中下方约 25%–30% 容纳对话、选项或交涉输入。选择出现时对话区域向上收拢；长文本允许展开阅读，不靠缩小字号塞入。

| 区域／控件 | 显示内容 | 交互建议 |
| --- | --- | --- |
| 剧情画面 | 人物、现场、视频、调查物件 | 可调查对象用轻微标记，点击查看；不做常驻任务栏 |
| 中下方对话框 | 人物名、台词；关键证词可展开为短句 | 继续、追问或选择目标证词；被质疑的原话在举证时保持可见 |
| 选项区域 | 预设问话、调查、执行行动 | 纵向排布短选项；仅推进剧情事件的行动注明代价 |
| 右侧「出示证据」 | 当前交涉的证据入口 | 普通浏览也可打开；没有可回应证词时只查看，说明出示条件 |
| 右上角三个入口 | 设置、存档、帮助 | 小图标配悬停标签；菜单中补足返回和关闭 |
| 短暂提示 | 新证据、行动结果、章节位置 | 就近出现后收起，重要内容可再读 |

推荐把交涉组成同一画面里的三个步骤，避免一次要求玩家面对完整表单：

1. **选定原话。** 在对话框选择要回应的那条证词，例如「必须现在进帐面见丞相」。证据浮层顶部固定显示这句话，并允许更换。
2. **选择证据。** 右侧浮层展开本轮已获取的物品和信息；查看详情、选择或取消，允许组合证据。选中后不会立即交给判定系统。
3. **组织说法。** 浮层收拢，已选证据缩成可点击的条目，中下方显示一个输入区，提示「你凭什么这样判断？接下来由谁做什么？」提交按钮使用「向魏延说明」一类人物化文案。

通常问话和执行继续使用预设选项；开放输入集中在关键交涉。这与架构文档一致，具体输入自由度仍留待玩法讨论。

## 证据浮层需要表达的信息

首版证据数量在四张以内，无需复杂背包、分类栏或搜索。建议右侧浮层覆盖约 35%–40% 画面，仍能看到交涉人物；证据详情在同一浮层内展开。

每条证据显示名称、类型（口述／文书／实物）、来源、取得时机和原话或内容。详情用「已知」与「尚未确认」解释证明范围，例如前哨口述只能确认敌军出现，不能证明营门已失守。物品另外显示用途和所需权限。

浮层中的「本轮证据」用于出示；另以低强调入口查看「回溯记忆」。过去循环读过但本轮尚未取得的信息在记忆中可重读，并明确标记「本轮尚未取得，不能出示」。记得木牌存在，也不等于当前持有木牌。回溯记忆无需增加常驻按钮，可以从证据浮层和失败复盘进入。

教学证据例子只有禁入安排、传报凭据或有限授权、前哨口述已在架构中提出，具体获取形式尚未定稿；不为填满四个格子额外创造证据。

## 反馈、执行与回溯

| 状态 | 玩家看到什么 | 必须保留的区别 |
| --- | --- | --- |
| 正在提交 | 对话区提示「等待回应」，暂停重复提交 | 输入内容与已选证据保留；阅读、写字与请求等待不推进剧情时间 |
| 论证不充分 | 人物指出具体缺项，提供修改说法或继续询问 | 不播放剧情失败，不自动耗尽等待窗口 |
| 方案尚缺条件 | 人物说明缺少的接报人、授权或执行步骤 | 有限同意不等于过关 |
| 人物接受安排 | 人物回应，出现「开始传报」等行动选项 | 必须继续落实安排；普通对话区承担反馈即可 |
| 行动推进 | 明确行动代价和等待结束条件 | 使用事件阶段，不放真实倒计时；例如「完成这次传报前，将军愿意等候」 |
| 技术异常 | 简短错误提示与重试入口 | 不包装成人物拒绝，不改变世界状态 |
| 剧情失败 | 结果画面结束后显示简短因果复盘 | 提供返回交涉前与回到当日傍晚两个入口，并说明各自恢复范围 |
| 局部成功 | 魏延留在帐外、军情得到处理、主灯仍亮的结果 | 只说明第六夜局部改变；不能宣称已让诸葛亮延寿 |

存档与时间回溯承担不同用途。存档用于恢复进度；失败后的回溯选择是剧情与循环的一部分，应在结果界面直接出现。是否允许随时主动完整回溯尚待讨论，暂不额外增加主界面按钮。

## 常规界面

设置建议包含音量、文字速度、字幕／视频跳过与显示选项。存档界面以章节、地点、关键状态和时间区分记录，明确标示自动检查点。帮助说明用少量实例解释证词、证据、安排，以及哪些行动推进事件；详细历史属性可在证据来源中查看。

首版视觉设计需要覆盖：剧情对话、问话选择、调查详情、证据浮层、交涉输入、人物反馈与执行、失败复盘、设置、存档、帮助。它们可以复用同一套面板与字体系，无需各自设计成独立大系统。

## 下一轮先讨论的一项玩法选择

关键交涉时，玩家表达自由度决定输入区和引导方式。建议先确定：

- **自由输入理由与安排**：最贴合当前架构，玩家自己组织推理；需要清晰提示和具体反馈。
- **选行动，再自由写理由**：先选接报人和行动组合，再说明依据；较容易理解，创意安排空间有所收窄。
- **全预设选项**：操作最快，分支内容更可控；举证体验主要来自选证据与选方案。

我的初步建议是第一种：普通调查与执行用预设选项，关键交涉自由输入，教学提示逐步提供帮助。此建议尚待共同确定，不作为已经接受的玩法规则。
