# 时间倒流：统一玩法与文本规范 v1

2026-10-11。本文统一玩法、记忆、文本条件、内容格式与协作目录；供【玩法构建】落实引擎、剧情对话编写章节、UI 消费可用操作。具体故事以《五丈原_教学关卡剧情本_v02》为准。本规范替代旧架构文档中冲突的流程，不另开一套玩法。

## 1. 将玩法收束为五种操作

**切换场景 → 选择人物与话题 → 调查/举证 → 关键说服自由输入 → 执行承诺。** 结果由事件规则结算，死亡后回到傍晚，保留玩家记忆。普通对话使用预设文本与选项；AI 只理解关键说服输入。

五丈原固定兑现两条核心路线：直接拦魏延并完成越职转报，保灯但玩家处斩，得到侧帐线索；复活后向乙举证、提前联系姜维、取得本轮许可、完成传报交接，保灯且生还。只说服不执行会失败。新场景、授权和人物回应都必须由实际经历解锁。

首版采用事件时间与完整回溯。暂不做好感度、随机说服概率、开放生成剧情、复杂军事操作，也不实现另一套检查点回退；可跳过重复演出并快速重新确认旧线索。

## 2. 记忆只保留发生过的事

每次有效操作写一条事件：哪一轮、哪位人物、哪个节点、选了什么、出示了哪些证据、判定结果、实际改变了哪些 flag。flag 是事件的状态摘要；日志用来解释因果和复盘，不能凭 AI 摘要重建世界事实。

| 记录 | 存什么 | 回溯规则 |
| --- | --- | --- |
| 玩家记忆，`memory.*` | 已经历结局、已听线索、已理解规则 | 保留；一次性演出记录同样保留。 |
| 本轮事实，`loop.*` | 已听本轮证词、军情进度、人物位置、许可、承诺 | 重置为章节初值。 |
| 人物认知，`loop.npc_*` | 该人物本轮亲历或收到的消息 | 重置；不读取玩家跨轮记忆。 |
| 本轮证据实例 | 证据 ID、取得轮次、取得节点、来源事件 | 重置；按记忆快速确认也必须真的触发当轮来源节点。 |
| 交互历史 | 节点/话题/台词到达记录、尝试次数、上次缺项、输入草稿 | 本轮记录重置；草稿和已看演出记录可跨轮保留，不能提供权限。 |

“打开人物对话”不会自动标记所有话题已听；到达并确认具体台词后才写入该条 effects。跳过演出等价于确认这条既定剧情，不跳过尚未选择的分支，也不自动执行承诺。

NPC 不知道玩家上轮说过什么。复活后可显示玩家内心“他仍不认识我”，不能让魏延说“你上次又食言了”。人物记得本轮已出示的证据、实际承诺与交接，这些记录决定后续回应。

## 3. flag 注册与组合条件

每个 flag 必须在 `initialFlags` 注册 ID、作用域、所有者、初值、允许值及含义。布尔值用于单个事实，枚举用于互斥进度，避免同时出现“已等待”和“已离开”等冲突。作者不能临时造 flag；AI 返回也不能直接写 flag。

建议五丈原首版使用下列状态。`loop.*` 均本轮重置；未列出的扩展须先注册。

| ID | 类型 / 初值 | 由什么操作写入 |
| --- | --- | --- |
| `memory.seen_execution` | false | 确认直接路线处斩结果。 |
| `memory.knows_relay_tent` | false | 处斩流程中听见乙的侧帐线索。普通灭灯不写入。 |
| `memory.knows_urgent_rule` | false | 听完甲的急报规则。 |
| `loop.player_alive` | true | 处斩事件改为 false。 |
| `loop.lamp_lit` | true | 闯帐事件改为 false。 |
| `loop.guard_heard_urgent_rule` | false | 完成对应台词；同时取得 guard_statement。 |
| `loop.knows_jiangwei_inside` | false | 本轮询问甲谁在帐里。 |
| `loop.scout_questioned` | false | 完成本轮军情追问；取得 scout_statement。 |
| `loop.weiyan_status` | approaching | 枚举 approaching / waiting / departed；交涉、领命或闯帐驱动。 |
| `loop.relay_agreed` | false | 对乙的说服通过；尚未递话。 |
| `loop.request_sent` | false | 实际执行托乙递话。 |
| `loop.jiangwei_approval` | false | 姜维批准节点；同时取得 approval_note。 |
| `loop.relay_location` | relay_tent | 枚举 relay_tent / waiting_area；请乙到场行动。 |
| `loop.report_status` | none | 枚举 none / delivered / replied / relayed；交接、取回话、转达依次改变。 |
| `loop.unauthorized_reroute` | false | 风险警告后选择承担并实际越职递报。 |
| `loop.npc_weiyan_saw_approval` | false | 当面向魏延出示有效本轮凭条。 |

证据持有状态由证据实例管理，不再额外维护同义的 `has_xxx` flag。承诺进度由承诺记录管理，不复制成三套状态。

条件只有六种：`all` 全满足、`any` 任一满足、`not` 取反、`flag + equals`、`evidence + mode`、`intent`。所有层使用同一条件求值器。空 `all: []` 表示无条件，空 `any` 不允许。

```json
{
  "all": [
    {"flag": "memory.knows_relay_tent", "equals": true},
    {"flag": "loop.player_alive", "equals": true},
    {"not": {"flag": "loop.request_sent", "equals": true}},
    {"any": [
      {"evidence": "entry_notice", "mode": "presented"},
      {"evidence": "scout_statement", "mode": "presented"}
    ]}
  ]
}
```

这组条件让乙在相关举证后开启递话话题，仍可要求玩家补齐另一条证据。`held` 表示本轮有效持有；`presented` 表示这次向当前人物实际选择出示，必须同时有效持有。`intent` 来自选择的说话目的或 AI 识别出的白名单意图。一次交互结束清空出示上下文，不能把上次出示给甲的证据当作已给乙看。

## 4. 人物能否对话与话题如何解锁

按顺序检查：场景入口可见 → 场景可进入 → 人物可见且位于本场景 → 人物可交谈 → 本话题可用 → 本选项可选。每层分别配置条件和不可用提示。剧情状态依赖统一事实；UI 只显示引擎返回的结果，不自行决定解锁。

| 对象 | 示例条件与表现 |
| --- | --- |
| 侧帐入口 | `memory.seen_execution && memory.knows_relay_tent` 后可见。死亡中获得线索，复活后才能进入。 |
| 甲 | 在帐门且玩家存活时可交谈；问过急报规则后新增“确认急报规则”，不再重复首次长对白。 |
| 斥候 | 本轮在传报处；问完后可重读军情，不刷新证据或推进时间。 |
| 魏延 | approaching 或 waiting 时能谈；departed 后不能把他从事件外召回。 |
| 乙 | 侧帐可进入后可选；被请到候报处后，侧帐提示“已往候报处”，候报处提供交接话题。 |
| 姜维 | 本关没有任意自由攀谈入口；乙实际递话后解锁帘边的限定接报对话。 |

话题里允许多个回应节点，`topicId` 相同，`availableWhen` 不同。优先使用最高 `priority` 的匹配节点；同优先级多个匹配属于内容错误。每个话题提供普通回应兜底，剧情关键动作不靠兜底强行通过。

以魏延的“暂缓入帐”为例：

| 状态 / 玩家选择 | 对应回应 | 写入结果 |
| --- | --- | --- |
| 选择预言，无当前证据 | “军情岂能凭怪话耽误？” | 只记录本次尝试，提示举证，不改变军情。 |
| 出示禁入记录，选择阻止，无接报安排 | “谁来接报？” | 解锁“补充接报办法”；不进入等待。 |
| 禁入与军情依据齐全、已知姜维在帐内，提出请姜维接报，无批准 | “你去叫姜维，我在这里等回话。” | waiting，开始直接传报承诺。 |
| 有本轮批准、当面出示凭条并提出交接 | “报信的人呢？你带来。” | 记录看过批准，waiting，开始授权交接承诺。 |
| waiting 且承诺尚未完成，再点人物 | “军报还在等着。” | 显示当前未执行步骤；重谈不延长等待。 |
| report_status=replied，再选择转达 | 领命回应 | 执行转达后才 relayed、departed。 |

## 5. 每段对话统一使用一种格式

唯一类型契约：`content/schema/narrative.ts`；格式样例：`content/examples/dialogue-format.example.ts`。正式章节写 JSON，严格遵循同一结构，不在台词里嵌可执行脚本。

每个 `DialogueNode` 定义：ID、场景、人物、话题、标题、目标证词或 null、触发方式、优先级、可用条件、重复策略、台词列表、选择列表、自由输入或 null、完成 effects、后续节点或 null。人物使用 placements 配置本轮位置条件，每次只能匹配一个位置；自由输入用 intentOptions 提供可选说话目的。

每条台词拥有独立 ID、说话者、文本、可选显示条件和媒体、到达后的 effects。选择包含显示条件、可选条件、意图、可选行动 ID 和 Outcome。Outcome 统一为固定回应、effects、后续节点；自由输入的不同判定结果也使用此格式。

`trigger` 区分点击话题、出示证据、事件推动。`repeat` 区分本轮一次、全程一次、可重复。本轮一次已看节点应有可重复重读/追问替代，不能让所有对话消失。一次性效果使用事件 ID 去重；重复点开不能重复发道具、启动同一承诺或加时间。

普通节点：预设对白和选择。关键说服节点：`freeInput` 配置问题引导、可编辑起句、证据要求、判定 ID、各类回应。执行节点：玩家选择后调用 `actionId`，实际 action effects 更新世界。`next` 只引导进入节点，不等价于玩家已完成节点中的行动。

动作效果只能使用契约中的 setFlag、grantEvidence、startPromise、fulfillPromise、breakPromise。内容作者能配置这些效果，引擎验证其注册 ID、值域及作用域；AI 没有 effects 接口。带 actionId 的选项先校验并执行 action，再提交该选项 Outcome；同一状态变化只配置在一处，不在两者重复启动承诺或发证据。

## 6. 自定义说服：有引导，有记忆，有明确判定

进入关键话题后，先选当前人物/目标证词、选择说话目的、选择证据，再填写理由与安排。输入框可合并两部分；提示三个问题：证据说明什么、请谁做什么、如何回应对方顾虑。可点“给我一个开头”填入可编辑起句；默认不把完整通关答案自动填好，不替玩家提交。

意图首版限于 ask_rule、ask_contact、propose_wait、propose_handoff、revise_plan、confirm_reply。采用语义等价判断，不要求固定关键词或文采。AI 可以澄清“你是请求批准还是声称已有命令”；未支持的合理创意反馈为待澄清或范围外，不污名化为逻辑错误。

同一交涉重试时保留草稿、上次已成立部分与具体缺项，提示“上一段理由已成立，请补充接报办法”。重试后仍按完整当前事实判定；先前认可不能成为以后伪造证据的依据。

请求只给当前角色、当前话题、选中的本轮证据、与该人物相关的本轮事件、当前授权/承诺和当前缺项。结构化记忆优先于自由摘要；日志按当前人物/承诺检索少量相关记录。玩家跨轮记忆仅可提供为玩家已知信息并注明 NPC 未知，不将未来结局、隐藏答案或旧轮批准当人物已知事实。

AI 返回 accept / need_evidence / need_plan / out_of_scope / clarify，以及意图、支持的证据 ID、缺项和解释。程序再次检查：实际持有并出示、获准意图、当前前提、有效状态版本。通过后优先匹配 JudgeDefinition.acceptanceCases，区分直接路线与授权路线；没有专门匹配时用 freeInput.outcomes.accept。每项选择和判定只提交一个 Outcome，不能两次应用 effects。

技术异常走独立 UI 状态，保留草稿并允许重试；不作为剧情判定，不写失败 flag、不推进时间。预设备用表达须显式提示“使用预设交涉选项”，不能将本地选项检查声称为自由文本 AI 理解。

## 7. 承诺和军令必须执行

承诺实例记录 promiseId、发起角色、开始事件、状态 pending / fulfilled / broken、完成步骤和 delay 计数。认可请求只开始承诺。完成条件由实际行动记录和 completedWhen 一起检查，不能用输入里的“我已经递报了”完成步骤。

- 直接传报：去帐门 → 经过风险警告选择承担 → 实际交付军情；触发 delivered 与 unauthorized_reroute，再结算保灯和处斩。
- 授权交接：实际请乙到场 → 当面交接军情 → 取姜维回话 → 向魏延转达；依次推进 report_status。姜维许可须在此承诺之前取得。

首版 delayBudget=2。必要传报链行动为 none；无关耗时行动为 delay。第一个 delay 给临界警告，第二个打破承诺、触发魏延闯帐。阅读、重复询问、写字、AI 等待与驳回均不消耗预算。明确放弃承诺可直接 broken。新说服不能重置已启动承诺的 delay。

事件结算至少区分：灯灭失败；直接传报保灯后处斩；授权传报完成后安全成功。处斩必须在 unauthorized_reroute 且 delivered 后发生，不由 AI 临时决定。安全成功同时要求未越职、批准有效、军情 relayed、灯亮、玩家存活。

## 8. 引擎伪代码与事务顺序

```text
getAvailableInteractions(state, scene):
  校验场景、人位置、人物交谈条件
  求值所有话题条件与重复策略
  按话题分组，选最高优先级；返回人物、话题、选项与不可用原因

confirmLine(lineId):
  检查该台词确实已到达、未提交同一效果
  原子写入台词事件和 effects；刷新可用话题

submitFreeInput(node, evidence, intent, text):
  校验节点、本轮证据、输入；锁定一次请求并记录 loopId + revision
  await AI(只包含当前交涉相关记忆)
  若已回溯/节点改变/版本过期：丢弃返回，保留草稿
  校验 AI 返回、意图和证据；将文本含义映射到已有 Outcome
  校验 Outcome 前提；原子写判定事件、effects、承诺
  显示回应与待执行动作；不直接完成军情

chooseAction(actionId):
  再次检查当前前提；用 interactionId 防重复点击
  原子写行动事件与 effects；更新承诺实际步骤与 delay
  检查承诺完成/打破条件
  按优先级结算事件，直到稳定；每个事件本轮至多触发一次
  保存状态和日志，再播放结果；跳过/重播媒体不重复 effects

rewind():
  保留 memory、历史日志、已看媒体和草稿
  loopId 换新；loop flag、NPC 认知、证据、许可、承诺重置
  当前场景回 entrySceneId；清理请求、当前人物和出示上下文
  从保留 memory 重新计算场景/话题；显示侧帐发现引导
```

前端存档记录 schemaVersion、chapterId、contentVersion、loopId、revision、flag、证据实例、承诺、交互记录与事件日志。读档先校验；不兼容版本明确提示，不悄悄把旧许可迁移为新许可。首版只做本机存档与同版本恢复。

## 10. 校验与交付边界

导入前校验 ID 唯一、flag 已注册且值域正确、所有引用存在、每段台词的说话者有效、条件非空/合法、场景人物位置一致、分支有兜底、动作不越权、事件不循环触发。非空 onComplete 仅用于无 choices/freeInput 的线性或结束节点；分支节点 effects 放对应 Outcome，避免双提交。类型校验覆盖结构，引用与可达性必须另做内容校验。

实际验证两条主路线与三个反例：无执行不能通关；普通灯灭不能解锁侧帐；回溯后旧授权不能使用。同时验证重复点击不重复写状态、NPC 不记上一轮、AI 晚返回无效、技术异常不消耗时间。以路径中的状态变化验收，不用“能看到文字”代替玩法闭环。

本轮交付统一规范、数据类型与格式样例、引擎伪代码。正式剧情和可试玩引擎由相应对话继续落实；当前不宣称已经试玩。
