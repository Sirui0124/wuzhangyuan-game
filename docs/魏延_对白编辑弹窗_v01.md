# 魏延对白编辑弹窗 v01

两次魏延交涉均使用同一套对白编辑工具。用户先实际出示所需证据，再点击「撰写回复」进入大弹窗；AI只协助整理草稿，最终必须由用户点击「确认回复」才进行魏延判定。

## 交互

桌面弹窗约占屏幕64%，避开上方标题和左侧地点导航。美术版使用深绿底、金色细框与朱红确认按钮；白模同步支持。证据、线索、润色与提示位于可滚动工具区，输入框和确认按钮持续可见。390宽度时弹窗位于导航下方。

| 模块 | 已实现行为 |
| --- | --- |
| 出示证据 | 显示本次真正提交的卡片。点击查看来源原话、能说明什么和尚不能说明；「修改」打开现有呈证面板，返回保留草稿。 |
| 记忆线索 | 从本轮已确认的魏延、斥候、守帐卒甲对白中取最多8条去重短语，允许选取与取消。只给润色参考。 |
| AI润色 | 点击向下展开，选择目的、语气，填写最多200字其他信息，再点击「确认生成」。 |
| 你的对白 | 最多1000字，可自行输入或修改生成文案，显示字数。 |
| 提示 | 两次交涉分别有固定提示，提醒理由、立即接报及执行者；只展示提示，不改草稿。 |

目的为「劝将军暂候／说清接报安排／保留原意」，语气为「敬重而坚定／平和说明／简短直接」。空白原稿只生成一个请求暂候、询问接报安排的开头，用户仍需自己补全办法。

## AI与证据边界

润色调用沿用现有本地代理8787，无历史对话与NPC记忆，25秒超时。输入为玩家原稿、目的、语气、其他信息、选中短语及实际出示证据；输出是一段主角对白正文。提示词要求保留执行者和承诺程度，不捏造军令、权限、位置及新证据，不把「营门未失守」写成没有危险。生成内容仍是模型建议，用户需要在提交前复核；样例中的含糊建议保留了原执行者，但模型仍可能补入已出示证据中的理由。

记忆线索是玩家回想对白的写作工具。它不授予证据、不计入魏延硬门槛，也不送入魏延分类器。本次没有增加NPC长期记忆。已有的三种决策和两轮证据门槛保持不变。

生成时可取消。关闭、切换节点、离开交谈或读档会中止本次生成；迟到结果不落地。若用户在等待期间修改原稿，完成后的文案不会覆盖新文字。异常、空结果、超长或错误格式均保留原稿。点击确认回复后等待魏延判定，重复提交与润色暂时禁用。

## 验证与文件

`npm run build:demo`通过，润色模块4项单测通过。最终纯文本协议的4组真实代理调用全部返回可用文案，覆盖两次合理计划、含糊建议与空白开头。早期JSON格式错误及承诺补写问题的原始记录保留，没有计入最终通过结果。

8821浏览器从正常开场取证，未注入剧情状态。第一次实际润色后提交，魏延接受立即转报，随后记恨、抬走并到达牺牲。第二次实际重新取得并提交禁令、斥候和姜维证词，润色后提交；魏延回应「你既愿即刻往帐外请姜将军出帐接报，便依你之法行事」，接报执行后到达生还。取消生成、等待期间修改、固定提示、证据修改、刷新保留、桌面美术／白模／390宽度均有实测记录。
