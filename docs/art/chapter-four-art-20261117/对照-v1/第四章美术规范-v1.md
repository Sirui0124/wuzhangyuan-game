# 第四章 · 夷陵撤军指挥美术规范 v1

日期：2026-11-17。状态：**设计提案，待用户审阅；尚未实施到试玩。**

适用：第四章独立试玩的地图、前线问话、往来军报、出兵调遣及其局部提示。v6 保留作对照，不接入正式第四章。本稿以用户新指定的两套本地素材替换 v6 的整屏墨绿色美术方向；不更改玩法、剧情、数值和自然语言判定。

## 1. 美术结论

本关采用 **“炭黑军帐，纸本舆图，墨字军报，少量旧金与朱砂”**。

《崇祯模拟器》提供地图和文书的物质感；《江山北望》提供外围界面、选中框与叙事气氛。两者按用途分工，不在每个组件上混合木纹、金框、墨迹和卷轴。

玩家首先看到可读的战区地图，然后是收到的军报，最后是自己写下的问话或军令。画面应像军帐里正在使用的图与文书，有明确的前后层次。主要操作保持平面、稳定、清楚；不靠满屏材质和装饰表达“古风”。

## 3. 色彩、材质与形状

以下为本关建议值，尚待实际页面校验。色彩语义优先于装饰。

| 用途 | 色值 | 使用边界 |
|---|---|---|
| 外围炭黑 | `#171717` | 顶栏、屏幕边缘、暗色外壳；无墨绿偏色 |
| 暗页底 | `#252421` | 调遣页外壳、确认框；与背景保持微弱层次 |
| 舆图纸 | `#C9C0AB` | 大幅地图；降低亮度，避免像白色网页嵌入黑背景 |
| 军报纸 | `#DED6C5` | 阅读区和输入区；文字背后保持干净 |
| 纸面正文 | `#292723` | 军报、地名、输入文字 |
| 暗底正文 | `#E7E0D2` | 暗面板的主体文字 |
| 暗底次要文字 | `#B4AB9B` | 过去时间、辅助信息；不可用于必要风险提示 |
| 旧金 | `#B69A64` | 当前选中对象、主要按钮边线、小型重点标记 |
| 纸面朱砂 | `#8E4037` | 急报/冲突标记，与“急报”“待处置”等文字同用 |
| 暗底警示浅朱 | `#DE9B8D` | 暗面板警示文字；不用深朱砂直接压在黑底上 |
| 河道青灰 | `#65777B` | 仅用于地图水系，不扩展为全局主题色 |

画面面积的初稿目标：暗色外壳约一半，纸面约一半；金色、朱砂只占零星小面积。这个比例用于判断整体气氛，不作为程序硬指标。地图纸与军报纸相近而不完全相同，避免出现两块明亮白卡。

材质仅三类：外围低对比暗布/木案、地图薄纸、军报书写纸。每个主要阅读面只用一种底材。纹理的局部明暗变化控制在不影响小字的程度；初稿可从约 3%–6% 叠加强度试起，再按最终合成检查。污渍、折痕只放边缘和空白处，禁止穿过正文、地名、路线交叉点。

面板以直边和微小不规则纸边为主。常规控件圆角 0–3px；不用胶囊按钮、玻璃模糊、浮空大阴影、金属渐变球和呼吸光。不是每块区域都加框：主图有纸边，军报靠分隔线，输入区靠纸色和焦点框识别。

## 4. 地图专项规范

### 构图与绘制

地图是本关主视觉。采用正视俯瞰的纸本战区图，保持现有节点、地形关系和可通行路线。先用无材质的线路草图核对拓扑，再绘制山川，最后叠加游戏标记。装饰山脉不能暗示不存在的阻断或通路。

- 山：疏密有序的短线、山形轮廓和少量灰褐染色；不做卫星影像、强立体浮雕或云雾遮图。
- 水：青灰色平涂河道，支流层级清楚；不加高光波浪动画。河名与地名避免密集交叉。
- 路：深褐细线，进入标记附近时留出空间。山体纹理的对比必须低于路线。
- 地名：动态文字独立绘制；主要点名 20–22px，次要地名 16–18px 为本关初稿等级，不代替对白标准。关键地名小屏也不能缩到难读。
- 边缘：允许轻微纸边与固定压纸角；不放无功能罗盘、闪烁雷达、装饰仪表和密集坐标网格。

### 信息图层

从下到上：纸张 → 山川 → 已知通路 → 最后获报标记 → 当前选中/军令预览 → 按需展开的信息。

| 信息 | 表现 | 不能造成的误解 |
|---|---|---|
| 三支前线部队 | 名签，使用“沙摩柯”“冯习·张南”“傅肜”完整名称 | 不能与玩家甲乙丙丁接应队混成同一组选择 |
| 已获报位置 | 小旗或点位配部队名；选中后显示原有报告时间 | 不表现为实时精确位置；不编造时效阈值 |
| 玩家接应队 | 简洁方签/旗签，附甲乙丙丁队名 | 不靠四种高饱和颜色区分身份 |
| 当前计划 | 细虚线与“拟令”文字；仅有实际预览数据时出现 | 不能画成已执行路线 |
| 未知状态 | 使用现有“未确认/未获新报”等真实文字 | 不新增敌人轮廓、数量或预测进度 |
| 新军报 | 对应名签短暂强调，详情进军报区 | 不用全屏弹窗打断普通报告 |

路线与状态依赖真实数据；没有的数据不为完成视觉效果而虚构。不得为画面完整新增敌军红点、胜率、威胁条和隐含倒计时。

### 尺寸与适配

以 1440×900 作为首张审阅图，另验 1280×720。上方地图初稿占可用高度约 45%–50%；玩家无需滚动即可看到当前对象、最新军报和输入操作。地图使用统一坐标变换缩放，背景与标记一致；禁止分别拉伸底图与点击坐标。窄屏优先减少装饰、折叠历史军报，保持输入字号；不把整张桌面界面缩成小图。

## 5. 页面与操作区

### 前线页

顶部只保留章节标识、现有时间/暂停/速度及设置等真实功能，视觉弱于地图。时间控件不做大号倒计时仪表，不新增时间机制。

地图下方是一条连续的指挥工作区：左侧选择三支前线部队并写问话；右侧阅读往来军报。两侧共用清晰的横向基线，避免六七张独立卡片。

三支部队使用简单名签，当前对象用金色短线和“当前”语义状态标明。问话输入区是可直接书写的纸面，不伪装成不可编辑的古籍。示例只用一条简短提示；建议项置于次级位置，点击后填入可修改的草稿，不夺走自然语言输入的中心位置。

**“出兵调遣”入口放在下方“往来军报”标题旁。顶部不新增“前线/调遣”页签。**

### 出兵调遣页

进入独立页面处理甲乙丙丁接应队：队名、现有兵力与任务清楚排列；下方以自然语言下令。不要为了模仿参考游戏增设粮食滑杆、技能树、军械栏或资源仪表。

军令预览将“对象、要做的事、会改变的安排”排成可读的文书短段落，突出真实变化；仍由现有逻辑给出结果。只有一个视觉主按钮负责发令。返回前线入口与原来调遣入口位于相近工作区域，减少寻找。

此规范只规定信息层次；输入解析、确认条件、自动配给等继续沿用当前游戏行为，不通过美术改稿暗中改变。

### 军报

每条依次为来源、时间、正文。正文占主要篇幅；不用头像气泡聊天列表和逐条圆角大卡。普通报告用墨字；真实需要决策的冲突用小朱砂标记及明确标题。历史记录降低对比但仍能阅读，不删除事实。

普通报告留在记录中，不弹确认；当前流程真正要求决策时才出现相应处置区域。弹窗沿用“外围暗、内容清楚”的材料关系，不满屏高斯模糊，不遮住需要比较的地图和报告。

## 6. 字体、按钮和反馈

同类字号继续服从[跨章节字号与字幕标准](../CHAPTER-TYPOGRAPHY.md)：对白/军报主体按 24px、行高 1.8、既定楷体字族；说话人 22px；普通选择 20px；导航 16px。不能直接拿参考素材字体替换全游戏正文。章节标题可以另做小范围题字，但不把长句、按钮或数字写成难辨识的草书。

必要数值与单位横排并列，保留真实“人”“斤”含义。主文字不描金、不叠粗阴影。题字只用于章名或场景名，不给每个分区都加书法标题。

| 控件状态 | 规范 |
|---|---|
| 默认 | 暗底浅字或纸底墨字，细边；次级动作更弱 |
| 悬停 | 边线略提亮，不放大控件、不挤动排版 |
| 键盘焦点 | 连续可见的清楚外框，不能只靠暗金色变化 |
| 选中 | 一条旧金边/短线与小型标记；语义状态同步 |
| 按下 | 底色轻微变深；不播放盖章动画拖延操作 |
| 不可用 | 降低装饰强度，必要时给出具体原因；不能低对比到看不清文字 |
| 请求处理中 | 同一按钮显示真实处理状态，保留草稿；不伪造前线回话 |
| 失败 | 就近明确提示并可重试；不要用“军令已发出”的装饰掩盖失败 |

可点击区域至少 44×44px；字短的按钮可通过内边距扩大，不必把图形拉大。普通文字对比目标 4.5:1，大字和重要控件轮廓按其适用标准检查；透明纸纹叠加后重新测量，不能只测原始色值。

动效建议：切页/展开约 160–220ms，选中反馈约 100–160ms，新报标记一次轻微强调即可。不得循环闪烁、逐字打字阻塞阅读，或用无关镜头漂移模拟“沉浸”。这些是本关建议，不是从两款参考中测出的时长。

## 7. 素材制作清单与实施顺序

| 优先级 | 产物 | 验收要点 |
|---|---|---|
| P0 | 1440×900 前线页静态稿 + 1280×720 适配稿 | 看清地图、当前对象、最新报告、输入与调遣入口；整屏无绿色罩染 |

| P0 | 前线名签、接应队旗签及选中/获报状态 | 三路前线与四支接应队能明确区分 |

| P1 | 调遣页与军令预览稿 | 沿用现有机制；不加资源配置表单；返回位置清晰 |
| P2 | 少量纸缘、暗纹及过渡动效 | 关闭装饰后信息结构仍成立；不影响输入和阅读 |

先完成 P0 的构图与可读性，再制作纹理。禁止先生成一张漂亮的整屏图，再把输入框和地图节点硬贴上去。地图若使用生成工具，输出只作地形/纸材底图；所有文字、节点、路线和状态由可编辑层管理。

原始制作文件放 `source-art`，发布资源放独立试玩对应资源目录。地图建议保留至少 2 倍目标显示分辨率；长按钮与面板用可伸缩边框/九宫格，不拉伸角饰。参考资产用于比较与研究，新版游戏资源另行制作或复用本项目已有合适素材，不把参考游戏成品直接作为交付资源。
