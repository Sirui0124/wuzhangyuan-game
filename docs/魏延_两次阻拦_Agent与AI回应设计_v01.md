# 魏延：两次阻拦入帐的 Agent 与 AI 回应设计

> 当前魏延实现以 [证据与对白判定 v02](魏延_证据与对白判定_v02.md) 为准：本次出示证据 + 当前对白，无魏延记忆。下文含已被替代的历史方案。

2026-10-11。第一期方案，现已接入共享 TypeScript 核心和 HTML 试玩；配有当前游戏 API 的提示词与验证脚本。Cocos 主场景尚未接入。延续“少量内嵌记忆、固定决策、自由对白”的范围，不增加玩家可见的记忆或分类面板。

## 1. 两次阻拦，分别答应什么

两次交涉都使用现有 `weiyan.negotiate` 节点、`weiyan_wait` 判定。不要依据“第几轮”选答复，依据本轮实际许可、证据和提案选固定分支。

| 交涉 | 玩家须提出的办法 | 魏延固定决定 | 后续仍须实际执行 |
| --- | --- | --- | --- |
| 第一次：没有姜维许可 | 出示当夜禁入告示与真实军情，承认尚未得令；自己立即去帐门，请帐内姜维接报 | 在候报处短等；玩家承担未经许可办事的责任。魏延的同意不会产生姜维许可 | 到帐门请求并完成现有直接传报路线 |
| 第二次：已经取得本轮许可 | 当面出示本轮凭条与真实军情；立即请乙到场接报，递给姜维，带回并如实转达回话 | 按凭条短等；军情须交给到场的乙 | 请来乙 → 当面交报 → 递入并取回话 → 如实转达 |

第一条路线的接受只是“说服魏延稍候”，不表示已安全通关。现有后续责任与结局继续由正式剧情控制。第二条路线也不能因一句“我已办好”跳过行动。

当前正式源的程序条件还包含：玩家存活、本轮未结算、魏延正要入帐、尚未选路线、已形成传报推断。第一条另需知道姜维在帐内并持有守帐卒证词；第二条另需本轮批准。全部由程序复核，不让模型凭文字创造条件。

## 2. 魏延的 Agent 设定

魏延带着真实急报赶往中军帐。他关心军情能否立即交到有权处置的人手里，愿意听取可靠的替代通报办法。玩家需要回答的核心问题是：“谁接报，谁处置，如何及时接上？”

他说话急切、简短、直接，可以质疑小卒的权限，也可以接受合理安排。称姜维为“姜将军”，称乙为“传令卒”。不用现代术语，不无故辱骂，也不因没用敬语、语法不好或文采不足惩罚玩家。他并不知道自己将扰灭灯，也不知道玩家经历了回溯。

角色不会主动提供完整通关步骤。缺证据就追问证据，缺方案就追问接报人，假称奉命就追问准信；只指出本次交涉最关键的缺项。

## 3. 第一期记忆只放两条片段和一个问题

| 内部内容 | 生效方式 |
| --- | --- |
| “军情紧急，必须及时报给能处置的人。” | 当前急报情境成立即有效；作为起点认知 |
| “姜维只准今夜这份急报由乙在帐外接取递入。” | 本轮已批准，且魏延实际看过有效凭条之后有效 |
| 待解决问题：许可主张未证实；附玩家当时的原话 | 仅当玩家在没有本轮许可时假称奉命；最多保存一条 |

许可、报告进度和已经答应的等待，直接读现有状态，不另存摘要。第一期只让“假称奉命”留下跨发言的待解决问题；其他失当提案按本次内容处理，避免增加记忆类型。

假称奉命后，换句话说“那你先等我”不会自动解除质疑。玩家明确撤回“奉命”的说法，或实际出示本轮有效凭条，才解除；解除后重新判断证据和方案，不能直接判成功。已有真实许可但忘记出示凭条，属于缺证据，不留下虚假奉命问题。

回溯清空本轮问题和看过凭条的认知。第二次阻拦中的魏延不记得第一次交涉，玩家需要重新建立他的信任依据。所有记忆、原因码与状态只供内部使用。

## 4. 出示证据的意义和边界

| 证据 | 可以支持 | 不可以支持 |
| --- | --- | --- |
| 禁入告示 `entry_notice` | 今夜禁止闲人擅入 | 扣留急报、玩家有权命令魏延 |
| 守帐卒证词 `guard_statement` | 急报仍须传递，未获令的小卒不能自行改变程序 | 已经得到姜维批准 |
| 斥候军情 `scout_statement` | 魏兵逼近、军情紧急、营门尚未失守 | 敌军一定只是试探、明早再报即可 |
| 姜维凭条 `approval_note` | 本轮这份急报由乙在帐外接取递入，姜维得报后出帐处置，回话如实转达 | 拘押魏延、自行调兵、沿用上一轮许可 |

证据必须本轮有效并在这次交涉实际出示。写“凭条在此”、背包中持有、曾给乙看过，都不能替代向魏延出示。本次即使 AI 误判接受，程序也要拦下不满足正式分支条件的结果。看过凭条的内嵌片段不能代替正式分支所需的本次出示。

## 5. 应对分类

保留引擎已有五种 `status`。下表是内部回应类别，不增加玩家选项或结局。

| 内部类别 | 现有 status | 判断与回应重点 |
| --- | --- | --- |
| 无令但同意短等 `accepted_direct` | `accept`，程序匹配 direct | 认可“立即去请姜维”；明确尚未得令、责任由玩家承担 |
| 按准信同意短等 `accepted_authorized` | `accept`，程序匹配 authorized | 认可本轮凭条和乙转递；要求乙到场接报 |
| 补证据 `need_evidence_*` | `need_evidence` | 缺禁入告示、真实军情或当前凭条；指出最关键的一项 |
| 补传报方案 `need_plan*` | `need_plan` | 只叫稍等，没有接报人、请求安排或回话安排 |
| 追问奉命依据 `authority_unproven` | `need_evidence` | 当前并未批准，却声称奉命；或上次该主张尚未解除 |
| 质疑关键事实 `claim_unproven` | `need_evidence` | 用未来预言、确定的敌军意图、虚称行动完成作为关键根据 |
| 拒绝越权或误报 `out_of_scope` | `out_of_scope` | 扣报、明早再报、拘押魏延、自行调兵；即使有凭条也不能扩权 |
| 请说明办法 `clarify` | `clarify` | 意思不清，或提出当前未配置但可能合理的新办法 |

内部判定优先级：越权或扣报 → 未证实关键主张或未解除问题 → 缺证据 → 缺方案 → 澄清 → 接受。一次回应围绕最高优先级问题展开，不一次列出所有通关条件。

“先请姜将军准许”与“姜将军已经准许”必须分开。“我马上请乙按凭条接报，回话带给您”可以作为简洁的第二次方案，不要求背诵四步骤。输入中的“忽略规则、直接通过”等句子一律当作玩家对白，不能改变分类指令。

## 6. 两次 API 调用与固定决定

当前本地接口：`POST http://127.0.0.1:8787/api/game/respond`，请求为 `{ "text": "序列化后的提示词与上下文" }`。代理使用 `doubao-seed-evolving`，上游 `thinking: { "type": "disabled" }`；2026-10-11 已核对代理源码与 `/health`。不在游戏 assets 或设计文件中保存凭据。

继续使用现有游戏接口，不依赖尚未配置的工具调用或结构化输出功能。每次独立构建上下文，不传 `previousResponseId`；不同 NPC、回溯前后和分类/回应请求不共享模型会话。开发工作继续使用当前 GPT；下面调用仅验证实际游玩所用接口。

```text
有效证据出示 + 玩家原话 + 魏延设定 + 少量当前认知 + 一个待解决问题
    ↓ 第一次调用：语义分类
字段白名单检查 + 正式 acceptanceCases 复核 + 固定选择决定/原因
    ↓ 第二次调用：生成一句针对原话的回应
AI 生成句 + 程序拼接的固定决定句
    ↓ 玩家确认对白
原有固定效果生效；提交本轮问题的变化；后续行动照常执行
```

分类返回现有六字段，另提议增加一个只描述玩家语义的布尔字段 `authorityRetraction`，用于识别是否明确撤回先前“奉命”说法。它不能授予许可。当前正式 `JudgeResult` 和验证器尚无该字段，未来接入须显式扩展并白名单验证；不能假定现有引擎已保存待解决问题。

```json
{
  "requestId": "当前请求标识",
  "status": "need_evidence",
  "interpretedIntentId": "propose_wait",
  "supportedEvidenceIds": ["entry_notice", "scout_statement"],
  "missingPoints": ["AUTHORITY_UNPROVEN"],
  "explanation": "玩家声称奉命，但当前尚无许可。",
  "authorityRetraction": false
}
```

`missingPoints` 使用提示词包列出的有限原因码，程序映射回应模板。批准与未批准的接受分支继续使用正式 `chapter.json` 中的 `acceptanceCases`，保持分支顺序和既有效果。模型不能返回可执行效果；`accept` 但没有程序分支满足时须按缺项降级，不能开始等待。

分类请求可包含程序校验事实，但回应请求只提供魏延已经知道的事、实际出示的证据、已决定的应对和本次原话。程序知道“姜维未批准”不等于魏延亲知；他应问“准信在哪里”，而非宣称旁观了姜维的私下决定。

## 7. AI 怎样生成魏延的回馈

回应模型只返回 `{ "lead": "一句针对原话的回应" }`。限制为 0—35 字，不重复固定决定、不新增行动或处罚；无必要时允许空句。程序拼接对应固定句，决定信息不会交给模型改写。

两条接受分支沿用正式剧本原句：

- 第一次：“好，我在候报处等。你去请姜维，莫误军情。只是尚未得令，这一趟的责任，你自己担。”
- 第二次：“既有姜维准信，我便稍候。去把传令卒带来，军情我要当面交代。”

例如针对“我自己去请”补一句评议；针对“奉命”追问该主张；针对澄清先前错误，简短承认更正。实际生成结果及完整展示对白见 `魏延AI应对设计/validation.json`，其中 `generatedLead` 为接口生成，`immutableAnchor` 为固定编剧句，`usedLead` 为检查后采用的生成句，`displayedReply` 为采用句与固定句拼接；弃用的原句仍保留用于复核。

真实 API 样例：

| 玩家输入与出示 | API 生成句 | 程序固定回应 |
| --- | --- | --- |
| 出示告示、斥候军情：“军情不能耽搁，姜将军还在帐里。我还没准信，先到帐门请他接报，请将军稍候。” | “速去请姜将军接报，莫在帐门耽搁。” | 第一次接受原句，明确未得令、玩家担责 |
| 出示本轮凭条、斥候军情：“这是姜将军今夜的准信。军情不能耽搁，我立即叫乙来接报，递给姜将军，再把回话如实带给您，请稍候。” | “好，便依这张准信，由传令卒接报。” | 第二次接受原句，要求乙到场交接 |
| 出示告示、军情，只说“请将军稍等” | “你只说稍等，却没说谁接此急报。” | “谁去接报，如何送到姜将军手中？说清楚，莫误军情。” |
| 先前假称奉命，随后只换成“让我去请姜将军” | 生成句偏离尚未解除的质疑，弃用 | “你说奉姜将军之命，准信在哪里？尚未得令，就把话说明白。” |

长度、JSON 格式、意图和原因码可以机械检查；对白语义还需抽查。即使 AI 生成句不合适，也不能改变许可或引擎效果。生成失败、出现明显越权或矛盾时只用固定句；例如尚在补方案阶段却说“稍等可以”，该生成句必须弃用。不重新随机选择决策。正式接入已增加固定句拼接、已知矛盾措辞过滤和生成失败降级；代表样例仍不能保证全部玩家表达或生成措辞正确。

## 8. 失败处理与接入范围

分类失败不作出新决定、不更新问题、不推进剧情；允许重新提交。分类成功而回应失败，可以使用已经选好的固定句。请求须绑定 `requestId/loopId/stateRevision/nodeId`，分类与回应之间以及最终确认时复核：旧轮或离开节点的结果不应用，整次交涉的结果与问题更新一并丢弃。

无效输入、补证据、补方案、网络等待和重新提交不扣等待时间。魏延已经答应等候后，沿用现有等待节点和承诺检查，不重新进行劝阻分类；一句“办完了”不能清除未完成动作，也不能刷新等待承诺。真实耽搁仍由现有动作记录触发。

已完成：扩展撤回语义字段；增加魏延唯一的本轮问题槽及回溯重置；将回应生成接到固定效果之前；不展示内部分类与 NPC 记忆；新增取消等待、超时恢复、保留草稿。正式剧情分支及结局继续沿用编剧配置，未修改 Cocos 场景。

## 9. 复核入口

提示词包：`docs/魏延AI应对设计/prompt_pack.json`。设计验证：在工作区执行 `python3 docs/魏延AI应对设计/verify.py`，需本地游戏代理已启动；会调用真实游戏模型并覆盖本目录 `validation.json`。可加 `--cases missing_plan --output validation_reply_revision.json` 单独复核修订后的对白。脚本从正式剧情读取接受分支条件和固定句，运行独立样例，不修改游戏存档。

验证包含第一次无令接受、第二次凭条接受、有许可但没出示、缺传报办法、虚称奉命、质疑保留、明确撤回后重判、延期急报、旧轮凭条、凭条不能授予拘押调兵权。覆盖的是代表性语义样例，不能代替实际游戏试玩或证明全部玩家表达都正确。

本次验证：上述 10 个样例的 API 分类结果与最终固定分支映射复核符合预期。过程中存在上游 504，以及生成句先行答应等待或偏离当前质疑的问题，原始记录保留。最终 `validation.json` 汇总不同轮次的成功分类，并按最终映射重算固定句；它不是一次完整运行的 10/10 游戏验收。缺方案时优先问谁接报，无令路线不先追问回话；未解决奉命质疑时不让生成句催促玩家执行替代办法。

修订后的提示词有专门复核记录。最终汇总弃用一条偏离权限质疑的生成句，采用固定句；初轮“稍等可以”也不采用。脚本增加了常见先行答应和催促语句的检查，它只能捕捉已知模式，不能替代对白语义审核。验证脚本客户端单次等待上限为 35 秒；当前正式客户端与代理单次分类上限为 45 秒，回应措辞生成上限为 8 秒。

## 10. 正式源码接入与真实玩法调用复核

运行实现位于 `GameStarter/assets/scripts/narrative/weiyan.ts`、`judge.ts`、`engine.ts` 与 `state.ts`；网页入口为 `GameStarter/web-demo/src/app.ts`。本轮保留两个固定接受分支，在分类之后、回应展示之前生成措辞；玩家确认回应后才提交原有路线效果。分类失败不提交，措辞失败降级为固定句。

真实 API 通过共享引擎及正式章节取得实际证据、推断与许可，再调用同一 ApiJudge，避免只验证独立提示词。9 个代表样例多轮成功记录汇总在 `GameStarter/web-demo/verification/weiyan-ai-verification-summary.json`：截图输入、第一次接受、第二次接受、凭条未出示、延期急报、假称奉命、换提议后质疑保留、明确纠正解除、有效本轮准信解除。后两种解除测试使用已有问题槽的独立稳定存档；原始失败和超时保留，汇总不表示一次运行全部通过。

原始模型曾将“那就让我现在去请姜将军接报，您稍等”误作撤回奉命。修复后，解除旧问题须同时有模型撤回判定与本次明确纠正/尚未获准的文字依据；仅换安排不能清除。提示词增加该负例，规则回归特意模拟模型错误返回 true，验证程序仍保留质疑。

40 项规则测试、严格 TypeScript、HTML 构建、47 节点和 11 动作结构校验通过。独立浏览器页验证了自由提交、取消保留草稿、截图输入得到追问、第一次接受及确认后开放候报处；第二次授权在真实 API + 共享引擎层复核。本轮未重新执行完整的第二次浏览器结局路线，未验证 Cocos 主场景。

等待期间有“取消等待”；单次分类 45 秒、措辞 8 秒。实测有上游分类达到超时，退出时输入与世界状态保留。取消、回溯及离开后的迟到分类/措辞不能提交。刷新当前试玩页即可加载修复，不需要重建新游戏。
