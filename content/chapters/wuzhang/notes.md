## 内容与对白

四个场景为中军帐门、营前传报处、传令侧帐、帐外候报处。四个主要可交谈人物为甲、斥候、魏延、乙；`notice` 和 `curtain` 用现有 Character / DialogueNode 表示调查热点，`player` 表示开场与记忆整理热点。姜维、诸葛亮、旁白和执行者只注册为演出说话者，不提供自由人物入口。它们没有 placements；`talkWhen` 的死时条件仅作不可自由选择的兜底，实际没有位置，任何状态都不能从人物列表选中。

魏延始终关注真实军情能否及时抵达有权处置的人。他愿意等的是可落实的接报安排；没有凭据、只说预言或把禁入扩大成扣报授权，他会追问军情出口。乙能代问、转递，不能自行批准；姜维一直从帐内或帘边回应，许可取得后才出帐处置。所有 NPC 重复回应只引用本轮事实，不记得玩家上轮说过什么。

普通调查和军情追问使用预设对白。关键说服分别为 `relay.contact` 与 `weiyan.negotiate`，都有三个引导问题、可编辑起句和五种有限结果；不把整段通关答案填进输入框。`evidenceSelection=optional` 允许没有证据时仍提出请求并收到缺证据反馈；真正推进世界的 acceptanceCases 严格要求当次向当前人物出示必要证据。持有不等于出示。两处明确标注的 `preset` 节点提供预设交涉，不声称经过自由文本 AI 理解。

证据为四类：禁入告示、甲的证词、斥候完整军情、姜维有限凭条。具体文书和口述措辞都是游戏补写，`historicalBasis=fiction`。它们借用演义舞台，不冒充从史料截取的文件。`source` 说明获得地点与原话／内容；`proves` 与 `cannotProve` 限制论证范围。姜维在帐内是笔记 flag；军情回话由 `report_status` 和对白事件记录，不新增第五类证据。

初问节点、记忆快速确认节点、本轮重读节点共用 topicId，以互斥 flag 和不同 priority 区分。快速确认仍发生在本轮真实来源地点，确认台词后才发证据；重读不发新证据。`scout.report` 的追问进入 `scout.followup`，也可以直接点“追问军情范围”；两者内容一致，证据实例由同一 evidenceId 去重。

## 数据和执行约束

所有 flag 共29项，显式注册 scope、owner、初值、允许值及含义。核心进度用枚举：魏延位置／等待、乙位置、军情阶段、选定路线和本轮结算。`loop.route` 不允许本轮已经启动直接承诺后再凭一次交涉切换路线，以免重启等待或绕过教学死亡；重新回到傍晚后恢复 `none`。

`memory.*` 保留，`loop.*`、NPC 本轮认知、证据实例、许可和承诺重置。侧帐可见同时要求 `memory.seen_execution`、`memory.knows_relay_tent` 和玩家活着，因此死亡演出中不会开放导航。普通灯灭只写 `memory.seen_lamp_failure`，不发侧帐线索。已有线索的玩家以后普通失败仍保留发现，这是回溯规则的自然结果。

`event.direct_execution` 先锁定 `loop.result=execution`，进入固定演出；乙线索只在确认 `ending.execution.clue` 时记住，真正死亡与 seen_execution 只在确认 `ending.execution.death` 时写入。首次演出不能漏读这两条效果；跳过当前已选择片段仍逐条确认。结算片段完整结束后才提供回溯入口，不能在听线索前回溯而宣称已取得线索。

`event.safe` 检查批准、魏延已看本轮凭条、军情已转达、未越职、灯亮、玩家存活。军情状态只能由有前提的实际 action 推进，承诺以 requiredActionIds 和 completedWhen 同时判断。内容不在 action effects 里调用 fulfillPromise：由引擎在记录本次 action 后完成承诺，避免在行动尚未入账前提前完成。

阅读、输入、查看证据、切换人物、重读以及本章场景导航都不消耗事件时间。两个显式 `delay.unrelated_*` 动作表示离开当前职责去追查闲谈：第一次临界警告，第二次破约、入帐灭灯。必要传报链全部为 `timeCost=none`。明确放弃通过 `promise.abandon` 立即破约。没有现实秒数倒计时；普通调查也不作为偷偷扣时的行为。

## 使用现有契约的接入建议

以下为交给【玩法构建】／UI 的明确建议，均没有擅自添加 JSON 字段。

1. **版本与终局。** Chapter 没有 contentVersion、ending、rewindAction 或 chapterLink 字段。加载器传入上面的内容版本；终局通过 `loop.result` 与三个 ending 节点识别。结算完成后 UI 提供引擎回溯按钮。后续两入口只显示现有 Outcome，不实际加载不存在的章节。
2. **开场与回溯引导。** Chapter 没有 onEnter。首次加载可打开 `player.intro`（arrival 话题），已确认开场后打开 `player.return`。回溯首次完成任一调查或记忆整理时，事件 `event.relay_discovery` 推送发现引导；它不自动带玩家进入侧帐。若要求回溯后立即展示，引擎需要在 rewind 后进行一次事件结算，沿用同一 EventRule。仅线索节点确认后写 `memory.seen_relay_guide`，保证一次提示。
3. **媒体类型。** 四个 Scene.mediaId 全为 null。Line.mediaId 的契约只允许 string 或省略，不允许 null；本章所有台词均省略该字段，没有虚构图片、视频或资源 ID。若以后希望每条台词都写 null，应统一扩展唯一契约。
4. **物件与演出人物。** 现有 Character 没有 role 字段，先用前述 ID 区分 UI 热点、玩家内心和演出说话者。四名主要人物之外的调查热点使用“查看／听取”，不要显示为新的第五名可交涉角色。以后可在唯一契约增加明确 role，不建第二份配置。
5. **行动必须来自当前节点。** Action 没有 sceneId、actorId，也没有“当前场景” Condition。动作世界前提已完整配置，但引擎仍需验证动作来自当前可见且可选的 Choice、当前场景和当前对象。不要把 Chapter.actions 当全局快捷按钮，否则可在错误地点请乙到场或越过台词片段直接执行。11个动作都有正式节点选择入口。
6. **next 的表现。** 本章承诺成立、乙到场等 Outcome 多数 next=null，让玩家主动切场景和选对象；少数线性 next 进入递话、批准、警告或结局。action.next 是引导，不能重复执行动作；event.next 优先进入结算。使用 actionId 的 Choice 完成 reply 后，应消费唯一 pending next，一次推进。
7. **AI 请求的有限事实。** requiredPoints 描述两种方案，acceptanceCases 负责世界前提。请把本轮相关批准、姜维在帐内、选中证据及当前承诺事实传给判定，勿仅取 owner=当前人物的 flag，也不要把其他角色的全部日志或未来隐藏分支透出。fallback accept 没有推进 effects，防止模型误判后无证据起承诺。
8. **展示可用性。** 若引擎列表只包含可用节点，默认询问节点和 evidenceSelection=optional 仍给缺证据玩家自然入口。不可用选择应使用其 label 的具体缺项和 lockedText 提示，普通 lockedText 只是兜底。
9. **引擎核查点。** `scout.followup` 的条件台词需按行到达时检查；grantEvidence 应幂等。同一承诺重谈不重置 delay。终局锁住普通选择并允许事件对白跨场景播放；否则 result 写入后会误把结局入口拦住。
