## 操作与策略

点地图军情，安排本路总人数、工作次序、其中的掩护人数、原部配合、专项物资与收队条件；“照此排定”保留本轮安排，“结束回合”才实际出动。原军令跨回合持续，前置在回合末完成，后续最早下回合开始。可以先用按钮完成整局，不需要输入文字或等待模型。

“比较本轮安排”用同一引擎计算工作进度、风险、支出与归营人数，不推进真实存档，不预告随机结果。路线军令笺也显示当前候选安排的数值。界面的工作量供比较策略：500人工作一轮完成500工作量，少量兵也按实际人数产生进展，每项一轮最多1000工作量。

- **傅肜**：分兵准备隘口与接替后阵，能提早形成退路；也可让原部在换防后整队一轮再回身掩护，少占接应兵。后队过隘需要工作兵和隘口掩护。不能将同一队同时算在两处。
- **冯习、张南**：迁旗与清路各500工作量，可并行或交换顺序，原军吏每轮承担250迁旗工作量。前置齐备后，将接应兵分在岔口引导与护送；通过半程记张南脱险，全程记冯习脱险。也可先护冯习收队，或张南出来即停止后续接应。
- **沙摩柯**：东沟500、西沟1000工作量。本部熟路军士每轮承担250搜寻工作，只搜一沟；接应工作兵可加快或分头搜。找到后下一回合才出林。林口足额掩护为第1—3回合300人、第4—5回合500人、第6回合起700人。沙摩柯先脱险，西沟与守口队仍有自己的结果。

部分撤回、整路完成后的归营，都真实占用一回合；轮末归营者下回合才可跨路出动。可以设置“等傅肜/张南/沙摩柯脱险后执行本次改令”；等待期间旧任务继续，新令所需兵力与物资列入待令额度。自我等待和互相等待会在确认前拒绝。已等待的军令若因战损使实际可用额度不足，将继续等待并说明，不悄悄动用未来归营兵。

## 数值与物资

初始2500名接应兵、8份军需，无疲劳、无刷新的自动补兵。新出动到同一路每开始500人消耗1份军需；同一路改分工不重复扣配给，归营再出动重新扣。原部只能在自己的现场承担上述工作，不进入通用兵池。

每路专项物资只用一次，消耗1份：

| 路线 | 专项作用 |
| --- | --- |
| 傅肜 | 队尾过隘工作量500降为300；仍需要隘口掩护 |
| 双将 | 撤军工作量1000降为500；岔口引导需求300降为200 |
| 山林 | 西沟搜寻转运工作量1000降为750 |

任务进展与减员风险分开。必要掩护足额风险0，达到六成但不足额为25%，不足六成为50%，空缺为100%且暴露地段通过暂停。每路每轮至多一次现场受挫，减25或50名可用接应兵；已经做完的工作保留。负伤、掉队和失联不全部写为死亡。各回合各路固定抽取随机数，因此相同初始种子的重试可以比较不同安排，不因另一路提前完成而改变本路的随机序列。

后阵、旧营、山林窗口分别在第6、7、8回合末关闭，先执行当轮任务再检查截止，末轮完成有效。未接出者保留未接出/失联结果，接应队下一轮紧急撤回，承担一次50%受挫概率。第9回合只收队点名。整局结束后分别展示四人、已知待接批次、接应兵、时间与余军需；没有把投入接应的人数当成获救人数，也没有新增总评分。

## 军令表达范围

实际执行由本目录TypeScript引擎决定。按钮支持同一路多岗位、既定任务先后、原部协同、在外减兵、归营、人物先走/继续接部众、等待另一位人物脱险后执行。

文字拟令与问讯可复用现有只读模型配置及模型传输，不改共享AI模块。生成只形成候选，仍要玩家核对并排定。服务端校验人数、资源、枚举及额外物资/新增协同的原话依据；明确人数被模型改错时自动重拟一次，仍不一致则拒绝采用。取消、切路、修改分工会使迟到回复失效。AI故障保留原话，手动分工可继续。

本版的文字军令笺一次处理一路；不支持任意未来脚本、甲乙分队身份跨路追踪、火攻、造桥或将原部抽去别路。不支持的要求会保留在未落实说明中，不能确认后静默略过。人物对白和开场采用简短军情；本次优先验证玩法，没有新增影片、配音、人物立绘或正式剧情接入。
