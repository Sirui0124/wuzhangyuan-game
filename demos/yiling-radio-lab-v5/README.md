# 夷陵前线 · 三路联络与出兵 v5

2026-11-17。独立试玩，待用户体验审核。入口 http://127.0.0.1:8954/ 。v4原样保留在8953，未接入正式第4章。

本次只拆分联络与调遣，并给三路问话接入受事实约束的API语义理解。战斗、行军、体力、侧翼、救援条件和时限沿用v4；`src/engine.ts`与v4逐字一致，不新增资源或剧情评分。

## 两个页面

- **前线联络**：`/#frontline`。选择沙摩柯、冯习张南、傅肜，询问位置、处境、需要的支援、为何不能撤、接应进展、窗口或敌情。左侧保留全线往来军报，避免漏掉其他路的紧急情况。问话不下令、不推进时间、不提前取得救援结果。
- **出兵调遣**：`/#dispatch`。查看甲700、乙800、丙600、丁400四支接应队的最近报告，用自然语言安排单队或多队。军侯复诵后由玩家确认，确认后返回前线持续执行。此页暂停战场，切换页面不会重开战局。

如果在前线页说“派甲队接傅肜”，只显示“去出兵页核对”，点击后携带原话到出兵页，不直接执行。两个页面各自保留尚未发送的文字，刷新后保留战局并暂停；切换对象或页面会取消未完成请求，迟到结果不得落到另一个对象。

## 三路问话依据

|联络对象|可了解的核心问题|状态变化|
|---|---|---|
|沙摩柯|东沟部众与西沟担架，找到将领后是否还要接伤兵|东沟接上后，支援需求转向西沟；接齐后仍须归营|
|冯习、张南|前队和后队的撤离次序，后队为何不能丢下|前队接上后仍报告后队未撤齐；两批各自按实际结果点名|
|傅肜|断后换防、守住退路、让换防者一起撤|接上前报告断后需要；会合后报告撤离；归营后不再说仍困后阵|

API只理解玩家问的是谁、哪类问题，再由本局已报告的事实组织答复。没有确切人数时明确未报，不编造部众数量、敌军兵力、未执行行动或未来成功。没有新定位就沿用“最后回报”，不提供全知GPS。失联后由军侯报告，不能让失联人物继续确认自己安全。

剧情方向沿用项目既有夷陵三路设定；此次没有扩写新的历史事件、正式章表或额外剧情系统。此联络方式是用户要求的三国题材交互调整，不宣称是《Radio Commander》的逐项原界面复刻。原作机制依据及数值简化范围见[v4说明](../yiling-radio-lab-v4/README.md)。

## 启动与验证

双击本目录`启动军报指挥试玩.cmd`，或运行`node launch.mjs`。需要项目现有Node与TypeScript依赖，沿用既有模型配置；不复制或修改凭据。

检查入口：`npm test`、`checks/browser.mjs`、`checks/layout.mjs`。实际结果记录在[发布检查](checks/release-verification.json)。开发检查不代表用户已经认可趣味性、对白或操作体验。

项目协作原则本轮已核对飞书在线rev39，并与本地副本比较一致。AI编剧专用对话读取不可用，本轮未联系其他人或改动正式AI模块；新增的联络适配限于本独立试玩。
