## 从Radio Commander复刻的部分

| 原作的指挥方式 | 本版实现 |

| 地图、通信记录与命令区共同构成指挥空间 | 一张纸本军图，下方持续军报与传令处；常规操作不切换人物大弹窗 |

## 怎样玩

接过军图后默认暂停。先联络任一路，听情况或直接输入。点击“说出”让军侯理解原意；明确军令会进入核对页，询问只得到回答。核对人数变化、出兵与粮草代价，点“照此传令”后，军图出现待执行安排，下一次结算才真正执行。

▶正常推进，4×加速，Ⅱ暂停。“推进至下次回报”可以直接结算一次。输入时、API请求和军令待确认时暂缓计时；查阅详情、札记或地图手记时也暂缓。切到后台自动暂停，刷新后保持暂停，避免玩家离开时偷偷消耗窗口。

普通报告自动进入通信记录。新增任务与原任务争抢人手时才请示，询问不会解除请示；可以增援、现队重整、在适用情形下救济，或明确接受照旧执行的后果。一次回复之后不会反复要求“继续”。

自然说法示例：

- “傅肜五百人，旧营八百人，沙摩柯七百人，都接齐回来，留五百预备兵。”
- “再给旧营添四百人。”
- “把剩下的预备兵全派给旧营。”
- “从他那儿抽回一半，留下的人继续接应。”
- “如果多派三百，跟现在比能快多少？先别下令。”
- “给旧营接应队补八百斤粮。”
- “给新增散兵发四百斤粮，接应队仍按原令继续。”
- “先让现有的人安置这批散兵，安置好再接后队，不增兵。”

“全部剩余预备兵”按扣除已有待执行安排后的余数计算；“一半”按当前队伍向下取整，确认页显示实际变化。人数和斤数不混用，否定的安排不执行。没有明确新派人数或补粮斤数时先问缺口，不默认给数。

## 策略与规则

冻结复用8949版的数值引擎，另设独立意图与表现层。初始2500名可调兵、5000斤前线粮。新兵每人携1斤，前线每人每时段用半斤，每队向上取整；额外补送、散兵救济分别记账，余粮随队归营。新回营的兵和粮下次下令才可调用。

三路窗口分别在第6、7、8时段末关闭。增兵可并行处理工作与新增任务，但占用预备兵并增加每时段耗粮；现队重整用时间换人力；救济只解决已知人群的饥饿，不能购买绳索、清除敌军或治疗重伤。缺粮使进展减半且增加25个百分点风险；已完成工作保留。

兵力及粮草守恒，固定种子便于同局比较。“札记→重新部署”可同局重试或换军情，先备份本局，不覆盖旧版。

## API与事实边界

真实使用现有模型配置理解自然语言，配置只读复用。NPC自由措辞不直接改存档；军令需通过语义、原话引用、人数、斤数、资源、任务和等待条件检查。

位置、兵粮、预计、人数比较和任务冲突的具体效果，由模型识别问题主题后使用真实引擎组织回话，避免模型将“足额救济解决问题”改写成“只能部分缓解”。比较的总数/增量必须引用当前原话；不提前泄露未知军情。原则性自由交流保留自然措辞，不能夹带未核算的具体数字。

取消、改写、切换对象或重开会使旧请求失效。服务失败保留原话并暂停，不伪装成模型成功。格式或含义校验失败自动纠正一次。界面支持可选系统中文语音读报，默认关闭；当前环境未完整验证声音质量，可完全只读文字，没有额外BGM。
