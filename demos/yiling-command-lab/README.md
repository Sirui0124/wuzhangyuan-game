## 玩家的循环

三路同时出现 → 看防线/接应进度/兵力 → 最多两条简短问讯 → 选队伍下军令 → 继续时间 → 追踪到达、敌军转向和撤离 → 暂停改令或召回 → 归营整顿再投入。

五支各500人的队伍：甲队为盾兵，坚守支撑高；戊队为轻卒，行军较快；其余为步卒。可以多选，跨路需要先回营；不能瞬移。返营只恢复疲劳，伤亡不自动补充。

三路统一使用防线、接应进度、敌军压力及接应/坚守/佯攻三种任务：

- 傅肜：守营断后。传达御驾已脱险的消息，接应效率提高；仍须撤走伤兵。
- 黄权：北岸集结。接应队的小舟往返已计入行军；唯一的成建制运输船队需另行派出。集结完成而无船时不会自动获救。这是原型的运输抽象，不是历史事实或正式章表既定设定。
- 沙摩柯：林中搜索会合。向导军令提高集结效率，绕行减少伤亡但变慢。

每路两条问讯不推进时间，不凭空完成救援。附加军令是可选的已知操作，不要求问中特定口令。已接入真实AI问讯和拟令；不支持的行动明确列在草案上，不能确认。手动调遣仍可使用，进入相同任务系统。

## 核心取舍与数值

以下仅为本次测试数值，不是史实或已批准正式平衡：

- 初始防线：傅肜72、黄权85、沙摩柯68；归零导致该路失利。
- 基础敌压：1.65 / 1.25 / 1.45；唯一机动援队增加0.85。240秒基础敌压+0.3，360秒再+0.25。
- 单队有效战力 = 当前人数/500 ×（1 − 疲劳×0.005）。坚守倍率普通1.8、盾兵2.1；接应1；佯攻0.75。
- 每秒防线变化 = −max(−0.025,（敌压−支撑）×0.22)。支撑足够时防线缓慢恢复；坚守本身不增加接应进度。
- 接应每秒进度 = 0.36 × 接应队有效战力和 × 路线倍率 × 军令倍率 × 剧情选择倍率 × min(1.1,1.65/敌压)。绕行效率0.9；傅肜与沙摩柯附加军令1.3。
- 每65秒评估一次机动援队目标：现场普通部队吸引权重1，佯攻权重5；同地略减权重，避免永远停在最初位置。改变目标提前20秒预告，到达后旧方向压力减轻，新方向上升。没有凭空复制援队。
- 直路行军36/48/28秒；绕行+18秒，轻卒乘0.8，疲劳会拖慢行军。
- 基础伤亡与当地敌压、路线、任务持续时间相关；绕行伤亡系数0.48，坚守0.65，撤离0.65。非战斗的行军不会扣战斗伤亡。
- 疲劳：坚守每秒+0.09，其他前线任务+0.15；归营每秒−0.45。可勾选低于220人或疲劳达到85自动撤回（护送撤离阶段不擅自离队）。
- 接应进度100后继续护送：傅肜38秒、黄权50秒（军令缩短到30秒）、沙摩柯32秒；途中防线仍承压。
- 船队赴北岸45秒；黄权接应完成后回南岸35秒。船只不被当作第二支战斗队，当前Demo只有黄权使用成建制渡运，没有假装实现多路抢船。
- 480秒仍未脱险的路线记为未完成；所有路线获得结果即可提前结算。

玩法深度来自不同时间安排和调度效率；首版未做自由画路线、额外占点、任意条件脚本、多人AI、动态天气或历史战场精确重建。

## v2 融合实现（2026-11-12，待用户试玩）

参考崇祯项目的《整理版/机制实现策划》与原始阶段一AI约束，简化为：玩家说军令 → AI给草案 → 玩家确认 → 规则系统执行 → 任务簿记录行军、等待、受阻、完成 → 依据实际结果复命。AI只拟令和对白，不能写入数值、虚构兵力或宣布胜利。重复确认不重复执行；战局变化后旧草案作废；取消等待或切路会丢弃迟到回复。

- 可用军令：派遣、召回、派船、既定联络准备、补送军需。支持到位后坚守/牵制若干秒再接应，撤回归营后跨路，等待另一路脱险后执行。新军令替代同队的未完成旧令；无法落实的条件列入“尚未落实”。任意火攻、修桥、自由拆队等不在本版能力范围。
- 例句：“甲队先去傅肜那边坚守40秒，再接人。乙队丙队去接黄权，同时派船。”AI拟成4项，未经确认不出兵。到达才开始计时，跨路必须实际归营。
- 初始军需4份。每路可补送1次，消耗1份，防线+10，现场部队疲劳−12；不补兵。补给在本版是即时调度抽象，没有新增运输路线。
- 每路共2次问讯额度，固定问句与自由提问共用。问讯不推进时间，不凭空产出救援进度。AI不可用时显示失败原因，保留原话，手动操作可继续。
- 三路接应达到35%各出现一次新军情，自动暂停。傅肜：花1份军需先接伤兵（防线+8、后续效率×1.1），或轮换抬人（效率×0.85、护送+12秒）；黄权：分批渡运30秒，或花1份军需稳泊点（防线+16、渡运50秒）；沙摩柯：继续搜寻（效率×0.85），或先护送会合者（效率×1.15，结尾保留未会合部众）。选择生效一次，写入存档和AI上下文。

剧情与对白参考江山北望的章节组织和人物说话方式：同一场撤军中的不同处境，人物先回应眼前事情，分支之后继续共同撤离主线，选择留下具体后果。已读参考工程架构与多章文本；本次对白为夷陵场景新写，没有移植参考游戏人物或原句。平时只显示简短军情，军帐对白按需展开，关键选择与结局按说话人展示。

AI复用正式工程已有模型配置和共享调用传输，本次未改共享AI模块、密钥或模型设置。独立适配入口为 `ai.mjs`，Prompt版本 `yiling-command-v2-20261112`。任务引擎 `src/orders.ts`、剧情阶段与分支 `src/story.ts`；正式存档不变。
