## 四局逐次传令、反馈与临场判断

### 1. 默认种子首局：临场形成办法

1. **第1时段**：“先分三路：派900人接傅肜、700人接冯习和张南、500人接沙摩柯。都把将领和部众接齐后回来；各路正常配粮、正常推进，余下400人留营待命。”开场三路初报指出傅肜第6时段关窗、旧营需迁旗清路、沙摩柯要搜两沟；我沿用旧版经验给傅肜较多兵，刻意留400应对突发。复诵准确列出900/700/500、正常配给，预计三路第4/6/8时段归营、全线食粮4850斤。确认后第1时段三路均推进，旧营出现新增散兵请示。
2. **第2时段**：“把营中待命的400人增派给冯习、张南这一路，专门接手新增散兵；原来的接应队继续收前后队，正常配粮、正常推进。”我选择增援而非400斤救济或重整，因预备兵恰好够且可并行接应。复诵700→1100；预计第5时段归营，但全线剩余粮可能不足。确认后第2时段旧营迁旗清路，第3时段张南脱险，第4时段冯习脱险，第5时段1100兵归营；全程不需对普通回报说“继续”。
3. **第6时段**：沙摩柯500人仍接西沟，营粮只余400斤，正常配给再需两时段各250斤。我临场说“沙摩柯一路现有500人不变，从本时段起口粮少给两成，正常推进，继续接齐西沟部众并护送回营。”复诵500不变、节用20%、两时段预计用400斤，同时明示本时段士气70→64、受挫概率25%。第6、7时段各发200斤，第7时段接齐，第8时段归营。结局4/4、3/3、0减员，粮0斤。

### 2. 同种子重跑：事先写定的应对规则

重跑前固定三步：**开局900/700/500留400并正常配给；若旧营新增散兵，增援留营的400；第6时段若沙摩柯仍接西沟且营粮400，改为八成配给**。页面依次输入的原话与首局上述三句完全相同，各次复诵均正确。第1时段旧营冲突、第2时段增援、第6时段沙摩柯节粮、第8时段归营，数值与首局相同。这验证同一默认种子下这个**多次改令的条件模板**可重复，不能称为“开局后完全不操作”的固定打法。

### 3. `seedOffset=2`：固定开局，按不同军报调整

1. **第1时段**输入与首局相同的900/700/500、留400、正常配给军令。复诵仍预计第4/6/8时段归营。实际第1时段冲突换到了沙摩柯：西沟新发现饥饿部众，可增400人、救济500斤、重整或接受效率降至50%。
2. **第2时段**：“把营中待命的400人增派给沙摩柯一路，接手新发现的饥饿部众；原队继续搜两沟、守林口，正常配粮和推进，全部接齐后回来。”这里沿用“把留营400人增派给发生冲突的一路”的固定规则，具体对象由真实军报决定。复诵500→900、预计第6时段归营，同时警示全线粮可能不足。
3. **第5时段**，第4时段末旧营请示明确写出“下一时段自动补给需800斤，营中仅余650斤”。我临场输入：“营粮不够下一时段正常补给。冯习张南现有700人、沙摩柯现有900人都暂时少给两成口粮，仍正常推进、继续把各自部众接齐，不抽兵。”复诵两路人数不变，分别用280和360斤，合计640斤；第5时段两路均接齐，第6时段归营。结局4/4、3/3、0减员、余10斤。此分支没有机械套用默认种子“第6时段只改沙摩柯”。

### 4. 主代理指定对照：仅改变配给政策

同默认种子沿用900/700/500留400、旧营冲突增400、正常推进；区别是三路**从开局均按八成配给**，而基线只有末段沙摩柯改八成。先后两条合并三路的原话均返回502“这次没听清安排”，页面显示未调兵、未扣粮；随后拆成三条真实军令并逐条确认：

1. “派900人接傅肜，接齐部众后回来，口粮少给两成，正常推进。”复诵节用20%，但傅肜预计**第5时段**归营、余下食粮1440斤，反比正常配给预计第4时段、1350斤更慢且多吃90斤。
2. “派700人接冯习、张南及部众，接齐回来，口粮少给两成，正常推进。”复诵节用20%、预计第6时段归营。
3. “派500人接沙摩柯，搜齐东、西两沟部众后回来，口粮少给两成，正常推进。”复诵节用20%、预计第8时段归营。
4. 第1时段末同样出现旧营散兵冲突。第一次措辞“把营中待命的400人增派……总计1100人……”返回502“人数需忠实引用本次原话”，未传令；简化为“给冯习张南一路增派400人，接手新增散兵；继续接齐部众，仍少给两成粮，正常推进。”后复诵700→1100、八成配给并确认。此局没有后续改变配给。

第3时段冯习一路受挫，25人负伤或掉队；第4时段傅肜才脱险，晚于基线第3时段。沙摩柯第6、7时段因士气继续下降，页面显示节奏修正65%、额外风险15个百分点；第8时段最终接齐归营。较基线省粮570斤，但损失25兵；结束士气傅46、冯47、沙28，远低于基线70/71/58。两次合并原话失败及一次增援原话被拒绝，使本局用了7次 API（4次成功、3次502）。这属于真实游戏交互失败，不计作工具超时。

## 判断与建议

- **三路兵力与留兵**：900/700/500留400在两种军情均能作为开局骨架，但两种冲突恰好都能用400人化解。留兵是真取舍：不增援可节省后续口粮，却会放慢接应；本测试未完整跑“全兵先发、冲突时重整”或“开局后不改令”，不能宣称此分配最优。
- **加粮、减粮、正常**：自动正常配给让首局不再需要逐路手填斤数；复诵把本时段拨粮与全线预计用量讲清楚。低配给在默认种子全程使用虽留下570斤，却造成25减员和士气大降，傅肜还多耗一个时段。临近粮尽时短期节用可以接齐，但不是无代价的省粮按钮。**本次没有实测多给粮**，不判断其收益。
- **赶路、休整**：页面说明了疲劳代价和休整一时段后自动继续；四局全部使用正常推进，没有实际下达赶路或休整命令。因此“值不值得”尚无实玩结论，不能以复诵预测代替完整局结果。
- **固定打法**：同种子规则模板复现成功；换种子时冲突对象及缺粮时点变化，需要读军报并改令。测试样本不支持“一个开局令、不处理后续也能通关”。
- **信息清晰度**：主动初报比旧版更有依据；自动配粮报告每时段实际发粮、士气和疲劳。默认种子第2时段增援复诵只警示“粮可能不足”，实际可用的应对在第6时段才明确；这种晚期紧张感成立，但玩家仍要读完总粮预测与每路用量。
- **自然语言问题，优先级 P1**：同一组三路人数在正常配给的一句合并令可成功，在“三路均少给两成/按八成配给”时连续两次返回502，分三句才成功。建议让多路共用配给条件的句子进入复诵，或在拒绝时指出具体哪一路/哪处表达无法落实；现在统一“没听清”难以自救。证据为对照局 API 1—5。
- **自然语言问题，优先级 P2**：“增派400人……总计1100人”同时提供增量和结果量时被校验拒绝。拒绝避免错派，合理；但提示“人数需忠实引用本次原话”未说明两种数字如何冲突。建议明确提示“请选择增派400或总计1100一种说法”。证据为对照局 API 6—7。

主观模型试玩评分（5分满分，非人类玩家评价）：信息清晰度4、自然语言可靠性3、决策取舍4、节奏4。分数仅对应这四局与上述操作。
