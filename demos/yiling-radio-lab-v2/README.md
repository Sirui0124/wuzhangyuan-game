## 优先级与本版处理

| 优先级 | 反馈 | 实施 |
|---|---|---|
| P1 必修 | 补粮覆盖待执行重整，出现无反馈的持续减速 | 补给附加到待执行任务，保留重整、坚守、等待、目标及已有补给；明确换任务才替换，复诵提示被替换的原安排 |
| P1 必修 | 单纯补粮误算为已经答复新冲突 | 单纯口粮补给不解除请示阻塞；重整、救济、明确继续等决断才答复 |
| P1 必修 | 问需求或建议报内部比较错误、答非所问 | API识别咨询后，规则层提供已知困难、真实可用额度和可核算的起步建议；未确报的待接人数明确未知，不编造 |
| P1 必修 | 总携粮与额外补粮混用、三路各200斤拒绝 | 总携粮包含新兵自动携粮；另补才追加。按斤前的数量核验证据，不把“三路”中的三当斤数 |
| P1 必修 | 本时段缺粮、减速和加风险被简报截掉 | 保留已发生的惩罚，并继续报告下一时段口粮；未解除冲突持续牵制时说明原因，不反复请示 |
| P2 信息 | 库存被误报为可用额度、计划被误报为执行 | 全线报告扣除预留；待执行安排单列；咨询与草案不改世界 |
| P2 交互 | 初次联络无路线信息、详情挡住推进 | 初次联络提供已有路线初报；详情加入关闭按钮，移至地图区域；确认或推进会收起 |
| P2 自由输入 | 微观分工只被泛化，玩家误以为已执行 | 复诵注明守口、分流和护送人数由部队安排，只执行复诵中的总兵力、任务与粮草 |
| P2 回归新增 | 旧军令中的已结束路线被误带入拒绝理由 | 限定本次原话作用域；拒绝理由引用未安排路线时纠正一次，不能因此拒绝本次其他路线补给 |
| P3 后续调优 | 预备兵吸引力偏弱、默认军情宽容 | 本版先补全可用决策信息与留兵取舍，结算显示真实用时。保留2500兵、5000斤、期限、风险和单次冲突参数；多事件、硬度和收益调整留待新版信息可靠后的试玩，不列为已修复 |

保留数值不是认定当前难度已通过。三个模型首局只覆盖同一军情，同时存在咨询和反馈缺口；现阶段直接加损失或压期限，会把输入与信息错误变成不公平失败。下一轮仍需检查新玩家在信息充分后是否主动留预备兵，以及“救齐”和“更省、更快、更少损失”的差异是否有吸引力。

## 怎样下令

仍以自然语言输入为主，推荐只帮助起步，不自动传令。普通报告不要求回复“继续”，真正冲突自动暂停。示例：

- “三路各有什么难处？需要多少兵粮，怎么分配合适？先别出兵。”
- “派九百人，带一千五百斤粮接傅肜。” → 初始新派900人、自带900斤，额外600斤，总调粮1500斤。
- “三路各补给二百斤口粮。” → 三队各200斤，人数保持。
- “先让现队重整一个时段，下轮恢复接应。”确认后，未推进前再说“给接应队补六百斤，原安排不变。” → 同轮重整兼补粮。
- “把剩下的预备兵全派给旧营。” → 扣除其他待执行安排后的可用兵。
- “从他那儿抽回一半，留下的人继续接应。”

固定规则仍是新兵每人至少自带1斤。如果总携粮低于已经在队及新兵自动携带的粮，不会暗中丢粮；会解释当前最低携粮。收队与补粮不能同路同轮兼做。

同一时段多条额外补粮相加；总携粮改为指定总量。军令复诵显示累计排定费用，取消未确认草案不改已确认安排。接应队返回余粮下次下令才可再用。

## 版本与接口

- 存档键：`yiling-radio-lab-v2-20261115`，仍为状态结构version3，独立于原版。
- API意图保留`set/add/remove/keep`，由客户端和引擎基于当前版本共同预览；响应commands不再提前改成最终总人数，避免同一补给在多次预览中重复相加。实际军令摘要、预计和代价来自同一引擎。
- 新增`grainMode: add | total`，旧调用未提供时按额外补给处理。队列保存的是已合并、可执行的总安排，不保存这种输入语义。
- 模型仍使用既有配置，凭据与正式AI模块均未修改。按项目约定尝试核对AI专用对话，当前入口不可用；本版相关接口变更记录于此，不声称已得到该对话审核。
- 协作原则在线核对到revision39，未写入或覆盖在线策划表。
- 画面沿用8950美术v2的纸本军图、军报册和传令笺；资源素材与来源见`art-generation.json`，无新增生成图、音频或视频。
