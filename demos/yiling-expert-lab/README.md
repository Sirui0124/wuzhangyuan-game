## 当前可玩流程

四路一直显示在地图上。先点人物军情，逐页阅读；可向营中的实际报告人自由提问0—2次，再选具体安排。选中只形成提案，确认调遣才占用队伍、必要时占用船队。每份行动的队伍需求与职责由剧情数据明确给出，不设置没有实际差异的数量菜单。

- 傅肜：接应队接替后阵，傅肜原部队退向隘口接应，接替末队最终撤回。
- 程畿：船队寻找后船、接应同行者，再护送末船归营。
- 黄权：首趟只核实两岸联络与接收；船回营报告后暂停，由玩家阅读实际回报，再决定第二趟渡运。首趟不计为救回黄权。
- 沙摩柯：跟随熟悉部众的人搜索，找到后在西侧集合，再共同归营。

五支接应队共2500人、唯一接应船队和故事时间在服务端共享。程畿与黄权争用同一船队；在外队伍不能再次派遣。归营才释放原队伍。新版没有伤亡计算、随机生死或隐含加兵。各路实际步骤不同；接应记录只在对应步骤完成时出现，营中归来场景只在队伍实际返营后出现。黄权中间回报必须读完才能进入渡运军情。

发令前默认暂停。打开军情会暂停全局，收起后仍暂停；确认调遣可开始走时，另有1×/4×和暂停控制。暂停、读剧情、问讯及等待模型不推进世界。24小时目前是背景时钟，没有超时死亡或自动失败结算；各路行军、执行和返营时长是显式调试参数，未作为历史行程或最终平衡承诺，不在选项中假报精确代价。

## 问讯与保存

问讯由本机已有模型配置发往真实模型服务。只读取当前阶段的剧情事实、当前报告人及实际调遣状态；不读取后续未发生的结局，不把提问当命令。黄权第二阶段使用新的已核实事实。`questionExamples`只辅助语言风格，不能扩大事实范围。回答通常一两句，允许简短未知回答；输出上限120字。

成功回答最多两次，技术失败不扣次数、不动世界并保留原问题；相同请求ID可幂等重试。跨路线问答分别保存，旧异步回答不能写入新路线。问讯只存在于调遣前的营中军情，不冒充远处人物即时应答。

页面刷新会用sessionStorage恢复当前本地服务中的这局，并暂停；各路阅读位置与草稿也保留。服务重启后旧内存会话失效，需要重新开始。这不是正式游戏存档。完成后可记录顺手程度、趣味、是否愿继续并导出本机JSON；记录包含阶段、调遣次数、问答、AI等待时间和决策用时，不上传。
