# 夷陵 · 军报交互稿 v1

2026-11-17，独立交互原型，待用户实际体验。入口：<http://127.0.0.1:8956/>。

本稿把美术小样变成可操作界面，用来检验看图、阅读、问话与传令的顺手程度。采用 TypeScript 和本地预设回报，不调用 AI API，不运行正式战斗/救援数值。页面顶部及首次说明均标明“交互演示 · 预设回报”。原 v6 试玩、静态参考板及正式第四章均未改动。

## 可体验的流程

1. 默认地图与操作区上下各半。点击地图军旗或下方的沙摩柯、冯习·张南、傅肜，选择联络对象；聊天区自动显示该队历史往来。
2. 输入问话，点击“传话”；可先点“拟一句问话”，建议只填入草稿。支持位置、伤兵、敌情、接应需要等预设主题，不支持的主题明确说明。
3. 回报自动进入聊天区，前线回报在左，自己的消息在右，输入框固定在底部。第一个筛选标签为当前对象往来，第二个“所有传令”可查看完整记录；重新选择队伍时默认回到该队往来。翻阅历史时，新报不会抢走滚动位置。
4. 点独立“传令”标签打开右侧调遣窗，选择甲乙丙丁接应队、出动人数、接应对象、行军和路线，交军侯复诵。也可直接在底部输入军令，例如“甲队接应傅肜，急行军，乙队留营待命。”
5. 点击“请军侯复诵”，检查各队任务、行军方式和绕行安排；可修改或取消。未确认时不会改变队伍任务。
6. 确认传令后，自动收到接令、途中、会合及归营回报，不需要重复点击继续。
7. 派队直接接应旧营会出现预设受阻报告。点击“安排绕行”仅填入新草稿，复诵、确认后演示绕行及归营。新军令会替换该队尚未发生的旧演示回报。
8. 每次成功问话或确认传令后，共用10秒间隔。切换队伍、切换问话/传令或刷新均不能绕过。倒计时期间可以看历史、写草稿、修改配置或复诵；未确认、空输入和不能理解的军令不消耗间隔。

右侧平时显示四队编制、状态和传令倒计时，点击部队也能进入调遣。出动人数只接受1至该队编制人数的整数；人数会进入复诵和已发军令，状态区展示本次出动数，归营后清零。余员仍在原编制中，本稿没有加入战斗损耗计算。一条军令可以同时安排多队，共用一次发送间隔；这不代表多次连续发送。

可写“乙队原地休整”“丙队撤回接应营”“丁队留营待命”。同一任务可以点名多队；不同任务请用逗号分开。含糊、否定或粮草配置语句会提示本稿不支持，不会假装已经执行。此范围只用于交互稿，不代表正式自然语言 API 的能力。

## 伸缩与阅读

- “展开军报/恢复均分”切换两种高度；分界线可以拖动，也支持上下方向键、Home/End。
- 1280×720 下地图与操作区各 302px；1654×1278 下各 581px。展开军报时地图 180px。单列聊天记录独立滚动，输入固定底部；复诵与确认位于右侧调遣窗，倒计时固定在窗底，长内容可独立滚动。
- 地图使用原 v6 地形资源；缩小时裁切并围绕当前关注部队调整视窗，不纵向压扁图像。地图、路线和地点一起平移。
- 下方面板为深铜色框、旧纸色聊天区与独立调遣浮窗；正文与输入为 18px 楷体，标签及辅助信息相应缩小。本调整只适用于本独立交互稿，不变更正式章节的公共字号规范。窄屏保留单列聊天和紧凑倒计时，传令窗从右侧浮出，可返回军情收起；允许页面纵向滚动。
- 三路前线以带人物简称的军旗和姓名标牌标识，使用不同旗色及选中高亮；已出营的接应队使用可点击兵筹，点击进入本队传令。
- 切换对象或工作页保留各自草稿；刷新恢复本稿的草稿、记录、布局和尚未到来的预设回报。

## 运行

在本目录执行 `node launch.mjs`，会编译、启动并打开浏览器。也可双击 `打开交互稿.cmd`。

开发验证：`npm run build`，然后启动服务，执行 `npm test`。

## 演示与正式机制的边界

军报时间为本机收报时刻；队伍的接令/行军/会合/归营分别按短暂预设延时播放，便于连续检查界面。急行军、休整、部队人数不在本稿中计算战斗效果，不能用于评估通关策略。旧营受阻是演示节点，不是随机战斗判定。预设文案参考 v6 的 `src/frontline.ts` 与 `src/engine.ts`，不写回正式剧情。
