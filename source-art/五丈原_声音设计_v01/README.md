# 五丈原：BGM 与触点音效设计 v01

2026-10-11。根据当前五丈原 v06 两轮玩法、正式剧情源和 HTML 交互代码设计。当前交付是三份 HappyShrimp 纯音乐 prompt、十二个处理后的触点音效候选、试听页及未来接入用的事件映射；未生成 BGM，未修改游戏运行代码，也未做游戏内试听验收。

建议整体声音是“冷夜军营里的低声思考”：古琴、柔和中低音弦乐和少量箫构成音乐，轻扣与翻纸构成交互反馈。两轮是同一夜的重来，用相同音色和短动机维持记忆感；第二轮稍有方向感，魏延交涉有压力但不催输入。避免战争大片式铜管、唢呐、大鼓、连续独奏和大悲大喜。

## 三段 BGM 与切换

| 曲目 | 使用位置 | 听感目标 | 变化 |
| --- | --- | --- | --- |
| 01 第六夜·初到军营 | 首轮教学、调查、普通人物对白 | 陌生、夜色、轻微不安 | 稀疏古琴、低音箫、极轻弦乐，无鼓 |
| 02 重返灯前 | 教学完成后重来的第二轮调查及普通人物对白 | 沉着、审慎、微弱希望 | 相同古琴动机，稍温暖；每两小节一次很轻的低皮鼓 |
| 03 帐前一言 | 两轮与魏延交谈、举证、写理由、等待与阅读回复 | 严肃、未决、克制的压力 | 低弦长音、古琴低音、每小节一次极轻低皮鼓，无倒计时感 |

三首都以 **64 BPM、4/4、D中心五声音阶（D/F/G/A/C）、D–A开放五度、A–G–D短动机** 为作曲目标。动机每八小节稀疏出现，不能变成循环洗脑旋律。统一速度和底色方便切曲，并不保证三次生成会自动保留同一旋律。32小节按该速度约为120秒，这是目标音乐结构，不是已验证的 HappyShrimp 时长参数。

以当前交谈对象 `weiyan` 为切换条件，不能仅凭到了营前传报处就切第三首，那里还有斥候。魏延曲从第一次与他交谈起，覆盖打开证据浮窗、输入、查看提示、提交及等待。打开输入框不重新起播；刷新后首次用户操作恢复对应曲目；普通重新渲染不重启音乐。离开交谈后，按 `progress.tutorial_completed` 回到第一或第二首。同曲不重启，换曲交叉淡化约1.8秒。

输入与等待期间在第三首常态电平基础上再降约3dB，用约0.5秒平滑过渡；不随着等待变长增加鼓点、加速或叠加声部。AI迟到、已取消的回应不能触发音乐变化或提示音。视频开始前把BGM平滑降到静音，视频结束后恢复；结局淡出约2.5秒，让结局文字保持安静，不另做第四首胜利/死亡曲。首页地图可低音量复用第一首。切到隐藏标签页时静音，返回后恢复同一状态。

## 在 HappyShrimp 使用

在 [HappyShrimp 官方页面](https://www.happyshrimp.ai/) 选择 **Instrumental**，分别复制 `prompts/` 中三份完整文本。不要让模型自动编歌词。官方页面当前可见 Instrumental 选项与音乐描述输入；这里不假定有独立 BPM、调性、循环点或负面提示框，所有音乐要求已写入同一段描述。

- [01 第一轮完整 prompt](prompts/01_第一轮_第六夜初到军营.txt)
- [02 第二轮完整 prompt](prompts/02_第二轮_重返灯前.txt)
- [03 魏延交涉完整 prompt](prompts/03_魏延交涉_帐前一言.txt)

试听时优先选择织体已经稳定、旋律很少、没有人声的版本。若只需修一个问题，保留原有描述，只追加相应修正句：

| 问题 | 追加句 |
| --- | --- |
| 太像影视配乐、有强高潮 | 从头到尾维持同样低的能量，去掉铺陈和高潮，仅保留三到四个安静声部。 |
| 太像歌曲、旋律抓耳 | 删除连续主旋律，古琴只演奏稀疏的单音与短动机，留白比发声更多。 |
| 太像恐怖片 | 去掉半音摩擦、低频轰鸣、惊吓重音和阴森音效，保持严肃但有人情味。 |
| 第三首催促输入 | 去掉心跳感与所有递增节奏，鼓只作很轻的固定呼吸，不随时间变化。 |
| 混入哼唱或环境音 | 仅保留器乐演奏，删除全部人声、气声吟唱、风声、火声与音效。 |

**“可循环”是生成要求，不代表成片天然无缝。** 下载后从稳定部分挑选连续的8/16/32小节，以实际拍点和相同和声状态确定起止，保留母带；处理尾部混响并检查接缝爆点，必要时对接缝做很短的交叉淡化。若有明显歌曲结尾、和声终止或大幅起伏，应重选片段/重新生成，不靠大幅淡出掩盖。最终至少连续循环五次，读两分钟对白、输入一分钟文字，再检查是否抢注意力。

## 触点音效候选

“配音元素”按此次要求理解为交互声音素材。本包先配置点击等触点，不添加人物念白、打字逐字声或每句话的人声嘀咕。下载原始素材并保留许可证；处理版为48kHz/16bit单声道WAV，小而短，方便浏览器与后续游戏导入。

| 事件 | 文件 ID | 处理后时长 | 设计用途 |
| --- | --- | --- | --- |
| 普通按钮 | ui_click_a / ui_click_b | 30ms / 30ms | 两个较轻短扣交替；其他专用音播放时不叠加普通点击 |
| 逐句推进对白 | dialogue_next | 22ms | 比按钮更轻；点击、空格、Enter推进统一 |
| 打开证据/记录/菜单 | panel_open | 143ms | 开册短音，仅面板实际打开时播放 |
| 关闭面板 | panel_close | 211ms | 轻合册，包括Esc或遮罩关闭 |
| 换证据详情、页签、地点 | paper_turn | 392ms | 短翻纸；换地点进一步减弱，无连续脚步 |
| 选择一张证据 | evidence_select | 40ms | 轻扣；不代表线索正确 |
| 实际出示证据 | evidence_present | 204ms | 短落案，强调已提交给人物，不表示已被接受 |
| 新证据获得 | evidence_gain | 700ms | 古琴感三音阶轻拨弦（D4–F4–A4），峰值比原版提高3dB；同批只响一次，重读或载入不响 |
| 提交自由输入 | submit | 248ms | 低沉落案；只在非空输入被接受提交时响 |
| 空白提交、缺选项、技术错误 | ui_warning | 226ms | 很轻的暗短扣；不把NPC驳回或服务错误演成死亡 |
| 当前有效 AI 回应到达 | response_ready | 100ms | 中性短提示，方便玩家回到阅读，不暗示成败 |

点击位置空白、悬停、拖动、文字选择、滚轮、禁用按钮、每次键入和自动存档都保持安静。等待AI不循环提示音。结局不播放游戏厅式胜负音；先用音乐淡出承接剧情。图标、声音和文案均不提前泄露未揭示的结果。

一个操作只优先播放一个有语义的声音；获得证据等系统事件优先于普通点击。相同事件至少间隔90ms，最多同时三路。音效总线候选起点0.65，最终听感在真实音乐与视频一起播放时再调整。处理版已削弱高频、控制峰值并做短淡入淡出；触点素材的材质和审美听感仍须在试听页确认，不能仅凭文件名视为定稿。

## 来源、配置与交付

原始素材来自 Kenney 的 [Interface Sounds](https://kenney.nl/assets/interface-sounds) 与 [RPG Audio](https://kenney.nl/assets/rpg-audio)，两个官方页面和包内 License.txt 均标明 CC0；支持个人和商业项目使用。每个候选的原文件、处理参数、校验值和来源链接记于 `audio-design-manifest.json`。保留原作者署名及许可证以便追溯。

- `声音设计与试听.html`：独立离线试听页；内嵌十二个WAV，可试听、下载、复制三段完整prompt。
- `prompts/`：三份可直接复制的中文纯音乐描述。
- `sfx/`：十二个处理版WAV，尚未放入游戏运行目录。
- `originals/`：原始下载包、完整解包内容及许可证。
- `audio-design-manifest.json`：候选资源与事件/BGM切换映射，状态为设计预览，游戏尚未读取。
- `prepare-sfx.py`：可复现处理脚本，使用本机ffmpeg和Python标准库。
- `verification.json`：格式、时长、电平、首尾零点及哈希检查，不代表听感或游戏内验收。
- `五丈原_音乐Prompt与触点音效包_v01.zip`：三份prompt、十二个WAV、配置、说明、试听页和许可证的便携包。

生成后BGM建议命名 `bgm_round_1`、`bgm_round_2`、`bgm_weiyan`，保留原始下载与最终循环版本；选定后再导入发布资源并完成音乐、交互、视频的整体试听。当前不替换已有视频音轨、不触发音乐付费生成。
